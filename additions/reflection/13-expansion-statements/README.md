# 13. Развёртывание обхода и runtime-значения

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
`auto`, `constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`template for` разворачивает отдельные фрагменты программы: у каждого поля
может быть свой тип. Обычный цикл выполняет одно тело с одним типом переменной
и не подставляет runtime-info в сплайсер. `std::define_static_array` переносит
полученную при компиляции последовательность в подходящее статическое хранение.
Сам `data` и его значения остаются обычными runtime-данными.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны списки отражений, константные выражения и типы полей.

У `Data` два поля разных типов: `int count = 2` и `double weight = 3.5`.
`template for` разворачивает отдельное обращение для каждого отражённого поля.
Имена `count` и `weight` известны при компиляции, значения читаются при запуске.
Сумма `total` после обхода — 5.5.

Обычный runtime-for по `info` не мог бы каждый раз менять статически
проверяемое обращение к неоднородному полю. Expansion statement формирует
подходящие участки кода заранее.

`define_static_array` предоставляет подходящий сохраняющийся диапазон метаданных.
Разворачивание может увеличивать объём кода и время компиляции.
Оно не создаёт потоков и не означает автоматическое параллельное выполнение.

## Типичные ошибки

`template for` разворачивает код, но не создаёт потоки. Обычная переменная цикла времени выполнения не становится константным отражением для сплайсинга.

### Самостоятельно

Добавьте строковое поле и используйте `if constexpr` по `type_of`, чтобы суммировать только арифметические значения.
