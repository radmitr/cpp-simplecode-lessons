# 15. Практика: `enum` в строку и обратно

## Версия C++

статическая рефлексия — **C++26**.
`enum class` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`common/reflection.hpp` содержит две небольшие функции без ручного списка
значений. Неподдерживаемое значение даёт пустой `string_view`, неизвестное имя —
nullopt. Сравнение имён регистрозависимое. Runtime-поиск здесь линейный;
рефлексия убирает дублирование списка, но сама не обещает оптимальную структуру
поиска. Политика для совпадающих значений объяснена в уроке [«14. Перечисления и совпадающие значения»](../14-enumerators/README.md).

## Как это работает

Нужны `enum`, `optional` и обход отражённых значений.

`enum_name(Color::green)` даёт green, `enum_value<Color>("blue")` —
непустой `optional` со значением `Color::blue`.
Строка BLUE не совпадает из-за регистрозависимого сравнения,
а число 99 не имеет именованного значения и даёт пустой `string_view`.

Пустой результат нужно проверять, а не безусловно разыменовывать optional.
Сама рефлексия убирает ручной повтор списка red/green/blue,
но runtime-поиск helper остаётся линейным.

При переименовании enumerator изменится автоматически получаемое имя.
Для постоянного внешнего формата лучше иметь явные стабильные имена/аннотации.
Псевдонимы с одним числом рассматриваются в уроке [«14. Перечисления и совпадающие значения»](../14-enumerators/README.md).

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh additions/reflection/15-enum-conversion/main.cpp
./build/additions/reflection/15-enum-conversion/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение `.exe`.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

Последняя строка успешного запуска — `OK 15-enum-conversion`.
Интерактивного ввода и файловых операций при запуске нет; успех — код `0`.
Ошибка проверки перехватывается: причина выводится в `stderr`, код — `1`.

Проверка всего раздела: `python scripts/check-additions.py --section additions/reflection`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Проверяйте пустой результат до чтения. Имена чувствительны к регистру; переименование перечислителя меняет автоматически получаемое внешнее имя.

### Самостоятельно

Добавьте своё сообщение об ошибке, не заменяя неизвестное значение первым элементом молча.
