# 01. Интроспекция, метаданные и время выполнения

## Версия C++

`constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Интроспекция отвечает на вопросы о типе; метаданные описывают сущности;
генерация кода использует эти сведения для построения операций. Здесь имя поля
и указатель на него заданы вручную. Проверка свойства типа выполняется компилятором,
а чтение значения `id` происходит при запуске. До C++26 стандарт не предоставлял
универсального обхода именованных полей произвольной структуры.
RTTI — получение сведений о типе во время выполнения; traits — шаблоны проверки
свойств типа при компиляции. Вместе с ручными описателями они решают отдельные
части задачи, а не заменяют встроенный обход полей.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны структуры, указатели на члены и проверка свойств типа.

`Descriptor` хранит текст `id` и указатель `int Record::*` на поле.
`record.*descriptors[0].member` применяет этот указатель к конкретному объекту.
Вывод `manual field: id=7` показывает отдельно метаданные имени и runtime-значение.

Запись `&Record::id` не указывает на единственный глобальный `int`: для чтения
нужен `Record`. Добавленное поле не попадёт в массив `descriptors` само.
Это и есть цена ручного описания: таблицу нужно поддерживать согласованной.
Такой подход полезен на C++17 и позволяет понять задачу до встроенной рефлексии.

Последняя строка успешного запуска — `OK 01-introspection-overview`.

## Типичные ошибки

Указатель на член требует живого объекта подходящего типа. Имя в описателе не проверяется на совпадение с именем поля; переименование требует ручной правки таблицы.

### Самостоятельно

Добавьте поле `int` age и его описатель. Проверьте, что без ручного изменения массива новое поле само не появляется.
