# 07. Оператор `^^` и `std::meta::info`

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
`auto`, `constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`info` — единый непрозрачный тип отражения сущности. Он не равен отражаемому
объекту и не является универсальной runtime-структурой. Метаданные используются
в константных вычислениях. Разные запросы проверяют категорию сущности; `type_of`
поля возвращает отражение типа этого поля. Метаданные типа не содержат текущее
значение `id` конкретного объекта.

## Как это работает

Нужны константные выражения и категории отражаемых сущностей.

`^^Sample` отражает тип, `^^Sample::id` — объявление поля.
Оба результата имеют `std::meta::info`, но относятся к разным категориям.
Поэтому сначала проверяется `is_type` или `is_nonstatic_data_member`,
а уже затем выбирается подходящий запрос.

`type_of(member)` даёт отражение `int`. Сравнение `info` проверяет отражаемую
сущность, а не значения runtime-объектов. `identifier_of(type)` выводит `Sample`.

Само отражение поля не содержит текущее значение `id`: объектов `Sample` может
быть много. Для чтения нужен конкретный объект и сплайсинг следующего урока.
Meta-info предназначено для compile-time-работы; это не обычный универсальный
runtime-дескриптор, который можно свободно передавать через сеть.

Последняя строка успешного запуска — `OK 07-reflection-info`.

(на Linux команда Python обычно называется python3).

## Типичные ошибки

Отражение типа и отражение поля имеют разные допустимые запросы. Метаданные поля не содержат значение этого поля для конкретного объекта.

### Самостоятельно

Сравните отражения поля, его типа и всей структуры. Добавьте `static_assert` для каждой категории.
