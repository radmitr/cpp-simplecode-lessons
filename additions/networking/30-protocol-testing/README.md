# 30. Некорректные данные, фрагментация и диагностика

C++17 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Проверяем протокол на произвольных границах чтения без случайных задержек. Нужен TCP framing.

## Как это работает

TCP передаёт поток байтов, а не границы ваших `send`. Кадр содержит четырёхбайтовую
длину в big-endian и тело, в котором допустим нулевой байт. Декодер принимает
порции данных; сначала собирает заголовок, проверяет предел `64`, затем тело.
Память незавершённого кадра ограничена `68` байтами. После ошибки объект отбрасывают.

Для семибайтового пакета проверяются все восемь точек разделения, включая пустую
первую/последнюю порцию. Следующая проверка передаёт два кадра одной порцией.
Отдельно отклоняются длина `65` и EOF посреди тела. Все результаты определяются
входом; тест не рассчитывает, что ОС разобьёт данные «нужным» образом.
Это автономная проверка парсера. Реальное соединение и дедлайны проверяются в
[TCP framing](../04-tcp-framing/README.md) и сетевых smoke-проверках.

Для диагностики полезно разделять DNS, подключение TCP, TLS, статус HTTP и тело
приложения. Записывают длительность стадии, код ошибки, объём и корреляционный ID;
содержимое токенов и ключи не журналируют. Захват пакетов показывает сетевые факты,
но TLS скрывает прикладное содержимое без специально настроенного окружения.

Нагрузочная проверка должна измерять throughput, задержки (включая хвосты), ошибки,
очередь и потребление ресурсов, а не только среднее время. Ограничивайте длительность
и число клиентов, запускайте на loopback. Моделирование потери/задержки транспорта
лучше выносить в отдельное изолированное сетевое окружение; этот урок не меняет
`tc`, маршруты и firewall вашего компьютера. «Потерять» кусок уже прочитанного TCP
потока в парсере — повреждение протокола, а не честная эмуляция повторной передачи TCP.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/networking/30-protocol-testing/main.cpp
./build/additions/networking/30-protocol-testing/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не считать один `recv` одним сообщением. Не выделять память до проверки длины. Не использовать `sleep` как доказательство порядка. Не запускать неограниченную нагрузку и не менять системный firewall ради обычного урока.
