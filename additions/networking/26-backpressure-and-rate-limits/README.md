## Как это работает

Token bucket хранит доступные разрешения. Вместимость `2` допускает краткий всплеск
из двух запросов, скорость пополнения — одно разрешение в секунду. Третий запрос
в тот же момент отклоняется; через `999 ms` разрешения ещё нет, через секунду — есть.
Время передаётся явно, поэтому проверка не зависит от `sleep` и нагрузки машины.
Это однопоточная модель политики, сетевой сервер здесь не запускается.

Очередь имеет вместимость `2`. Пока обработчик занят, третий элемент не добавляется;
после извлечения первого снова можно принимать. **Обратное давление** означает,
что ограничение обработчика доходит до источника: приостановить чтение, отказать
в новом запросе или ограниченно ждать. Просто переносить данные в бесконечную
очередь нельзя — память будет расти. При HTTP возможны `429` для ограничения
конкретного клиента и `503` для общей временной недоступности; повтор должен
учитывать возможность дублирования операции и допустимую задержку.

Лимит запросов в секунду не ограничивает число одновременно исполняемых запросов;
лимит очереди не ограничивает размер одного сообщения. Нужны отдельные пределы
соединений, байтов, времени и работы. В многопоточном сервере Bucket и очередь
требуют синхронизации или владения одним strand; общий лимит нескольких процессов
требует координации. Управление перегрузкой TCP/QUIC — механизм транспорта,
а не реализация нашего token bucket.

[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).

## Типичные ошибки

Не использовать wall clock вместо монотонного времени для интервалов. Не откладывать каждый отказ в неограниченный список повторов. Не считать показанный однопоточный Bucket безопасным при одновременных вызовах.
