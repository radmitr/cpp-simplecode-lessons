# 25. Многопоточный Asio и strand

## Версия C++

`std::thread`, `std::atomic`, `std::mutex`, `std::shared_ptr` и лямбды — **C++11**;
захват лямбды с инициализацией — **C++14**. Сборка — **C++17**.
`io_context`, `strand` и `bind_executor()` предоставляет внешняя библиотека Boost.Asio.

## Что изучаем

В [первом асинхронном сервере](../22-asio/README.md) один поток исполнял
все обработчики. Здесь `io.run()` вызывают три потока. Разные соединения могут
обслуживаться одновременно, но поля одного соединения изменяются последовательно.
Сначала разберите [потоки](../../../multithreading/lesson-01-thread/README.md),
[mutex](../../../multithreading/lesson-06-mutex/README.md) и асинхронные операции Asio.

## Примеры

- [server.cpp](server.cpp) — три потока `run()`, отдельный `strand` на сессию,
  чтение, запись и таймер ожидания.
- [client.cpp](client.cpp) — три параллельных клиента по три сообщения; каждый
  проверяет ответы `1:client-N`, `2:client-N`, `3:client-N`.
- [Интеграционная проверка](../tests/smoke_advanced.py) дополнительно открывает
  три молчащих соединения и проверяет завершение по таймауту.

## Как это работает

Клиент 1 посылает строку `client-1`. Сервер извлекает её до `\n`, увеличивает
счётчик этой сессии `sequence_` с 0 до 1 и отвечает `1:client-1`. Другая сессия
имеет собственный счётчик: её первый ответ тоже начинается с `1:`.
Порядок ответов внутри сессии сохраняется; общего порядка между клиентами нет.

Теперь чтение и таймер могут завершиться почти одновременно. Оба обработчика
обращаются к `finished_`, сокету и таймеру. Если исполнять их в разных потоках
без согласования, появится гонка данных — одновременный доступ к памяти,
при котором хотя бы один поток пишет без требуемой синхронизации.

Каждая `Session` создаёт собственный `asio::make_strand(io)`. `strand` — исполнитель,
который не допускает одновременного исполнения переданных ему обработчиков.
`start()` передаёт начало работы через `dispatch(strand_, ...)`, а завершения
чтения, записи и таймера привязаны через `bind_executor(strand_, handler)`.
Привязка передаётся и внутренним обработчикам составных операций
`async_read_until()` и `async_write()`.

Таким образом, обработчик таймера не закроет сокет одновременно с обработчиком
записи той же сессии. Для `sequence_`, `reply_` и `finished_` отдельный `mutex`
не требуется. Это работает только потому, что **все** обращения во время работы
пула проходят через тот же `strand`. Само создание `strand` не защищает обращения
напрямую из другого потока. `strand` не закрепляет сессию за одним физическим
потоком: следующие обработчики могут выполнять разные рабочие потоки.

Приём подключений и таймер приёма используют отдельный `control`-strand,
переданный конструктору `acceptor`. Поэтому `accepted`, `acceptNext` и приёмный
таймер согласованы между собой. Созданная сессия затем передаёт работу своему
исполнителю. Разные сессии используют разные `strand` и не блокируют друг друга.

Чтение имеет буфер 4096 байт, ожидание строки вместе с ответом ограничено тремя
секундами. Следующее чтение начинается после завершения предыдущей записи.
Поэтому две записи одного сокета не пересекаются: один `strand` сам по себе не
запрещает запустить две незавершённые асинхронные записи, а Asio этого не допускает.
Номер `readOperation_` отличает новый дедлайн от старого таймера, уже готового
к вызову в момент отмены. `finished_` делает закрытие однократным.

`reply_` живёт в сессии до обработчика записи; захват `shared_from_this()`
удерживает сессию. `completed` и `failed` — общие для разных сессий значения,
поэтому они атомарные: `std::atomic` обеспечивает согласованные операции над
одной переменной. Атомарный флаг не защищает остальные поля сессии.

`runPool()` запускает два `std::thread`, главный поток тоже вызывает `run()`.
После трёх подключений приём закрывается, а после трёх ответов закрывается сессия.
Когда закончились операции, `run()` возвращается. `join()` дожидается обоих
рабочих потоков до уничтожения переменных `main()`.
Исключения из рабочих обработчиков сохраняются в `exception_ptr` под `mutex`;
пул останавливается, все созданные потоки присоединяются, затем ошибка передаётся
в `main()`. Без `join()` деструктор присоединённого `std::thread` вызвал бы
`std::terminate`. Таймауты обрабатываются кодами ошибок, без исключений.

## Сборка и запуск

[Зависимости Windows](../README.md#windows), [Linux](../README.md#linux),
[F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Достаточно заголовков Boost; OpenSSL этому уроку не нужен.

Из корня, Linux:

```bash
bash scripts/build-linux.sh additions/networking/25-asio-strand/server.cpp
bash scripts/build-linux.sh additions/networking/25-asio-strand/client.cpp
```

Windows:

```powershell
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh additions/networking/25-asio-strand/server.cpp
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh additions/networking/25-asio-strand/client.cpp
```

В первом терминале запустите `./build/additions/networking/25-asio-strand/server`,
после `Listening` во втором — `./build/additions/networking/25-asio-strand/client`.
В PowerShell соответствующие команды:

```powershell
& .\build\additions\networking\25-asio-strand\server.exe
& .\build\additions\networking\25-asio-strand\client.exe
```

Оба принимают необязательный порт, по умолчанию `42021`; сервер разрешает `0`.
Ввода нет. Клиент выводит `Strand verified: 3 clients, 9 ordered replies`,
сервер — `Strand clients: 3; run threads: 3`; оба возвращают `0`.
Число потоков обозначает число вызовов `run()`, а не обещание равномерного
распределения девяти ответов между ними. Ошибка или таймаут — код `1`.
Без клиентов сервер ожидает не дольше 15 секунд; с молчащими клиентами —
до таймаута соответствующих сессий. Для повторного опыта перезапустите сервер.
В папке урока доступны задачи `Networking: Run server/client`.
Проверки: [окружение и `smoke_advanced.py`](../tests/README.md#зависимости-python).

## Типичные ошибки

- Привязать к `strand` только таймер, оставив чтение и закрытие вне него.
- Использовать один `strand` для всего сервера и ожидать параллельной работы сессий.
- Считать `strand` отдельным потоком или заменой очереди исходящих сообщений.
- Использовать обычный общий `bool` для ошибок, записываемых разными сессиями.
