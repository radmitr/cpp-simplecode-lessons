# 27. Выбор сервера и отказоустойчивые повторы

## Версия C++

C++17 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Разбираем выбор получателя запроса и поведение при недоступности узлов. Нужны переподключение и подтверждение операций.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

Модель выбирает здоровый backend с наименьшим числом активных запросов; при равенстве
сохраняется первый индекс. Узел `1` сначала нездоров, поэтому малое значение `active=0`
не делает его кандидатом. После отказа узла `2` выбирается `0`; при отказе всех
возвращается `nullopt`. Восстановленный узел вновь становится доступен.
Это проверка политики в памяти, а не готовый TCP/HTTP-прокси.

Round robin циклически распределяет новые запросы; least-connections учитывает
текущую занятость, но не стоимость запроса. Весовые схемы нужны при разной мощности.
Health check даёт наблюдение на определённый момент, а не гарантию успеха следующего
запроса. На практике учитывают последовательные отказы/успехи, таймауты и период
восстановления, чтобы узел не переключался бесконечно между состояниями.

При фактической передаче запроса счётчик увеличивают до отправки и уменьшают на
каждом пути завершения, включая ошибку. При нескольких потоках выбор и резервирование
должны быть согласованы. Если соединение оборвалось после отправки, сервер уже мог
выполнить действие: повтор записи требует идентификатора операции и дедупликации,
как в [request/ACK](../12-request-ack/README.md). Балансировка не делает хранилище
согласованным автоматически; локальная сессия пользователя также не переносится сама.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/networking/27-load-balancing/main.cpp
./build/additions/networking/27-load-balancing/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не считать сетевую ошибку доказательством, что операция не выполнена. Не повторять неидемпотентную запись без протокола дедупликации. Не учитывать только успешный путь уменьшения active.
