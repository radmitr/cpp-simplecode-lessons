# 05. Стандартный модуль и пересоздание CMI

## Версия C++

C++23 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Используем стандартную библиотеку через `import std` и разбираем зависимость CMI от сборки. Нужны именованные модули.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

`import std;` предоставляет экспортируемые объявления стандартной библиотеки;
`vector`, `accumulate` и `println` дают `sum=6`. Здесь нет текстовых `#include`.
Стандартный модуль появился в C++23; поддержка модулей языка из C++20 сама по себе
не означает наличия `std` у любой стандартной библиотеки.

GCC 16 в выбранной установке умеет `--compile-std-module`. Сборочный helper
передаёт этот флаг драйверу для урока; тот подготавливает нужные стандартные
модульные единицы и связывает программу. Всё выполняется из каталога
`build/additions/modules/05-import-std/module-build`, без записи в `/opt`.
Подготовка может занимать заметно больше времени и памяти, чем один обычный исходник.

CMI — скомпилированный интерфейс, а не переносимый исходник и не замена `.o`.
Он связан с компилятором, библиотекой, ключами языка и зависимостями. Общий helper
перед сборкой очищает только cache своего урока и пересобирает зависимости.
После обновления GCC, заголовков или параметров требуется такой rebuild.
Для ручной демонстрации удалите только каталог `module-build` этого урока и снова
вызовите общую команду сборки: `sum=6` должен сохраниться.

`std.compat` — отдельный стандартный модуль для совместимости с частью глобальных
C-имён; он не нужен этому примеру. Поддержка `import std` в IntelliSense может
отставать от драйвера GCC. На Windows нужна реализация GCC/libstdc++ с тем же
флагом; наличие настройки запуска не означает, что запуск Windows уже проверен.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/modules/05-import-std/main.cpp
./build/additions/modules/05-import-std/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не переносить `gcm.cache` между разными выпусками компилятора. Не фиксировать CMI в Git и не удалять системные каталоги ради rebuild. Не смешивать несовместимые CMI одного модуля из разных конфигураций.
