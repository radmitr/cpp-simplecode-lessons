# 02. Несколько модулей, повторный экспорт и шаблоны

## Версия C++

C++20 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Строим зависимости из двух модулей и экспортируем определение шаблона. Нужен вводный урок модулей.

## Примеры

- [main.cpp](main.cpp) импортирует только `facade`.
- [numbers.cppm](numbers.cppm) определяет шаблон `square`.
- [facade.cppm](facade.cppm) повторно экспортирует `numbers` и добавляет `twice`.

## Как это работает

Сначала компилируется `numbers.cppm`, затем зависящий от него `facade.cppm`,
потом `main.cpp`. `export import numbers;` делает интерфейс `numbers` доступным
импортёрам `facade`: поэтому `main` видит `square`, хотя не импортирует `numbers`
самостоятельно. Обычный `import numbers;` дал бы доступ самому фасаду, но не такой
повторный экспорт его пользователям.

Определение `square` находится в интерфейсе, чтобы импортёр мог создать нужную
специализацию. Это не обычная функция, чьё определение достаточно спрятать в `.cpp`.
При вызове `square(5)` выводится `T=int`, результат `25`; `twice(3)` возвращает `6`.
`export` управляет доступностью объявлений, но не создаёт пространство имён.
При совпадающих публичных именах по-прежнему нужны namespaces.

`module-units.txt` задаёт порядок зависимостей. Общий скрипт пересобирает все единицы
урока и очищает его `gcm.cache`, поэтому изменения компилятора и исходников не
оставляют старый CMI. Это простой полный rebuild, а не оптимальный incremental build.
В промышленной сборке порядок извлекается сканером зависимостей; циклические
импорты между модулями нужно устранить архитектурно.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/modules/02-reexport-and-templates/main.cpp
./build/additions/modules/02-reexport-and-templates/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не путать `export import` с `using namespace`. Не линковать только CMI: нужны и объектные файлы. Не переносить определения произвольных экспортируемых шаблонов в недоступную импортёру единицу реализации.
