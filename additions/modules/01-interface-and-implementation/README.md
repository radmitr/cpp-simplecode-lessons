# 01. Интерфейс и реализация модуля

## Версия C++

Именованные модули и `import`/`export` — C++20. Режим сборки — **C++20**. Для этой конфигурации нужен GCC 16+.

## Что изучаем

Отделяем доступные вызывающему коду объявления от реализации. Нужны функции, структуры и раздельная компиляция.

## Примеры

- [main.cpp](main.cpp) — импорт публичного интерфейса; вывод `5 16`.
- [arithmetic.cppm](arithmetic.cppm) — интерфейс `arithmetic`: экспорт объявлений функций и `Pair`.
- [implementation.cpp](implementation.cpp) — реализация функций и неэкспортируемый помощник; отдельного `main` нет.

## Как это работает

1. `export module arithmetic;` объявляет интерфейс модуля. `export` делает выбранные
   объявления доступными импортёру; имя модуля не обязано совпадать с именем файла.
2. `module arithmetic;` присоединяет единицу реализации к тому же модулю.
   Она видит интерфейс и определяет ранее объявленные функции.
3. `import arithmetic;` в `main.cpp` подключает объявления из скомпилированного интерфейса.
   Помощник `checked_demo_sum` не экспортирован и не доступен вызывающему коду по имени.
4. Линковщик объединяет объектные файлы интерфейса, реализации и `main`.

`#include` текстово вставляет заголовок при обработке исходника; `import` использует
готовый интерфейс. Поэтому единицы строятся в порядке зависимостей. Одного `-std=c++20`
для выбранного GCC недостаточно: применяется `-fmodules`.

`module-units.txt` перечисляет интерфейс, затем реализацию. Общие скрипты сначала
компилируют их, затем `main.cpp`; CMI (`gcm.cache`) и объектные файлы находятся в
`build/additions/modules/01-interface-and-implementation/module-build/`.
Они зависят от компилятора, его версии и параметров и не добавляются в Git.

## Сборка и запуск

[Настройка и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh additions/modules/01-interface-and-implementation/main.cpp
./build/additions/modules/01-interface-and-implementation/main
```

На Windows из MSYS2 Bash используйте `scripts/build-windows.sh` и файл
`build/additions/modules/01-interface-and-implementation/main.exe`. Конфигурации F5/Ctrl+F5 находятся в `.vscode/`.

Интерактивного ввода и сетевых служб нет. Программы не создают пользовательские файлы.
Каждый вариант проверяет результат:
последняя строка `OK reference-example`, код завершения `0`;
нарушение проверки или необработанная ошибка — код `1`.
При сборке читаются три исходника урока; запускается только `main`. Скрипты используют отдельный каталог сборки и на Linux, и на MSYS2/MinGW; Windows-запуск требует GCC 16+ с поддержкой модулей.

## Типичные ошибки

Нельзя собрать импортёр до интерфейса или только запустить компилятор для `main.cpp`
без объектных файлов модуля. CMI не является переносимой библиотекой и не заменяет
объектный файл. Изменение интерфейса требует пересборки зависимых единиц.
`import std` и header units — другие сценарии; здесь они не используются.
Поддержка модульного синтаксиса в IntelliSense может отставать от сборки GCC.
GCC пока реализует не все варианты модулей; пример ограничен интерфейсом и реализацией,
без private module fragment и разделов. Это не обещание ABI-совместимости между компиляторами.
