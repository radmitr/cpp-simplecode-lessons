# 03. Протокол co_await и собственный awaiter

## Версия C++

C++20 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Разбираем три шага ожидания и три случая: готовый результат, отказ от приостановки и сохранённое продолжение. Нужен урок владения кадром.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

`calculate` сначала создаёт кадр; `initial_suspend` откладывает тело. Первый
`task.resume()` начинает выполнение. У `Immediate` результат готов:
`await_ready()` возвращает `true`, поэтому `await_suspend()` не вызывается.
У `NoPause` готовность ложна, но `await_suspend()` возвращает `false`:
корутина сразу продолжает работу. У `Pause` вариант с результатом `void`
сохраняет handle и оставляет корутину приостановленной.

Первый шаг оставляет журнал `{1}`. `main` забирает сохранённый handle через
`exchange` и вызывает `resume()` ровно один раз. `await_resume()` возвращает `21`,
после чего сумма `1 + 20 + 21` попадает в `co_return`. Итог — журнал `{1,2}` и `42`.
`await_resume()` вызывается и для готового результата, и после возобновления.
Здесь всё происходит в одном потоке; приостановка не создаёт поток автоматически.

Собственный awaitable может предоставлять `operator co_await`; тогда результат
этого оператора становится awaiter. Этот вариант показан в
[задаче с результатом](../04-task-result/README.md). Promise может раньше изменить
операнд через `await_transform`; наш `Task` этого не делает. Сам протокол допускает
возврат другого `coroutine_handle` из `await_suspend`: так построен переход между
задачами в общем [task.hpp](../common/task.hpp).

## Типичные ошибки

Не вызывать `resume()` для завершённого/уничтоженного кадра и не возобновлять один кадр одновременно. Сохранённый handle не владеет кадром: его владельцем остаётся `Task`. Ссылки на `events` и `pending` должны пережить все возобновления.
