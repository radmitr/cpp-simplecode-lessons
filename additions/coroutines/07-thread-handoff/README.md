# 07. Безопасная передача возобновления другому потоку

## Версия C++

C++20 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Публикуем продолжение через семафор и ждём окончания работы до чтения результата. Нужны `jthread` и синхронизация.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

Главный поток создаёт приостановленную задачу и worker, затем вызывает `task.resume()`.
В `await_suspend` записывается `pending`; `ready.release()` публикует handle.
Worker ждёт в `acquire()` и после него видит запись, затем возобновляет корутину.
Она проверяет смену потока и возвращает `42`. Главный поток вызывает `join()`
и только после его возврата читает promise и разрешает уничтожение кадра.

Порядок `запись → release/acquire → resume → join → result/destructor` исключает
одновременное чтение/изменение результата. Задержек `sleep` и предположений о
планировщике нет. После `ready.release()` метод awaiter больше не обращается к
своим полям: worker уже может продолжить корутину и уничтожить сам awaiter.

Кадром владеет `task`, handle в `pending` — только невладеющий адрес. `jthread`
сам по себе при разрушении также присоединяется, но здесь `join()` сделан явно:
результат требуется до конца области видимости. Это одноразовая передача, а не
готовый многопоточный executor; общие данные требуют собственной синхронизации.

## Типичные ошибки

Не читать `done()`/promise параллельно `resume()`. Не создавать второй путь возобновления того же ожидания. Не обращаться к awaiter после публикации handle. Внешний поток должен завершиться до деструктора владельца кадра.
