# 04. Инварианты класса и внешний ввод

## Версия C++

C++26 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Сохраняем допустимое состояние объекта и отдельно проверяем недоверенные строки. Нужны классы, `optional` и исключения.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

Инвариант — условие допустимого состояния объекта между публичными операциями:
здесь баланс от `0` до `1000`. Отдельного синтаксиса автоматического инварианта
класса в примере нет: `invariant()` явно вызывается в `pre`/`post` нужных методов.
Начальное значение `0` сразу удовлетворяет условию.

`parse` проверяет всю строку, переполнение числа и диапазон до вызова `deposit`.
Строка `25` увеличивает баланс; `-1`, `oops`, `1001` отклоняются обычным `if`.
Эти проверки работают и при отключённых контрактах. Затем допустимое число `1000`
не помещается в текущий баланс: метод бросает `out_of_range` **до изменения**.
Баланс остаётся `25`; это проверяется обычным `check`, а не постусловием,
поскольку при исключении `post` не выполняется.

Предусловие описывает обязательство вызывающего кода. Ожидаемые ошибки внешнего
ввода обрабатываются явно; контракт помогает находить ошибки программиста внутри
уже проверенного кода. Для сложного изменения готовят новое состояние отдельно,
проверяют его и лишь затем фиксируют; перенос этой идеи см. в гарантиях исключений.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/contracts/04-invariants-and-input/main.cpp
./build/additions/contracts/04-invariants-and-input/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не передавать пользовательскую строку непосредственно в функцию, рассчитывая на `pre`: режим `ignore` убирает проверку. Не проверять диапазон после потенциального целочисленного переполнения. Не считать постусловие гарантией состояния после исключения.
