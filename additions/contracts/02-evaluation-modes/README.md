# 02. Режимы проверки и обработчик нарушения

## Версия C++

C++26 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Сравниваем один безопасный вызов при четырёх семантиках. Нужны функции и исходный урок контрактов.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

`echo(1)` удовлетворяет предусловию. `--violate` передаёт `-1`, но тело только
возвращает число: даже продолжение после нарушения не выполняет недопустимую операцию.
Обработчик определён в глобальном пространстве имён с точной сигнатурой GCC.
Он читает вид проверки, место нарушения и признак обязательного завершения;
не сохраняет ссылку на временный `contract_violation` и не выбрасывает исключения.

| `CONTRACT_SEMANTIC` | Запуск с `--violate` |
|---|---|
| `ignore` | `value=-1 violations=0`, код `0`; предикат не вычисляется |
| `observe` | Сообщение `handler`, затем `value=-1 violations=1`, код `0` в этой конфигурации GCC |
| `enforce` | Сообщение обработчика, затем аварийное завершение |
| `quick_enforce` | Аварийное завершение без вызова обработчика |

Сборочный скрипт принимает только четыре перечисленных значения. Например:

```bash
CONTRACT_SEMANTIC=observe bash scripts/build-linux.sh additions/contracts/02-evaluation-modes/main.cpp
./build/additions/contracts/02-evaluation-modes/main --violate
```

Замените `observe` последовательно остальными режимами. Для `enforce` и
`quick_enforce` ненулевой код/сигнал — ожидаемая демонстрация, а не успешный обычный
запуск. Проверка `scripts/check-contracts.py` выполняет её в отдельном процессе,
отключает core dump и проверяет наличие/отсутствие обработчика. Точное число
повторных проверок в иных конфигурациях не является переносимым обещанием.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/contracts/02-evaluation-modes/main.cpp
./build/additions/contracts/02-evaluation-modes/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не использовать обработчик для восстановления нарушенных инвариантов. `observe` продолжает выполнение после возврата обработчика; `enforce` завершает программу, а не бросает обычное исключение. Не помещать необходимые действия в предикат: `ignore` их исключает.
