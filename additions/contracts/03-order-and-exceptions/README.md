# 03. Порядок проверок и выход по исключению

## Версия C++

C++26 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Наблюдаем границы вызова без побочных эффектов в самих предикатах. Нужны RAII и исключения.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

Пример специально собирается с `observe`, заданным в `contract-semantic.txt`.
При нормальном выходе `VBDV` означает: обработчик ложного `pre`, тело (`B`),
деструктор локального объекта (`D`), обработчик ложного `post`. Значение результата
уже вычислено к постусловию; локальный объект к этому времени уничтожен.

Второй вызов имеет истинное предусловие, но тело бросает исключение. Разматывание
стека уничтожает `local`, затем внешний `catch` записывает `C`. Получаем `BDC`:
постусловие относится к нормальному возврату и при таком выходе не проверяется.
Предикаты только читают данные; журнал меняют тело, деструктор и обработчик.

Сначала создаются параметры вызова, затем проверяются предусловия, выполняется
тело и при нормальном выходе — постусловия. Несколько условий в объявлении
располагают от общих проверок к тем, которым нужна уже установленная предпосылка.
Проверка указателя и его разыменование внутри одного предиката должны быть связаны
коротким замыканием `&&`, а не зависеть от режима или числа проверок.
Вывод `VBDV` проверяет выбранный GCC и его параметры; стандарт допускает особенности
размещения/повторения проверок. Это не универсальный счётчик вызовов предиката.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/contracts/03-order-and-exceptions/main.cpp
./build/additions/contracts/03-order-and-exceptions/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Постусловие не является `finally`: для освобождения ресурсов при исключении нужен RAII. Наблюдаемая семантика не делает недопустимое разыменование безопасным. Не выводить сообщения из предикатов ради необходимой логики программы.
