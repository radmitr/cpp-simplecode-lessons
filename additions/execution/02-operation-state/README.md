## Как это работает

`just(42)` описывает отправку значения. `connect` соединяет sender с receiver и
возвращает **состояние операции** — объект, содержащий данные до завершения работы.
До `start` счётчики нулевые. `start(operation)` получает lvalue; этот объект
нельзя считать обычным переносимым контейнером уже запущенной работы.

Receiver объявляет `receiver_concept` и способы завершения. `set_value(int) &&`
принимает итог и вызывается один раз. Для данного `just(int)` другие каналы
не выбираются; их защитные реализации завершают процесс при нарушении предположения.
`get_env()` возвращает пустое окружение — информацию о свойствах получателя.
Никакого нового потока здесь нет: `just` завершается синхронно внутри `start`.

`value` и `completions` живут дольше receiver и operation. Для асинхронного sender
нельзя уничтожать operation сразу после `start`: необходимо дождаться сигнала
завершения. Повторно вызывать `start` для того же operation нельзя. Отдельный запуск
требует нового состояния, созданного новым `connect`.

## Типичные ошибки

Не приравнивать `connect` к запуску. Не вызывать `start` дважды. Не уничтожать operation или данные receiver до завершения. Методы завершения receiver должны соблюдать `noexcept`.
