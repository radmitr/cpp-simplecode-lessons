# 04. Объединение операций и зависимые шаги

## Версия C++

C++26 — режим сборки; механизмы и даты их появления указаны в исходниках. Учебный компилятор — GCC 16+.

## Что изучаем

Объединяем независимые значения и создаём следующий sender по результату предыдущего.

## Примеры

- [main.cpp](main.cpp) — самостоятельный пример; успешное завершение — код `0`.

## Как это работает

`when_all` запускает дочерние операции и завершает объединённую после согласованного
завершения детей. `just(2)` и `just(3)` синхронны: пример не обещает параллельности.
Их значения поступают в следующий `then` в порядке дочерних senders, сумма — `5`.
Для реальной параллельной работы нужны планировщики.

`then` превращает полученные значения в новое значение. `let_value` возвращает
**новый sender**, запуск которого становится зависимым шагом той же операции.
Здесь `7` хранится достаточно долго для шага с параметром `int&`, новый sender
отправляет `42`. Если вернуть sender из `then`, он будет обычным переданным объектом,
а не автоматически исполненным вложенным шагом.

`MaybeValue` из [common.hpp](../common.hpp) объявляет успешное значение и остановку;
конкретный запуск выбирает остановку. Поэтому объединённый тип остаётся пригодным
для `sync_wait`, которому нужен один вариант успешного завершения.
Остановка одного ребёнка `when_all` приводит к остановленному общему результату
в показанном случае. Для реально одновременно завершившихся ошибок и запросов
остановки нельзя рассчитывать на выбранный по задержке «первый» результат.
Состояние объединённой операции должно пережить завершение всех её детей.

## Сборка и запуск

Из корня проекта:

```bash
bash scripts/build-linux.sh additions/execution/04-composition/main.cpp
./build/additions/execution/04-composition/main
```

На Windows используйте `scripts/build-windows.sh` через MSYS2 Bash и файл `.exe`.
[Настройка F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Внешние службы и интерактивный ввод не нужны, если ниже не оговорено иное.
Успех — `OK reference-example` и код `0`; ошибка проверки — код `1`.

## Типичные ошибки

Не доказывать параллельность наличием `when_all`. Не возвращать из `let_value` sender с ссылкой на локальную переменную уже завершившегося обработчика. Не уничтожать operation после завершения только одного ребёнка.
