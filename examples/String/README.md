# `String`: владение символьным буфером

## Версия C++

`std::move` — **C++11**.
`std::vector`, `std::exception`, `std::boolalpha` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

[String.hpp](String.hpp) задаёт интерфейс, [String.cpp](String.cpp) —
реализацию. Нужны конструкторы, деструкторы, правило пяти, ссылки и потоки.

## Примеры

- [main.cpp](main.cpp).
- [main2.cpp](main2.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

### Два запуска

`main.cpp` создаёт Hello и , world!, складывает строки и присваивает результат
в уже существующий `s3`. Получается Hello, world!.
`main2.cpp` выполняет проверки конструкторов, присваивания, сравнений, доступа,
`find`/`substr`/`replace`, регистра, префиксов, итераторов и ввода-вывода,
затем демонстрирует тот же интерфейс. `assert`-проверки отключаются при `NDEBUG`.

### Как устроено владение

Объект хранит `char* str` и длину `len`. Буфер заканчивается нулём;
`len` не включает этот нуль. Копирование выделяет отдельный массив,
перемещение передаёт указатель и делает источник пустым.
`operator+` создаёт новый буфер; += использует результат сложения.
Деструктор выполняет `delete[]`.

[] в этом классе проверяет индекс и бросает `out_of_range` — это свойство
именно данной реализации. `find` возвращает `npos` при отсутствии,
`substr` принимает начальную позицию и число байтов, `replace` заменяет фрагмент.
`c_str()`/итераторы заимствуют память: замена буфера и уничтожение владельца
делают сохранённые указатели недействительными.

### Сравнение содержимого через `std::strcmp`

В [String.cpp](String.cpp) оператор `==` проверяет `std::strcmp(str, other.str) == 0`,
а `<` использует отрицательный результат сравнения. `strcmp` возвращает ноль
для одинакового содержимого, отрицательное число для меньшей строки и
положительное для большей; конкретные ненулевые значения не обязаны быть `-1`/`1`.
Функция сравнивает байты до завершающего нуля, а не адреса буферов.
Раздел сравнений в [main2.cpp](main2.cpp) использует разные объекты со строками
`apple`, `banana` и `apple`.

### Ограничения, которые стоит разобрать

- Это байтовая C-строка: встроенный нуль не поддерживается как обычный символ,
  `length` не считает Unicode-буквы, а `toUpper`/`toLower` не преобразуют UTF-8 целиком.
- Перемещение объявлено `noexcept`, но выделяет новый пустой буфер для источника.
  Если `new` выбросит исключение, программа завершится через `terminate`.
- Некоторые операции удаляют старый буфер до успешного нового выделения.
  Полной гарантии сохранения корректного состояния при `bad_alloc` здесь нет.
- C++17-ввод через `char buffer[]` в `operator>>` не задаёт ограничение width.
  Используйте в опыте короткие слова; для произвольного ввода нужен
  ограниченный или динамический разбор.
- `MAX_INPUT` ограничивает пользовательский `getline`. Длинная строка вызывает
  ошибку потока; код не реализует неограниченное чтение.
- `STRING_ENABLE_LOGGING` определён как `false`, но проверяется через #ifdef:
  макрос существует, поэтому диагностический `LOG` фактически включён.

Эти свойства видны в исходнике и не являются рекомендацией проектировать
прикладную строку таким способом. Для обычной работы есть `std::string`,
а для продолжения — [гарантии исключений](../../exceptions/bonus/04-exception-guarantees/README.md).

### Сборка

Откройте `main.cpp` или `main2.cpp` и нажмите F5/Ctrl+F5. Общий скрипт автоматически
добавляет `String.cpp` к выбранному `main`, но не добавляет другой `main`.

Из корня, Linux:

~~~bash
bash scripts/build-linux.sh examples/String/main.cpp
./build/examples/String/main
~~~

Windows: используйте `build-windows.sh` и результат `main.exe`.
Для проверок замените `main.cpp`/`main` на `main2.cpp`/`main2`.
[Общая настройка Windows/Linux](../../README.md#требования).
