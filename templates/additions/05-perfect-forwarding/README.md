# 05. Forwarding references и `std::forward`

## Версия C++

`std::string_view` — **C++17**.
`std::move`, `std::forward` — **C++11**.
`std::string`, `std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`T&`& является forwarding reference в показанном контексте вывода `T`.
Для lvalue `T` выводится ссылочным типом; схлопывание ссылок сохраняет его.
Именованный `value` — lvalue, а `forward<T>` восстанавливает категорию вызывающего.
Безусловный `move` внутри такой обёртки мог бы отобрать ресурс у lvalue. Forwarding
не продлевает жизнь и не делает безопасным многократное потребление одного аргумента.

## Как это работает

Нужны категории значений, перегрузки и `std::move`.

`route` принимает forwarding reference: `T` выводится из переданного аргумента.
Для text получается lvalue, для временной строки и `std::move(text)` — rvalue.
`select` в примере только возвращает название выбранной перегрузки,
поэтому text остаётся Ada даже после `route(std::move(text))`.

~~~cpp
template<class T>
auto route(T&& value) {
    return select(std::forward<T>(value));
}
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Внутри функции имя `value` является lvalue. Без `forward` все три обращения
попали бы в lvalue-перегрузку. `std::forward` восстанавливает категорию,
выведенную на границе `route`; `std::move` безусловно предлагает rvalue.

Не всякая запись `T&`& — forwarding reference: `T` должен выводиться
в подходящем контексте, без `const` у самой формы параметра.
Повторная передача одного ресурса как rvalue может использовать уже
перемещённое состояние; perfect forwarding сам этим не управляет.

## Типичные ошибки

Именованный параметр имеет категорию lvalue даже при типе `T&&`. Пробрасывающая ссылка требует соответствующего вывода `T`; не всякое `&&` является такой ссылкой. Безусловный `move` вместо `forward<T>` изменяет смысл передачи lvalue.
