# Урок 140. Защита заголовков от повторного включения

Предварительно: Урок 139 и препроцессор #include.

## Примеры

- [src/main.cpp](src/main.cpp): Включает оба заголовка и вызывает `foo` и `bar`.
- [src/foo.cpp](src/foo.cpp): Содержит реализацию `foo`.
- [src/bar.cpp](src/bar.cpp): Содержит реализацию `bar`.

Каждый `main*`.cpp — отдельная программа. В уроках 139–140 вспомогательные .cpp из src/ собираются вместе с `src/main.cpp`.

## Механизм и разбор

Препроцессор текстово вставляет заголовок в каждое место #include.
Если один заголовок пришёл двумя путями, include `guard` не даёт повторно
объявить его содержимое в одной единице трансляции.

~~~cpp
#ifndef PROJECT_HEADER_H
#define PROJECT_HEADER_H
// Содержимое заголовка.
#endif
~~~

Сокращённый фрагмент; полный пример: [src/main.cpp](src/main.cpp).

Первое включение определяет макрос, последующие пропускают блок.
Имя защиты должно быть достаточно уникальным. #pragma once — распространённая
альтернатива с поддержкой компиляторов проекта.

Guard не предотвращает определения одной обычной функции в разных .cpp:
каждая единица трансляции обрабатывает свои макросы отдельно.
Это уже вопрос ODR/линковки. После правки заголовка нужно пересобрать
зависящие исходники, а не только перезапустить старый бинарник.

## Запуск и результат

F5 — запуск с отладчиком; Ctrl+F5 — без отладчика.

Откройте папку урока или корень проекта, затем нужный исходник и нажмите F5/Ctrl+F5.
Сборка из корня в MSYS2 Bash на Windows:

```bash
bash scripts/build-windows.sh "basics/lesson-140-multi-file-project-include-guard/src/main.cpp"
```

На Linux используйте `scripts/build-linux.sh` с тем же аргументом.
Подробности запуска из терминала и рабочей папки — в [README раздела](../README.md).

Программа связывает обе реализации и выводит их сообщения.

## Что важно понять

Открывайте `src/main.cpp`. Include `guard` предотвращает повторную обработку заголовка внутри одной единицы трансляции. Он не исправляет несколько определений обычной функции в разных .cpp: это отдельный вопрос ODR и линковки.
