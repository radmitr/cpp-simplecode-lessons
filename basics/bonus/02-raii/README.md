## Как это работает

RAII (Resource Acquisition Is Initialization) связывает владение ресурсом
со временем жизни объекта. Объект получает ресурс при инициализации и
освобождает при разрушении. Ресурсом могут быть память, открытый файл или
захваченный мьютекс. Владелец должен сразу принять ответственность за ресурс.

### `main.cpp`: обычный выход, `return` и исключение

`process` создаёт `unique_ptr` с демонстрационным deleter. Три режима показывают:

1. Выход через конец функции.
2. Досрочный `return`.
3. Исключение, которое выходит из функции и перехватывается вызывающим кодом.

Ожидаемый вывод:

```text
acquire 42
normal exit
release 42
acquire 42
early return
release 42
acquire 42
throw
release 42
caught: operation failed
```

Третье `release` появляется до caught: при раскрутке стека разрушается локальный
владелец, а уже затем выполняется подходящий обработчик. Отдельного `delete`
в каждой ветке нет. Пользовательский deleter нужен для наблюдения за освобождением;
для обычного владения `int` достаточно `std::make_unique<int>(42)`.

### `main2.cpp`: исключение из конструктора

Члены `Operation` создаются в порядке объявления: `first`, затем `second`.
Тело конструктора выбрасывает исключение. Уже созданные члены разрушаются
в обратном порядке, но деструктор самого `Operation` не вызывается:
конструктор объекта не завершился.

```text
construct first
construct second
constructor throws
destroy second
destroy first
caught: initialization failed
```

Поэтому ресурсы лучше держать в готовых RAII-членах, например `unique_ptr`,
`vector` или `fstream`. Сырой указатель сам по себе память не освобождает при
ошибке конструктора. Когда все ресурсы уже управляются членами, обычно можно
следовать правилу нуля: не писать собственные операции копирования, перемещения
и деструктор без необходимости.

### Границы гарантии

Примеры показывают обычный выход и исключение, для которого найден обработчик.
При аварийном завершении процесса автоматическое освобождение через
деструкторы не гарантируется. Деструкторы и deleter не должны выпускать
исключения; вывод в deleter здесь демонстрационный и использует стандартную
настройку `cout` без `exceptions()`.

Закрытие файла в деструкторе освобождает ресурс, но не заменяет проверку
успешной записи. Если нужно сообщить об ошибке сохранения, проверяйте запись
и явное закрытие до выхода из области видимости.

Упражнение: создайте два владельца в одной области видимости и проверьте
обратный порядок освобождения при выходе через `return` и исключение.

### `main3.cpp`: обратный порядок уничтожения локальных объектов

Внутри блока сначала создаётся `Buffer first`, затем `Buffer second`.
При выходе из блока деструкторы выполняются в обратном порядке:
`Destroyed 2`, затем `Destroyed 1`. Только после обоих печатается `After block`.
Каждый деструктор освобождает свой массив; копирование класса закрыто
объявлениями конструктора копирования и присваивания.

Ввод не нужен. Последовательность основного вывода: `Created 1`,
`Created 2`, `Leaving block`, `Destroyed 2`, `Destroyed 1`, `After block`.
Затем `OK moved-example-080`; код успеха `0`. Необработанная ошибка `new`
может аварийно завершить пример. Возможности этого варианта — C++98.
