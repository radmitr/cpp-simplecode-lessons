# 09. Перемещение и `std::move`

## Версия C++

`std::make_unique` — **C++14**.
`std::move`, `auto` — **C++11**.
`std::string`, `std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`std::move` — приведение категории выражения. Ресурс передаётся только
когда подходящий конструктор или оператор реально выполняет перемещение.
Для `unique_ptr` источник после передачи пуст. Для `string` нельзя универсально
требовать пустую строку: придерживайтесь гарантий конкретного типа. `const` часто
мешает перемещению и приводит к копированию. Именованная переменная T&& сама
является lvalue-выражением.

## Как это работает

Нужны конструкторы, ссылки и уникальное владение.

Пример специально разделяет приведение выражения и передачу ресурса:

~~~cpp
auto&& reference = std::move(first); // Всё ещё тот же unique_ptr.
auto second = std::move(first);     // Создаётся новый владелец.
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Первая строка не вызывает перемещающий конструктор `unique_ptr`:
`reference` лишь ссылается на `first`. Вторая строка вызывает его,
после чего `first` пуст, а *`second` равно 7.
Именованная `reference` сама является lvalue при последующем обращении.

Перемещение `string` сохраняет payload в destination. Источник text затем
переиспользуется присваиванием reused; код не полагается на его прежнюю пустоту.
Вывод: 7 reused. Сам `std::move` не делает объект недопустимым;
гарантии состояния определяет конкретная операция типа.

Возврат локального объекта обычно пишут `return value`, без `std::move`:
лишнее приведение может помешать NRVO. Перемещение `const` объекта
часто выберет копирование, поскольку обычный `move`-конструктор требует T&&.

## Типичные ошибки

Само `std::move` лишь меняет категорию выражения. Ресурс передаётся выбранным конструктором или присваиванием. Не требовать пустоты от любой перемещённой строки; гарантированная пустота перемещённого `unique_ptr` — отдельный контракт.
