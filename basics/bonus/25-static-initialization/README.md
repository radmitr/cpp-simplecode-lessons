# 25. Статические объекты и constinit

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: c++20. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

constinit требует статической инициализации подходящего объекта, но
не запрещает последующее изменение. Это отличается от const и constexpr.
Порядок динамической инициализации между файлами может создавать зависимости;
локальный static переносит инициализацию до первого входа в объявление.
Потокобезопасная инициализация локального static не делает последующее изменение
самого объекта потокобезопасным. Также учитывайте порядок разрушения глобальных объектов.

## Разбор кода и полезные варианты

constinit требует статической инициализации global_count, но не делает
переменную const: main увеличивает её с 7 до 8.
constexpr-переменная была бы неизменяемой и имела бы другие требования использования.

cached() создаёт локальную static string при первом обращении
и возвращает const-ссылку на один сохраняющийся объект.
Проверка адресов двух вызовов подтверждает общую строку.

~~~cpp
const std::string& cached() {
    static const std::string text = "initialized on first use";
    return text;
}
~~~

Инициализация локальной static согласована между потоками начиная с C++11.
Но дальнейшее изменение произвольного static-объекта потребовало бы
своей синхронизации. Если инициализация выбросит исключение, следующий
вход может повторить попытку. Избегайте рекурсивного входа в ещё инициализируемый static.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh basics/bonus/25-static-initialization/main.cpp
./build/basics/bonus/25-static-initialization/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 25-static-initialization`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section basics/bonus`
(на Linux команда Python обычно называется python3).
