# 11. `unique_ptr`: фабрики, массивы и deleter

## Версия C++

`std::make_unique` — **C++14**.
`std::unique_ptr`, `std::move`, `auto`, `noexcept` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Фабрика возвращает владельца по значению. Параметр `unique_ptr` по
значению принимает владение; для наблюдения обычно достаточно ссылки/указателя
на сам объект. `get` не передаёт ответственность за `delete`, `release` передаёт её
вызывающему без освобождения. `reset` освобождает старый ресурс. `Deleter` должен
соответствовать способу получения ресурса и не выпускать исключений; время
жизни данных, на которые он ссылается, должно быть достаточным.

## Как это работает

Нужны RAII, динамическая память и перемещение.

Фабрика `make_number` возвращает владельца `int` со значением 7.
`get()` даёт заимствованный указатель, а `consume(std::move(pointer))`
передаёт владельца по значению: после вызова `pointer` пуст, ресурс освобождён
при уничтожении параметра `consume`.

~~~cpp
int* observed = pointer.get();
check(observed == pointer.get(), "get must not transfer ownership");
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Массив `make_unique<int[]>(3)` инициализируется нулями. Пользовательский `Deleter`
считает удаления; `reset` в локальном блоке удаляет `int` ровно один раз,
последующий деструктор уже пустого `unique_ptr` ничего не удаляет.

`release`, в отличие от `get`, снимает ответственность с `unique_ptr`;
возвращённый сырой ресурс надо немедленно передать новому владельцу
или освободить подходящей операцией. Для FILE*, дескрипторов и библиотечных
объектов используют соответствующий deleter, а не случайный `delete`.

### `main2.cpp`: `release()` не удаляет объект

`first.release()` возвращает сохранённый адрес и делает `first` пустым.
Само число `42` ещё существует. В следующей строке `second` принимает
этот адрес и становится новым владельцем. После `second.reset()` число удалено.

Вывод: `First empty: true; second: 42` и `OK unique-ptr-release`.
`get()` лишь наблюдает адрес и оставляет владельца прежним;
`release()` снимает ответственность за удаление. Если после него не назначить
нового владельца и не удалить объект, получится утечка.
Между освобождением владения и назначением нового владельца здесь нет
потенциально бросающих рабочих операций.

Ввода и файлов нет; успех — `0`, ошибка проверки — `1`.
Выберите `main2.cpp` либо замените имя в командах урока.

## Типичные ошибки

`get()` оставляет владение у `unique_ptr`, `release()` отдаёт указатель без уничтожения, `reset()` уничтожает прежний объект. Не создавать второго владельца из результата `get()`. После передачи по значению через `std::move` исходный владелец пуст.

### Самостоятельно

Оберните FILE* в `unique_ptr` с fclose-deleter, проверяя открытие до использования. Сравните с `fstream`.
