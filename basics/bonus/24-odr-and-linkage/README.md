# 24. ODR, `inline` и связывание

## Версия C++

`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Многофайловый пример включает один заголовок в две единицы трансляции.
Include `guard` защищает от повторного включения внутри одной единицы, `inline`
разрешает согласованные определения функции в нескольких единицах. Это разные
задачи. Неinline-определение обычной внешней функции в заголовке может дать
multiple definition; отсутствие реализации — undefined reference. Определения
шаблонов обычно должны быть доступны в месте инстанцирования.

## Примеры

- [main.cpp](src/main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны заголовки, объявления, определения и раздельная компиляция.

Оба .cpp включают `shared.hpp`. `inline int shared_answer()` { `return` 42; }
может иметь согласованные определения в нескольких единицах трансляции.
`support.cpp` определяет обычную answer_from_other_file, а `main` сравнивает
её результат с прямым вызовом. Перед OK печатается 42.

Заголовочная защита предотвращает повторный текст внутри одной единицы
трансляции. Она не делает произвольную обычную функцию допустимой
для определения в нескольких .cpp. Для этого нужны соответствующие
правила `inline`/шаблонов либо одно определение в отдельном исходнике.

`inline` в этой роли связано с ODR, а не обещает подстановку машинного кода.
У одинаковых `inline`-определений должны совпадать не только внешние имена,
но и необходимые условия согласованности. Различающиеся тела из-за
неудачных макросов могут нарушить ODR без обязательной удобной диагностики.

## Типичные ошибки

Include guard предотвращает повторное включение в одной единице трансляции; он не устраняет конфликт обычных определений между файлами. `inline` здесь связано с правилами определений, а не с обещанием оптимизации вызова.
