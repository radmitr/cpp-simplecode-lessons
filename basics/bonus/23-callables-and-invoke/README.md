# 23. Вызываемые объекты, `invoke` и `reference_wrapper`

## Версия C++

`std::invoke` — **C++17**.
`std::function`, `std::ref` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`invoke` даёт единый интерфейс для обычных функций, объектов-функторов
и указателей на члены. `std::ref` передаёт наблюдение за объектом через копируемую
обёртку, не продлевая его жизнь. `std::function` стирает конкретный тип вызываемого
объекта и может выделять память; шаблонный параметр сохраняет тип, но порождает
специализации. Вызов пустого `std::function` выбрасывает bad_function_call.

## Как это работает

Нужны функции, лямбды, указатели на члены и ссылки.

`invoke` единообразно обрабатывает функцию, метод и указатель на поле:

~~~cpp
std::invoke(&Counter::add, counter, 3);
check(std::invoke(&Counter::value, counter) == 3, "member invocation failed");
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Первый вызов делает `counter.value` равным 3, второй обозначает то же поле.
`std::function<void(int)>` хранит `std::ref(counter)`, поэтому `callback(2)`
обращается к исходному счётчику. Итоговый вывод — 5.
Без ref типичный копируемый функтор был бы сохранён по значению.

`std::function` стирает конкретный тип вызываемого объекта, сохраняя сигнатуру.
За это возможны косвенный вызов и выделение памяти.
Пустой `std::function` можно проверить через `bool`; его вызов бросит bad_function_call.
Переданный по ref объект обязан жить дольше `callback`.
Ссылка на поле после уничтожения `Counter` недействительна.

## Типичные ошибки

`std::ref` сохраняет ссылку и требует живого объекта. Перед вызовом пустоту `std::function` проверяют через `bool`; иначе возникает `bad_function_call`. Хранение функции не синхронизирует доступ к её захватам.
