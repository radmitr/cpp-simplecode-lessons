# 22. Лямбды: время жизни и захват перемещением

## Версия C++

`std::make_unique`, обобщённые лямбды, захват с инициализацией — **C++14**.
`auto`, лямбды — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Возвращаемая лямбда владеет счётчиком, поэтому не ссылается на исчезнувший
параметр. Init-capture позволяет передать `unique_ptr` во владение замыканию;
такое замыкание некопируемое. `[this]` хранит указатель, `[*this]` — копию объекта.
mutable меняет сохранённую копию, не исходную переменную. C++17 `std::function`
требует копируемую цель, поэтому лямбду, которую можно только перемещать, нельзя туда просто поместить.

## Как это работает

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

`make_counter` возвращает лямбду с собственным `value`. После ухода функции
состояние остаётся в объекте лямбды. mutable разрешает менять захваченную
копию при вызове: первые вызовы дают 6 и 7, следующий в выводе — 8.

~~~cpp
return [value = initial]() mutable { return ++value; };
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`owner` захватывает `unique_ptr` по перемещению и возвращает 9.
Такое замыкание нельзя просто копировать; это важно для интерфейсов,
требующих копируемый `std::function`.
Generic lambda с `auto`-параметром формирует шаблонный оператор вызова.

`Sample::snapshot` использует `[*this]`, то есть копирует объект `Sample`:
после `original.value = 20` сохранённая лямбда всё ещё возвращает 10.
Обычный `[this]` сохранил бы указатель и требовал живого `original`.
Ни `[&]`, ни `[this]` не продлевают жизнь внешних объектов автоматически.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 22-lambda-lifetime`.

в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
