# 29. Диагностика, `assert` и санитайзеры

## Версия C++

`std::array` — **C++11**.
`std::exception`, `std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`static_assert` проверяется компилятором, `assert` может исчезнуть при `NDEBUG`,
а `check` этого раздела остаётся активной проверкой примера. Предупреждения и
санитайзеры дополняют друг друга и не доказывают отсутствие всех ошибок.
ASan полезен для выхода за границы/ошибок времени жизни, UBSan — для некоторых
видов неопределённого поведения. Отрицательный исходник хранится как текст и
запускается только отдельным Linux-скриптом `run-sanitizers.sh`; обычный F5/Ctrl+F5 безопасен.
Поддержка санитайзеров зависит от установленного компилятора и runtime.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

`static_assert(sizeof(char) == 1)` проверяется при компиляции.
Это один байт C++, но он не обязан универсально означать восемь бит.
`assert(data[index] == 3)` действует при запуске только без `NDEBUG`.

`check(...)` из `common/check.hpp` — обычная всегда активная проверка:
при ошибке выбрасывает исключение, которое `main` превращает в сообщение и код 1.
`data.at(index)` отдельно контролирует границы; проверка index до `data[index]`
не позволяет сначала выполнить уже ошибочный доступ.

Не помещайте необходимую работу внутрь `assert`, например `assert(save())`:
в сборке с `NDEBUG` сам вызов может исчезнуть.
Санитайзеры находят определённые классы ошибок в выполненных путях;
они не доказывают корректность всех входов и не заменяют проверки интерфейса.

Отрицательный ASan-пример запускается отдельным скриптом, не обычным F5/Ctrl+F5.
Прежде чем трактовать отчёт как ошибку программы, отличайте обнаруженный
неверный доступ от сбоя загрузки или неподдерживаемой среды диагностики.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 29-diagnostics`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section basics/bonus`
(на Linux команда Python обычно называется python3).
