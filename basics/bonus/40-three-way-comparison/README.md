# 40. Трёхстороннее сравнение

## Версия C++

`operator<=>` и категории сравнения — C++20. Режим сборки — **C++20**. Достаточно GCC 11+.

## Что изучаем

Согласованно задаём порядок и равенство объектов. Нужны перегрузка операторов и сравнения.

## Примеры

- [main.cpp](main.cpp) — порядок полей и несравнимый NaN; вывод `1 1`.
- [main2.cpp](main2.cpp) — слабый порядок по ASCII-имени без учёта регистра; вывод `Ada ada`.

## Как это работает

Для `Point` default-оператор сравнивает сначала `x`, затем при равенстве — `y`.
Поэтому `(1,9) < (2,0)`. Из `<=>` компилятор получает переписанные выражения
`<`, `<=`, `>` и `>=`. Default-объявление `<=>` также позволяет неявно объявить
default-равенство; у самостоятельно написанного `<=>` автоматического `==` нет.

| Категория | Смысл |
|---|---|
| `strong_ordering` | Полный порядок; равенство соответствует взаимозаменяемости по значимому наблюдаемому состоянию |
| `weak_ordering` | Полный порядок с эквивалентностью: объекты могут различаться наблюдаемым свойством |
| `partial_ordering` | Возможны несравнимые значения (`unordered`) |

Во втором примере написания `Ada` и `ada` различаются, но сравнение по выбранному
свойству считает их эквивалентными. Правило ограничено ASCII и не является
Unicode-нормализацией. `double` допускает NaN: тогда сравнения результата с нулём
на «меньше», «равно» и «больше» одновременно ложны.

## Сборка и запуск

[Настройка и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh basics/bonus/40-three-way-comparison/main.cpp
./build/basics/bonus/40-three-way-comparison/main
```

Для второго примера соберите `main2.cpp` и запустите `main2` из того же каталога сборки.
На Windows из MSYS2 Bash используйте `scripts/build-windows.sh` и файл
`build/basics/bonus/40-three-way-comparison/main.exe`. Конфигурации F5/Ctrl+F5 находятся в `.vscode/`.

Интерактивного ввода и сетевых служб нет. Программы не создают пользовательские файлы.
Каждый вариант проверяет результат:
последняя строка `OK reference-example`, код завершения `0`;
нарушение проверки или необработанная ошибка — код `1`.

## Типичные ошибки

Результат `<=>` сравнивают с литералом `0`, а не считают обычным числом `-1/0/1`.
Не делать вывод о равенстве только из ложности `<` и `>`, если порядок частичный.
Сортировке нужен строгий слабый порядок: обычный `<` над данными с NaN не обеспечивает
подходящих отношений эквивалентности. Не путать default-сравнение с порядком байтов структуры.
