# 04. Инициализация и initializer_list

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: c++17. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

Фигурные скобки запрещают многие сужающие преобразования и могут
предпочесть initializer_list-конструктор. Поэтому vector(3, 7) создаёт три семёрки,
а vector{3, 7} — два заданных элемента. int{} инициализируется нулём; простой
локальный int без инициализации читать нельзя. Список initializer_list хранит
const-элементы и имеет ограниченное время жизни: не сохраняйте ссылку на временный список.

## Разбор кода и полезные варианты

Скобки участвуют в выборе конструктора, а не просто оформляют список:

~~~cpp
std::vector<int> a(3, 7); // {7, 7, 7}
std::vector<int> b{3, 7}; // {3, 7}
~~~

Поэтому печатается (3,7): 3; {3,7}: 2.
int zero{} равен нулю. int narrowing{number} при double number = 3.5
закомментирован, потому что такая list-initialization запрещает сужение.
Явный `static_cast<int>`(number) разрешает выбранное преобразование и даёт 3.

{} не гарантирует самый желаемый конструктор: перегрузка initializer_list
может иметь приоритет. У пользовательского типа всегда смотрите набор
конструкторов. Пустые () в записи T object(); могут объявить функцию;
форма T object{} обычно избегает этой неоднозначности.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh basics/bonus/04-initialization/main.cpp
./build/basics/bonus/04-initialization/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 04-initialization`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section basics/bonus`
(на Linux команда Python обычно называется python3).
