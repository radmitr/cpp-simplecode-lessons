# 38. Вычисляемые сообщения и удалённые функции

## Версия C++

Режим сборки — **C++26**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках. Для C++26 реализация ещё может быть неполной.

## Что изучаем

Даём понятное сообщение об ошибке компиляции. Нужны `static_assert`, `constexpr` и перегрузки.

## Примеры

- [main.cpp](main.cpp) — успешные static_assert и разрешённая перегрузка; вывод `report.txt`.

## Как это работает

Объект сообщения `static_assert` предоставляет `size()` и `data()`, доступные в константном вычислении. В отличие от прежнего требования строкового литерала, сообщение можно хранить в `constexpr std::string_view`. В рабочем примере проверки истинны. Удалённая перегрузка `open(int)` участвует в выборе функции, но её вызов запрещён; причина записана в `= delete("...")`. Вызов с текстовым именем использует разрешённую перегрузку.

## Типичные ошибки

Сообщение `static_assert` всё равно должно быть доступно при компиляции. `delete("reason")` не удаляет объект из памяти. Для проверки диагностик временно замените истинное условие ложным или вызовите `open(1)` — это намеренно некомпилируемые изменения, не рабочий сценарий.
