# 113. Интерфейс через абстрактный класс

C++17. Нужны классы, конструкторы, ссылки и области видимости.

В C++ нет отдельного ключевого слова interface. Bicycle задаёт контракт
через чисто виртуальные twistTheWheel() и ride(), а конкретные велосипеды
предоставляют реализации.

~~~cpp
void rideOn(Bicycle& bicycle);
~~~

Human работает с Bicycle&, поэтому одинаковый алгоритм подходит RoadBicycle
и MountainBicycle. Сначала main показывает поездку по асфальту, затем по
бездорожью; выбор сообщений происходит через виртуальные вызовы.

## Владение и время жизни

Ссылка не создаёт копию велосипеда и не передаёт владение. Оба велосипеда
живут в main дольше вызовов rideOn. У Bicycle есть virtual ~Bicycle() = default:
интерфейс также допускает корректное уничтожение производных объектов
через владеющий указатель на базу.

override помогает проверять сигнатуры. Невиртуальные функции и поля тоже
допустимы в абстрактном классе, но чистый интерфейс обычно оставляют небольшим.
Наследование интерфейса не требует знать внутреннее устройство каждого велосипеда.
