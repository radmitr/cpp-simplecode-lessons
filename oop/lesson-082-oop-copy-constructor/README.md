# 082. Конструктор копирования

C++17. Перед изучением нужны классы, конструкторы, ссылки и области видимости.

Копирование создаёт **новый объект** из существующего. Передача по значению
в `foo(a)` создаёт отдельный параметр, а передача `const MyClass&` позволила бы
читать исходный объект без копии.

## Варианты исходника

- `main.cpp`: `foo(a)` принимает `MyClass` по значению. Неявный конструктор копирования
  копирует `int data`, но сам не печатает сообщение. Поэтому можно увидеть один
  обычный Constructor и два Destructor: уничтожаются параметр и исходный `a`.
- `main2.cpp`: `foo2()` возвращает локальный `temp`. Компилятор может применить NRVO —
  построить возвращаемый объект сразу в месте `b`. Отсутствие видимой копии
  не означает передачу ссылки на уже уничтоженный `temp`.
- `main3.cpp`: `MyClass b(a)` явно создаёт второй объект. Запись `MyClass b = a`
  тоже является инициализацией, а не присваиванием существующему `b`.
- `main4.cpp`: объект владеет `new int`[`size`]. Конструктор копирования выделяет
  новый массив и переносит значения, поэтому два деструктора освобождают
  разные области памяти.

~~~cpp
MyClass(const MyClass& other);
~~~

Сокращённый фрагмент; полный пример: [main4.cpp](main4.cpp).

& в параметре означает ссылку: копирование самого параметра вызвало бы
снова конструктор копирования. `const` разрешает читать источник без изменения.
Адрес `this` показывает, какой объект создаётся/удаляется; конкретные адреса
различаются между запусками.

## Ограничения и продолжение

Побитовое копирование указателя не копирует массив и не разделяет владение
безопасным способом. У main4 ещё нет корректного оператора присваивания:
рассматривайте его вместе с уроком 83 и правилом трёх/пяти.
В C++17 часть исключения копирований обязательна, но NRVO именованного `temp`
остаётся необязательной оптимизацией. `-fno-elide-constructors` не отменяет
обязательные правила C++17.

Каждый файл с `main` — самостоятельная программа.
