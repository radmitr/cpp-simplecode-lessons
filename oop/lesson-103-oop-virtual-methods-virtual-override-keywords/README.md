# 103. Виртуальные методы и `override`

C++17. Нужны классы, конструкторы, ссылки и области видимости.

`Gun` объявляет `shoot` виртуальным, `SubmachineGun` и `RPG` переопределяют его.
Поэтому вызов через `Gun*` выбирает функцию по реальному типу объекта:

~~~cpp
Gun* pGun = &smg;
pGun->shoot(); // SubmachineGun::shoot
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`main` печатает BANG!, затем BANG! BANG! BANG!, затем BADABUM!!!.
Повторный вызов через `pGun` снова даёт очередь, а `Player` с &`rpg` — BADABUM!!!.
`Player` принимает общий интерфейс и не проверяет конкретный тип оружия.

## Роль `override`

`override` заставляет компилятор проверить, что сигнатура действительно
переопределяет виртуальную функцию базы. Ошибка в `const` или параметрах
тогда диагностируется вместо случайного создания другой функции.
После объявления `virtual` в базе виртуальность сохраняется и в наследниках.

Все объекты `main` локальные, указатели ими не владеют. Если добавить удаление
через `Gun*`, базовому классу потребуется виртуальный деструктор.
В конструкторах и деструкторах виртуальные вызовы не переходят в ещё не
созданную или уже разрушенную более производную часть.
