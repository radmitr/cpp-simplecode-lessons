## Как это работает

Ромб возникает, когда две базы наследуют один общий тип, а третий класс
наследует обе ветви. По умолчанию он содержит **два подобъекта** общей базы.

### Четыре варианта

- `main.cpp`: `GraphicCard` имеет `Component` отдельно через `GPU` и `Memory`.
  `gc.GPU::companyName` равно AMD, `gc.Memory::companyName` — Samsung.
  Конструктор `Component` вызывается дважды.
- `main2.cpp`: обе ветви используют `virtual Component`. Общая база теперь одна,
  её конструктор выбирает наиболее производный `GraphicCard`. Он передаёт AMD,
  поэтому обе квалифицированные записи `companyName` показывают AMD.
  Аргумент Samsung не создаёт второй `Component`.
- `main3.cpp`: `OrcWarrior` имеет два `Character`. Печатаются два этапа создания
  общей базы. `HP` в этом варианте не инициализирован и не читается.
- `main4.cpp`: `virtual Character` один. Он начинает с `HP = 100`, затем `Orc`
  добавляет 20, `Warrior` — 30, `OrcWarrior` — 10. Итог `HP = 160`.

~~~cpp
class GPU : public virtual Component {};
class Memory : public virtual Component {};
~~~

Сокращённый фрагмент; полный пример: [main2.cpp](main2.cpp).

### Важные различия

`virtual` у наследования объединяет общую базовую часть. `virtual` у метода
включает динамический выбор функции — это разные назначения одного слова.
Виртуальную базу инициализирует самый производный класс; если создать `Memory`
отдельно, уже `Memory` отвечает за свой `Component`.

Общая виртуальная база создаётся раньше обычных баз и уничтожается после них.
Размеры и смещения подобъектов зависят от реализации, не рассчитывайте их
вручную. Виртуальное наследование не делает деструктор автоматически виртуальным.
