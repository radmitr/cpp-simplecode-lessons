## Как это работает

Создание `C` требует сначала создать его базовую часть `B`, а для неё — `A`.
Поэтому сообщение конструкторов идёт в порядке:

~~~text
A
B
C
~~~

В файле сообщения длиннее, но последовательность именно такая.
Тело конструктора производного класса выполняется после конструкторов баз
и инициализации полей. Оно уже может пользоваться созданной базовой частью.

`private`-наследование не меняет этот порядок, оно регулирует доступ.
Без явного выбора вызывается доступный конструктор базы по умолчанию.
Если его нет, производный конструктор должен указать аргументы в списке
инициализации, как в уроке [«102. Выбор конструктора базового класса»](../lesson-102-oop-inheritance-base-constructor-call/README.md).

Объект `C` содержит базовые подобъекты; это не три независимо созданных
локальных переменных. При неудаче конструктора уничтожаются уже успешно
сконструированные базы/поля, но деструктор ещё не созданного `C` не вызывается.
