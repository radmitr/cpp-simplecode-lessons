# cpp-simplecode-lessons

Мои упражнения и эксперименты по C++ на основе материалов канала [#SimpleCode](https://www.youtube.com/@SimpleCodeIT), в первую очередь плейлиста [«Основы C++. Программирование для начинающих»](https://www.youtube.com/playlist?list=PLQOaTSbfxUtCrKs0nicOg2npJQYSPGO9r). Это личный учебный репозиторий, а не официальный проект автора курса.

## Структура

- `basics/` — основы языка и небольшие программы.
- `oop/` — объектно ориентированное программирование.
- `stl/` — контейнеры, алгоритмы и другие темы стандартной библиотеки.
- `multithreading/` — многопоточность.
- `examples/` — дополнительные примеры.
- `_template/` — заготовка для новых уроков.
- `scripts/` — общие скрипты сборки для Linux и Windows.
- `docs/` — результаты проверки и ограничения примеров.

Каждый урок находится в отдельной папке. У разных уроков могут быть собственные `main.cpp` и настройки VS Code в `.vscode/`.

## Сборка и запуск в VS Code

Нужно расширение VS Code **C/C++** от Microsoft. CMake в этом репозитории пока не настроен.

### Общий каталог результатов

Все задачи используют **один `build/` в корне репозитория** с сохранением структуры исходников. Результат не зависит от того, открыт весь репозиторий или отдельный урок:

| Исходник | Linux | Windows |
| --- | --- | --- |
| `basics/lesson-118-file-io-fstream/main3.cpp` | `build/basics/lesson-118-file-io-fstream/main3` | `build/basics/lesson-118-file-io-fstream/main3.exe` |
| `basics/lesson-139-multi-file-project/src/main.cpp` | `build/basics/lesson-139-multi-file-project/src/main` | `build/basics/lesson-139-multi-file-project/src/main.exe` |

Промежуточные папки внутри общего `build/` создаются автоматически. Каталоги `build/` внутри уроков больше не используются.

### Открыть весь репозиторий: Linux и Windows

В корне есть общие `.vscode/tasks.json` и `.vscode/launch.json` для обеих платформ. На Linux нужны `/usr/bin/g++`, `/usr/bin/gdb` и `/bin/bash`; на Ubuntu/Debian они входят в пакеты `build-essential`, `gdb` и `bash`. Проверить инструменты и кодировку терминала Linux:

```bash
g++ --version
gdb --version
locale charmap
```

Для русского ввода и вывода последняя команда должна показать `UTF-8`. На Windows нужны MSYS2 MinGW-w64: `g++` и `gdb` из `C:/msys64/mingw64/bin/`, Bash и служебные утилиты из `C:/msys64/usr/bin/`. Каталог MinGW с DLL среды выполнения должен быть доступен через `PATH`. При другой установке MSYS2 потребуется изменить пути в конфигурациях и Windows-скрипте.

1. Откройте **корень репозитория** в VS Code.
2. Откройте исходный `.cpp` с `main()`, например `basics/lesson-118-file-io-fstream/main3.cpp`. Сборка использует активную вкладку.
3. **Ctrl+Shift+B** — собрать; **F5** — собрать и запустить под GDB, конфигурация `C++: Run and Debug`.
4. **Terminal → Run Task… → C/C++: Build and Run** — собрать и запустить без отладчика. **C/C++: Run (No Build)** — запустить существующий бинарный файл.

**Ctrl+F5** — стандартный запуск без отладки через `launch.json`; перед запуском выполнится сборка `preLaunchTask`. Дополнительная привязка для этого не требуется.

Общие задачи автоматически вызывают `scripts/build-linux.sh` на Linux или `scripts/build-windows.sh` на Windows. Оба скрипта используют C++17, `-O0 -g`, предупреждения компилятора и `-pthread`. Для уроков с `SimpleTimer.cpp` и примеров `String` они добавляют вспомогательный исходник. Для уроков 139–140 собираются все `src/*.cpp` с заголовками из `include/`. Другие `main2.cpp`, `main3.cpp` и т. п. остаются отдельными программами.

Скрипты только компилируют; запуск выполняют задача `Build and Run`, `Run (No Build)` или отладчик. Linux-бинарникам расширение не добавляется; на Windows используется `.exe`.

Рабочая папка при запуске — папка исходника, поэтому относительный `myFile.txt` относится к соответствующему уроку, а не к `build/`. Вводить данные при F5 нужно во встроенном **Terminal**, а не в **Debug Console**.

Linux-скрипт можно вызвать из терминала в корне проекта:

```bash
bash scripts/build-linux.sh basics/lesson-118-file-io-fstream/main3.cpp
cd basics/lesson-118-file-io-fstream
../../build/basics/lesson-118-file-io-fstream/main3
```

На Windows из Git Bash/MSYS2 аналогично вызывается `bash scripts/build-windows.sh basics/lesson-118-file-io-fstream/main3.cpp`; результат имеет расширение `.exe`.

### Отдельные уроки: Linux и Windows

В каждой папке урока и в `_template` сохранены собственные конфигурации. Блоки `linux` автоматически выбирают GCC/GDB из `/usr/bin` и Bash из `/bin`; Linux-задачи используют C++17 и `-pthread`.

Требования к инструментам Windows те же, что для открытого корня. В отдельных Windows-задачах сохранены прежние параметры стандарта C++, в том числе C++26 в части уроков; для них нужен достаточно новый MinGW GCC. Общие задачи корня используют C++17.

1. Откройте в VS Code **папку нужного урока** как отдельную рабочую папку. Тогда VS Code увидит именно её `.vscode/tasks.json` и `.vscode/launch.json`.
2. Для обычного урока откройте нужный исходный файл `.cpp` перед сборкой: задачи с `${file}` используют активную вкладку. Если активен, например, `tasks.json`, компилятор попытается собрать этот JSON-файл.
3. В верхнем меню VS Code выберите **Terminal (Терминал) → Run Task… → C/C++: Build and Run**, чтобы собрать и сразу запустить программу.

Другие доступные действия:

- **Ctrl+Shift+B** — выполнить задачу сборки по умолчанию (`C/C++: g++.exe build active file`); она создаёт бинарный файл, но не запускает его.
- **F5** — выполнить конфигурацию `C++: Run and Debug` из `launch.json`: сначала задачу сборки `preLaunchTask`, затем запуск под GDB.
- **Ctrl+F5** — выполнить конфигурацию из `launch.json` без отладки, предварительно запустив задачу сборки `preLaunchTask`.
- **Terminal → Run Task… → C/C++: Run (No Build)** — запустить уже собранный бинарный файл без повторной компиляции. Если исходник изменился, эта задача всё равно запустит старую версию программы.

При открытии отдельного урока пути ведут в тот же общий `build/` через корень репозитория (`${workspaceFolder}/../..`). Задача `C/C++: Create build directory` создаёт нужную папку внутри общего `build/` перед компиляцией. Рабочая папка запуска остаётся папкой исходника.

В многофайловых уроках 139–140 результат соответствует `src/main.cpp` и находится в `build/basics/<папка урока>/src/main` либо `main.exe`; эти задачи создают каталог сами. Название задачи `C/C++: g++.exe build active file` сохранено для совместимости; на Linux она вызывает `/usr/bin/g++`.

В конфигурациях отдельных уроков указан их путь относительно корня. При копировании `_template` в новый урок или переименовании папки обновите этот путь в скопированных `tasks.json` и `launch.json`. Общие задачи корня вычисляют путь по исходному файлу автоматически.

### Дополнительные сочетания клавиш

**Ctrl+F5** уже назначен в VS Code на запуск без отладки. На Linux сочетания **Ctrl+Alt+F1…F12** обычно переключают виртуальные консоли, поэтому **Ctrl+Alt+F5** для задач редактора лучше не использовать.

Для запуска без пересборки на Linux можно выбрать, например, **Ctrl+Alt+R**. В палитре команд **Ctrl+Shift+P** откройте **Preferences: Open Keyboard Shortcuts (JSON)** и добавьте правило в пользовательский `keybindings.json`:

```jsonc
[
    {
        "key": "ctrl+alt+r",
        "command": "workbench.action.tasks.runTask",
        "args": "C/C++: Run (No Build)",
        "when": "isLinux && editorTextFocus && editorLangId == cpp"
    }
]
```

Это правило действует при фокусе в редакторе C++; оно запускает задачу текущей рабочей папки. На Windows при желании можно назначить **Ctrl+F5** непосредственно на `C/C++: Build and Run`, а **Ctrl+Alt+F5** — на `C/C++: Run (No Build)`:

```jsonc
[
    {
        "key": "ctrl+f5",
        "command": "workbench.action.tasks.runTask",
        "args": "C/C++: Build and Run",
        "when": "isWindows"
    },
    {
        "key": "ctrl+alt+f5",
        "command": "workbench.action.tasks.runTask",
        "args": "C/C++: Run (No Build)",
        "when": "isWindows"
    }
]
```

Если в `keybindings.json` уже есть правила, добавьте нужные объекты в существующий массив. Эти примеры не устанавливают сочетания автоматически: пользовательский `keybindings.json` находится вне репозитория. Windows-правило для **Ctrl+F5** заменяет стандартный запуск без отладки через `launch.json` запуском задачи `Build and Run`.

## Что хранится в репозитории

Исходные файлы и настройки задач/отладки в `.vscode/tasks.json` и `.vscode/launch.json` полезны для воспроизведения учебных примеров. Все текущие задачи создают программы внутри общего `build/` в корне; он исключён через `.gitignore` независимо от расширения файлов. Правила `*.exe` и `*.out` оставлены также для результатов ручной или прежней сборки вне `build/`. Также исключены `point.dat` урока 117 и `myFile.txt_` урока 118. Пять учебных `myFile.txt` отслеживаются Git: запуск примеров записи может менять их. Локальные `.vscode/settings.json` исключены: они содержат в основном привязки файлов к языку C++ и не нужны для сборки.

Результаты проверки всех 166 программ на Linux, известные особенности примеров и границы проверки описаны в [docs/linux-check.md](docs/linux-check.md).
