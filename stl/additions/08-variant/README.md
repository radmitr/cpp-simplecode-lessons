# 08. Значение одного из типов `variant`

## Версия C++

`variant`, `visit`, `monostate` — C++17. Режим сборки — **C++17**. Достаточно GCC 11+.

## Что изучаем

Описываем конечный набор возможных типов без ручного отслеживания активного поля `union`. Нужны шаблоны, лямбды и исключения.

## Примеры

- [main.cpp](main.cpp) — состояния, доступ по типу/индексу, обработчик `visit`; вывод `xxx`.
- [main2.cpp](main2.cpp) — две независимые альтернативы и неверный `get`; вывод `5.5`.
- [main3.cpp](main3.cpp) — намеренно бросающий конструктор и восстановление; вывод `9`.

## Как это работает

`variant<monostate,int,string>` начинает с первой альтернативы `monostate`. Это обычный
пустой тип, которым удобно обозначить ещё не выбранное значение. Присваивание `7`
переключает активную альтернативу на `int`, а `emplace<string>(3,'x')` — на строку `xxx`.
`index()` возвращает индекс с нуля; `holds_alternative<T>` проверяет конкретный тип.

`get<T>` возвращает ссылку и бросает `bad_variant_access` при несовпадении.
`get_if<T>(&value)` возвращает указатель либо `nullptr`. Типовой доступ требует,
чтобы `T` встречался в списке ровно один раз; для `variant<int,int>` нужен индекс.

`visit` вызывает переданную функцию для активного значения. Все возможные альтернативы,
а при нескольких `variant` — все сочетания, должны компилироваться. В форме C++17
результат должен иметь один и тот же тип и категорию значения; пример явно возвращает `double`.

При присваивании перемещением между разными альтернативами старое значение
уничтожается. Если конструктор нового значения бросает исключение, получатель остаётся
без альтернативы. `main3.cpp` проверяет это состояние `valueless_by_exception`:
индекс равен `variant_npos`.
Это отличается от присутствующего `monostate`. Успешный `emplace` восстанавливает значение.

## Типичные ошибки

Не читать прежнюю альтернативу после переключения; ссылки на неё уже недействительны.
Не всякое исключение делает `variant` пустым: гарантия зависит от операции.
`visit` для объекта без значения бросает `bad_variant_access`.
Для открытого набора типов с общим виртуальным интерфейсом может лучше подойти полиморфизм.
