# 21. Политики выполнения алгоритмов

## Версия C++

`seq`, `par`, `par_unseq`, `reduce`, `transform_reduce` — C++17; `unseq` — C++20. Режим сборки — **C++20**. Достаточно GCC 11+.

## Что изучаем

Разрешаем библиотеке выбирать способ выполнения стандартного алгоритма. Нужны итераторы, лямбды и основы гонок данных.

## Примеры

- [main.cpp](main.cpp) — сумма, преобразование и сортировка; вывод `5050 200`.
- [main2.cpp](main2.cpp) — совмещённые преобразование/свёртка и `unseq`; вывод `55`.

## Как это работает

Сначала массив заполняется числами, затем алгоритм получает политику первым аргументом.
Выходной массив для `transform` заранее имеет достаточный размер; обработчик пишет
только свой результат и не меняет общий счётчик.

| Политика | Что разрешено реализации |
|---|---|
| `seq` | Последовательные вызовы в вызывающем потоке |
| `par` | Параллельные вызовы; допускается и последовательное выполнение |
| `par_unseq` | Параллельность и неупорядоченные, например векторизованные, вызовы |
| `unseq` | Неупорядоченные вызовы в вызывающем потоке, без требования многопоточности |

`reduce` вправе менять группировку и порядок сложения даже с `seq`; `accumulate`
идёт слева направо. Для маленьких целых без переполнения результат совпадает;
для вещественных чисел округление может дать другой результат. `transform_reduce`
объединяет преобразование и свёртку без обязательного промежуточного массива.

В libstdc++ backend выбирается реализацией. Маркер `parallel-backend` подключает
`-ltbb`, если выбранный GCC использует TBB; при последовательном backend он ничего
не добавляет. Сам по себе успешный вызов с `par` не доказывает работу нескольких потоков
или ускорение. Размеры и результаты проверяются независимо от планирования.

## Сборка и запуск

[Настройка и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh stl/additions/21-parallel-algorithms/main.cpp
./build/stl/additions/21-parallel-algorithms/main
```

Для второго примера соберите `main2.cpp` и запустите `main2` из того же каталога сборки.
На Windows из MSYS2 Bash используйте `scripts/build-windows.sh` и файл
`build/stl/additions/21-parallel-algorithms/main.exe`. Конфигурации F5/Ctrl+F5 находятся в `.vscode/`.

Интерактивного ввода и сетевых служб нет. Программы не создают пользовательские файлы.
Каждый вариант проверяет результат:
последняя строка `OK reference-example`, код завершения `0`;
нарушение проверки или необработанная ошибка — код `1`.

## Типичные ошибки

Для стандартных политик исключение из пользовательского обработчика вызывает `terminate`,
в том числе с `seq`; это отличается от обычной перегрузки алгоритма без политики.
Ошибка выделения памяти может дать `bad_alloc`. Для `par_unseq`/`unseq` не использовать
блокирующие операции и захват мьютекса в обработчике. Не менять размер исходного
или выходного вектора во время обработки и не писать в один общий элемент.
