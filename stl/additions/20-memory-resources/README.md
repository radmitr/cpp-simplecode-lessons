# 20. Ресурсы памяти `pmr`

## Версия C++

`memory_resource`, `polymorphic_allocator` и `pmr`-контейнеры — C++17. Режим сборки — **C++17**. Достаточно GCC 11+.

## Что изучаем

Отделяем способ выделения памяти от типа контейнера. Нужны RAII, аллокаторы и время жизни.

## Примеры

- [main.cpp](main.cpp) — арена над массивом без запасного выделения; вывод `7 9`.
- [main2.cpp](main2.cpp) — пул, наблюдение выделений, копирование и присваивание; вывод `all blocks released`.
- [main3.cpp](main3.cpp) — вложенные строки с PMR и без PMR; вывод `80 80`.

## Как это работает

Аллокатор — объект, через который контейнер получает и освобождает память.
`pmr::vector<T>` использует `polymorphic_allocator<T>`: тот обращается к выбранному
`memory_resource` через виртуальные функции, поэтому ресурс выбирается при запуске.

| Ресурс | Поведение |
|---|---|
| `monotonic_buffer_resource` | Выдаёт новые участки; отдельное освобождение не возвращает их в оборот |
| `unsynchronized_pool_resource` | Переиспользует блоки подходящих размеров; сам не синхронизирует обращения |
| `null_memory_resource()` | Любое выделение завершается `bad_alloc` |

Первый пример передаёт арене массив и запрещает запасное выделение через `null_memory_resource`.
Небольшой вектор помещается, запрос на 10000 элементов — нет. Сначала уничтожается
контейнер, затем вызывается `release`: она освобождает блоки ресурса, но **не вызывает
деструкторы объектов**, которые ещё могли бы находиться в них.

При обычном копирующем конструировании PMR-контейнер выбирает текущий ресурс по
умолчанию; явный второй аргумент позволяет задать другой. Копирующее присваивание
сохраняет ресурс получателя. `main2.cpp` проверяет оба правила, не меняя глобальный ресурс.
`main3.cpp` показывает передачу аллокатора вложенной `pmr::string`; обычная `std::string`
в таком векторе продолжает использовать свой обычный аллокатор для символов.

## Сборка и запуск

[Настройка и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh stl/additions/20-memory-resources/main.cpp
./build/stl/additions/20-memory-resources/main
```

Аналогично соберите `main2.cpp` и `main3.cpp`; имена исполняемых файлов — `main2` и `main3`.
На Windows из MSYS2 Bash используйте `scripts/build-windows.sh` и файл
`build/stl/additions/20-memory-resources/main.exe`. Конфигурации F5/Ctrl+F5 находятся в `.vscode/`.

Интерактивного ввода и сетевых служб нет. Программы не создают пользовательские файлы.
Каждый вариант проверяет результат:
последняя строка `OK reference-example`, код завершения `0`;
нарушение проверки или необработанная ошибка — код `1`.

## Типичные ошибки

Ресурс должен жить дольше использующих его контейнеров; исходный массив — дольше арены.
`clear()` вектора не означает возврат памяти монотонной арене. Не вызывать `release`
при живых пользователях. `swap` контейнеров с неравными непередаваемыми аллокаторами
нарушает предусловия. В нескольких потоках нужна внешняя синхронизация либо подходящий
синхронизированный ресурс; PMR сам по себе не делает контейнер потокобезопасным.
