# 06. Необязательное значение `optional`

## Версия C++

`std::optional` — C++17. Режим сборки — **C++17**. Достаточно GCC 11+.

## Что изучаем

Храним либо значение известного типа, либо его отсутствие. Нужны значения, ссылки и исключения.

## Примеры

- [main.cpp](main.cpp) — пустота, значение `0`, проверяемый доступ, запасное значение и `reset`; вывод `9`.
- [main2.cpp](main2.cpp) — `emplace`, перемещение и вычисление запасного значения; вывод `Ada Ada 1`.

## Как это работает

`optional<int>` сначала пуст. `value = 0` создаёт присутствующее число: `bool(value)`
проверяет **наличие**, а не истинность числа. `reset()`/`nullopt` уничтожают хранимое
значение. Оно располагается внутри `optional`; отдельный `new` для самой обёртки не нужен.

| Доступ | Пустой `optional` |
|---|---|
| `*value`, `value->member` | В C++17 нарушается предусловие; сначала проверьте наличие |
| `value.value()` | Исключение `bad_optional_access` |
| `value.value_or(default_value)` | Возвращается запасное значение по значению |

Аргумент `value_or(fallback())` вычисляется **до** вызова `value_or`, даже при наличии
значения. Условный оператор вызывает `fallback()` только в выбранной ветке.
`emplace` уничтожает прежнее значение и конструирует новое на его месте; при ошибке
конструктора обёртка остаётся пустой. Перемещение присутствующего `optional<string>`
не делает исходный `optional` пустым: внутри остаётся строка в допустимом состоянии,
конкретное содержимое которой в общем случае не задано.

Цепочки C++23 уже показаны в [уроке expected](../07-expected/README.md), а
`optional<T&>` и обход из C++26 — в [уроке необязательной ссылки](../10-optional-reference/README.md).

## Типичные ошибки

Отсутствие значения не содержит объяснения причины: для результата с ошибкой подходит
`expected`, для обязательного возвращаемого значения — обычный `T`. Ссылки на содержимое
перестают быть действительными после его уничтожения или замены. В C++17 тип `optional<T&>`
запрещён; `optional<reference_wrapper<T>>` требует отдельно учитывать жизнь объекта.
