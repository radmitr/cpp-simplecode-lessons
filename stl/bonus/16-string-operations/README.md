# 16. Поиск подстроки и заполнение строки

## Версия C++

Режим сборки — **C++23**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках.

## Что изучаем

Проверяем вхождение подстроки и заполняем строку напрямую. Нужны `string` и невладеющий `string_view`.

## Примеры

- [main.cpp](main.cpp) — contains и resize_and_overwrite; вывод `abc`.

## Как это работает

`contains` проверяет наличие символа, C-строки или `string_view` без ручного сравнения с `npos`; поиск чувствителен к регистру. Пустая подстрока найдена в любой строке. `resize_and_overwrite` предоставляет буфер для записи и принимает от переданной функции итоговую длину. В примере запрашивается четыре позиции, записываются три буквы и возвращается `3`; строка становится `abc`. Завершающий ноль управляется самой строкой.

## Сборка и запуск

[Настройка компилятора и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh stl/bonus/16-string-operations/main.cpp
./build/stl/bonus/16-string-operations/main
```

Для остальных вариантов замените `main.cpp` и имя исполняемого файла. На Windows вызовите `scripts/build-windows.sh` через MSYS2 Bash, затем соответствующий файл `build/stl/bonus/16-string-operations/main.exe`. Готовые `tasks.json` и `launch.json` содержат оба варианта системы.

Ввода, сетевых служб и постоянных файлов не требуется, если ниже не указано другое. Каждый пример проверяет результаты; успех — строка `OK modern-example` и код `0`, ошибка проверки — код `1`.

## Типичные ошибки

`string_view` не владеет памятью и не гарантирует завершающий ноль. Функция, переданная в `resize_and_overwrite`, не должен бросать, сохранять указатель или возвращать длину больше полученного размера. Читать незаписанные ячейки нельзя.
