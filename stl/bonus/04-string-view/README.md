# 04. Строковое представление `string_view`

## Версия C++

`string_view`, литерал `sv` — C++17. Режим сборки — **C++17**. Достаточно GCC 11+.

## Что изучаем

Передаём строку без копирования символов и отделяем представление от владельца памяти. Нужны `string`, указатели и время жизни.

## Примеры

- [main.cpp](main.cpp) — границы представления, изменение символов владельцем и нулевой байт; вывод `Ada Eda 3`.
- [main2.cpp](main2.cpp) — подстрока без завершающего нуля и `at`; вывод `abc abc`.

## Как это работает

`string_view` хранит адрес и длину. После `remove_prefix(5)` представление
`name=Ada` показывает `Ada`; исходная строка не изменилась. Пока память владельца
остаётся действительной, изменение символа видно через представление. `string(view)`
создаёт самостоятельную копию. `substr` возвращает новое представление той же памяти.

Конструктор из `const char*` ищет завершающий ноль; форма `(data, size)` и литерал
`"a\0b"sv` сохраняют явно заданную длину, включая нулевые байты. `data()` не обещает
ноль на границе представления. Для API, принимающего C-строку, во втором примере
создаётся `string` и используется её `c_str()`.
Проверка `prefix.data()[3]` читает существующий четвёртый символ владельца `abcdef`;
это обращение по указателю в пределах исходной строки. У самого `prefix` размер `3`, поэтому
`prefix[3]` недопустим, а `prefix.at(3)` бросает исключение.

`at(i)` бросает `out_of_range`, если индекс недопустим. Для `operator[]`,
`remove_prefix`/`remove_suffix` границы обязан соблюдать вызывающий код.
`find` возвращает `npos`, если совпадения нет; проверяйте это до арифметики индекса.

## Типичные ошибки

Не возвращать представление локальной строки и не сохранять представление временного `string`.
Перераспределение памяти строки инвалидирует представления; `string_view` не отслеживает его.
Он запрещает запись **через свой интерфейс**, но не мешает владельцу менять символы.
Поиск `contains` появился позже: [операции строк C++23](../13-string-operations/README.md).
