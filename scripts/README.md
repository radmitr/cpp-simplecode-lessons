# Скрипты сборки

build-linux.sh и build-windows.sh собирают один выбранный .cpp.
Запускайте их через Bash, передавая путь к существующему файлу.

Из корня репозитория, Linux:

~~~bash
bash scripts/build-linux.sh multithreading/lesson-10-unique-lock/main.cpp
./build/multithreading/lesson-10-unique-lock/main
~~~

Из корня репозитория, Windows / MSYS2 Bash:

~~~bash
bash scripts/build-windows.sh multithreading/lesson-10-unique-lock/main.cpp
./build/multithreading/lesson-10-unique-lock/main.exe
~~~

## Компилятор и результат

Linux использует /usr/bin/g++, Windows — C:/msys64/mingw64/bin/g++.exe.
Скрипт определяет корень проекта по собственному расположению.
Поэтому путь к исходнику может быть абсолютным или относительным к текущей папке.
Файлы за пределами репозитория скрипт отклоняет.

Результат сохраняется в build/ с тем же относительным путём, что у исходника.
main.cpp и main2.cpp собираются отдельно. Если рядом есть SimpleTimer.cpp
или String.cpp, скрипт добавляет их как вспомогательные исходники.
Для src/main.cpp с соседней папкой include/ собираются все .cpp из src/.

## Стандарт C++

По умолчанию выбирается c++17. Если в папке исходника существует
cxx-standard.txt, скрипт читает стандарт из него.
Файл должен содержать одну строку c++17 или c++20 без пробелов.
Другие значения вызывают ошибку; пример для C++20 находится в
[бонусе про jthread](../multithreading/bonus/06-jthread-stop-token/).

~~~bash
standard=c++17
if [[ -f $source_dir/cxx-standard.txt ]]; then
    standard=$(<"$source_dir/cxx-standard.txt")
    standard=${standard//$'\r'/}
    case $standard in
        c++17|c++20) ;;
        *) printf 'Unsupported C++ standard: %s\n' "$standard" >&2; exit 2 ;;
    esac
fi
~~~

- [[ -f ... ]] проверяет наличие обычного файла.
- $(<"...") читает файл, как $(cat "..."), и убирает завершающие символы LF.
- ${standard//$'\r'/} удаляет символы CR, которые могут остаться от окончаний CRLF.
- c++17|c++20) ;; — пустая ветка case для двух разрешённых значений.
- *) — ветка для остальных значений; ;; завершает ветку.
- "-std=$standard" передаёт выбранный стандарт компилятору.

В Windows-файле одна строка может оканчиваться на CRLF (\r\n).
После подстановки команд останется CR (\r); отдельная замена удаляет и его.
Файл на диске при чтении не изменяется.

## Связь с VS Code

Задача C/C++: Build вызывает нужный скрипт для активного файла.
При копировании урока проверьте пути к scripts/ и build/ в его
.vscode/tasks.json и .vscode/launch.json: они зависят от глубины папки.

Ctrl+Shift+B, F5 и Ctrl+F5 вызывают сборку без генерации настроек IntelliSense.
Для обновления настроек выполните
**Terminal → Run Task… → C/C++: Update IntelliSense**.
Эта задача доступна в корне, отдельных уроках, примерах и шаблоне на Windows
и Linux. Она запускает generate-compile-commands.sh, который создаёт и обновляет
общую базу IntelliSense и локальные конфигурации уроков. Открытый `.cpp` не нужен.
Выполните задачу после клонирования; при простом открытии папки генератор
не запускается. Из терминала в корне репозитория его можно вызвать отдельно:

~~~bash
bash scripts/generate-compile-commands.sh
~~~

Генератор записывает build/compile_commands.json для всех .cpp из каталогов
уроков, примеров и шаблона, включая вспомогательные исходники. Каждая запись
описывает компиляцию одного исходника; для уроков 139–140 добавлен include/.
Стандарт выбирается из cxx-standard.txt рядом с исходником.
База используется корневой .vscode/c_cpp_properties.json и сгенерированными
конфигурациями в папках с .vscode/tasks.json внутри каталогов уроков,
примеров и шаблона. Корневую конфигурацию генератор не изменяет.
Локальные файлы содержат конфигурации Linux и Win32 с относительным путём
к общей базе и резервным стандартом из cxx-standard.txt. Для уроков 139–140
маркер ищется в src/ рядом с main.cpp. Глобальные настройки VS Code не нужны.

После добавления, удаления или переименования исходников, изменения стандарта,
компилятора или флагов повторите задачу C/C++: Update IntelliSense.
При обычном редактировании кода повторная генерация не нужна. При изменении
флагов в build-linux.sh или build-windows.sh обновите их и в генераторе.

Локальные c_cpp_properties.json создаются в формате JSON с комментарием,
который поддерживает расширение C/C++. Первая строка содержит имя генератора
и SHA-256 остального содержимого. Генератор обновляет только файлы с корректной
меткой и контрольной суммой; существующие пользовательские файлы, символические
ссылки и отредактированные вручную конфигурации сохраняются. Их пути выводятся
в сообщениях Keeping custom IntelliSense configuration. Чтобы снова генерировать
конфигурацию автоматически, удалите этот локальный файл и повторите задачу
C/C++: Update IntelliSense.
Неизменившиеся конфигурации и база сохраняют время изменения.

На Windows генератор переводит пути в формат C:/... через MSYS2 cygpath.
Базу нужно создавать на текущей системе; переносить её между компьютерами
не следует. Она находится в игнорируемом build/, а сгенерированные локальные
конфигурации также игнорируются Git. На новом компьютере или после переключения
между Windows и Linux выполните C/C++: Update IntelliSense заново.

Все примеры команд сборки приведены для Bash. Сам Bash запускает компилятор,
а C++ выполняется в собранной программе.

## ThreadSanitizer

В [бонусе 26](../multithreading/bonus/26-thread-sanitizer/) есть отдельный
run-tsan.sh для диагностики гонки данных на Linux/WSL:

~~~bash
bash multithreading/bonus/26-thread-sanitizer/run-tsan.sh main.cpp
bash multithreading/bonus/26-thread-sanitizer/run-tsan.sh main2.cpp
~~~

Он выбирает clang++ (либо компилятор из CXX), добавляет -fsanitize=thread,
-O1 и -g, затем запускает результат. Нужна соответствующая библиотека TSan.
main.cpp исправлен, main2.cpp намеренно содержит гонку: отчёт и код 66
для него ожидаемы. Обычные build-linux.sh/build-windows.sh и F5 эти флаги
не добавляют. Бинарники с суффиксом -tsan сохраняются отдельно в build/.
