# Шаблон нового урока

[Lesson-00-](Lesson-00-/README.md) — видимая заготовка с минимальным
`main.cpp` и настройками VS Code. Имя `_template/` сохраняется:
это общая часть проекта, которую удобно найти в проводнике.

## Где создавать урок

В обычные каталоги курса добавляйте только подтверждённые исходные темы
с их номерами. Новые самостоятельные сценарии размещайте в `additions/`
соответствующего раздела; целое новое направление — в корневом `additions/`.
Дополнительные `main2.cpp` тоже подчиняются этому правилу.
Личные промпты и черновики храните в игнорируемой `.local/`.

## Что проверить после копирования

1. Переименуйте папку по теме и глубине: например `basics/additions/31-topic/`.
2. В `.vscode/tasks.json` и `launch.json` исправьте пути к `scripts/`
   и `build/`. Исправьте также включение `common/console.hpp` в исходнике:
   для глубины три нужен префикс `../../../`.
3. Замените пустое тело реальным примером, укажите в комментарии версии API.
4. Подготовьте README по структуре: «Версия C++», «Что изучаем», «Примеры»,
   «Как это работает», «Сборка и запуск», «Типичные ошибки»,
   «Связанные темы и источники». Пустые разделы не нужны.
5. Различайте дату появления API и режим сборки. Для режима, отличного
   от C++17, добавьте `cxx-standard.txt`; при необходимости — `gcc-min-version.txt`.
6. Дайте ссылку на общий запуск с **F5** и **Ctrl+F5**. В самом уроке опишите
   ввод, файлы/службы, допустимый вывод, код завершения и намеренное ожидание/ошибку.
7. Соберите и запустите безопасные варианты, проверьте локальные ссылки,
   добавьте урок в каталог и обновите IntelliSense.

`main.cpp`, `main2.cpp` и следующие варианты — независимые программы.
Их нельзя компоновать вместе, если у каждого есть `main()`.
Сначала ссылайтесь на уже существующий пример; не создавайте копии ради другого имени.
