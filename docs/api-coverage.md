# Покрытие API запускаемыми примерами

## Что проверено

Проверены README всех уроков проекта: упоминания API, примеры кода,
самостоятельные `main`-варианты и локальные вспомогательные заголовки.
При сверке учитываются реализации в общих заголовках сетей, PostgreSQL,
рефлексии и пула потоков: отсутствие вызова непосредственно в `main.cpp`
не означает отсутствие кода.

Упоминания разделены по смыслу:

- Механизм разбирается по шагам — нужен полный запускаемый исходник.
- Приводится короткая альтернатива — нужна именованная ссылка к её объяснению
  и существующему коду.
- Описано ограничение или запрещённая операция — оно явно объясняется;
  выполнять UB ради демонстрации нельзя.
- Название встречается в метке версии, перечне или предварительных требованиях —
  это не утверждение, что в этом файле реализован отдельный пример API.

Добавлены **63 дополнительных перехода к коду в 55 README**.
Названия уроков и полные исходники доступны по ссылкам; новые сценарии
размещены в бонусах. Это аудит содержания справочника, а не заявление,
что реализованы все API и все возможные случаи C++.

## Что проверяет автоматическая команда

`python scripts/check-docs.py` (Linux: `python3`) проверяет локальные цели
и якоря ссылок, ссылки на полные исходники, порядок разделов,
доступность скриптов и каталоги вывода конфигураций VS Code.
Также отвергает типичную неточную подпись «команды» с якорем требований,
голый номер в подписи ссылки и служебные адреса webview.

Это не анализатор семантики C++: наличие слова в исходнике не доказывает
правильную реализацию, а отсутствие слова может объясняться заголовком,
псевдонимом или другой формой записи. Внешние сайты этой командой не проверяются.
[Выполненные сборки и границы проверки платформ](validation.md).
