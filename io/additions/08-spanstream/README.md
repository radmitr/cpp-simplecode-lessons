# 08. Потоки над готовым буфером

## Версия C++

Режим сборки — **C++23**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках.

## Что изучаем

Форматируем и читаем данные в заранее предоставленном массиве. Нужны строковые потоки и `span`.

## Примеры

- [main.cpp](main.cpp) — запись и повторный разбор; вывод `7 2.5`.
- [main2.cpp](main2.cpp) — переполнение и раздельные позиции общего spanstream.

## Как это работает

`ospanstream` записывает в память вызывающего кода, `ispanstream` читает из неё, `spanstream` совмещает оба направления. В первом примере запись `7 2.5` создаёт пять символов; `span()` возвращает записанную часть без требования завершающего нуля. Затем входной поток разбирает именно этот диапазон. Во втором примере слишком маленький буфер приводит к ошибочному состоянию потока. Вариант с общим потоком возвращает позицию чтения к началу через `seekg`.

## Сборка и запуск

[Настройка компилятора и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/additions/08-spanstream/main.cpp
./build/io/additions/08-spanstream/main
```

Для остальных вариантов замените `main.cpp` и имя исполняемого файла. На Windows вызовите `scripts/build-windows.sh` через MSYS2 Bash, затем соответствующий файл `build/io/additions/08-spanstream/main.exe`. Готовые `tasks.json` и `launch.json` содержат оба варианта системы.

Ввода, сетевых служб и постоянных файлов не требуется, если ниже не указано другое. Каждый пример проверяет результаты; успех — строка `OK modern-example` и код `0`, ошибка проверки — код `1`.

## Типичные ошибки

Поток не увеличивает переданный буфер. Не трактуйте `.data()` как гарантированную C-строку. Проверяйте состояние после записи и чтения. Массив должен жить дольше потока и выданных представлений.
