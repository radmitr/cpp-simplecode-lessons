# 07. Буферизация, `endl` и `flush`

## Версия C++

`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`endl` вставляет перевод строки и запрашивает `flush`, обычный `\n`
сам по себе не делает второй операции. Реальные стандартные потоки имеют также
tie и `unitbuf`, а терминал/stdio — собственное поведение буферизации. Метод
подсчёта `flush` отделяет семантику от шумного измерения времени. `sync_with_stdio(false)`
вызывают до работы со стандартными потоками и затем не полагаются на согласованный
порядок смешанного C/C++-вывода. `flush` не равен гарантии сохранения на физический диск.

## Как это работает

Нужны потоковая запись, перевод строки и `streambuf`.

`CountingBuffer` считает вызовы `sync`. Три записи '\n' не вызывают его,
`std::flush` добавляет один вызов, три `endl` — ещё три.
Итоговый счётчик после всех действий равен 4.

~~~cpp
for(int i=0;i<3;++i) output << i << '\n';
// Между циклами в исходнике проверяется число вызовов sync().
output << std::flush;
for(int i=0;i<3;++i) output << i << std::endl;
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

В реальном `cout` буферизация зависит также от терминала, синхронизации с C stdio,
связанных потоков и unitbuf. Проверка использует собственный буфер, чтобы
отделить смысл манипуляторов от поведения конкретной консоли.

`flush` не гарантирует физическую сохранность данных на диске при потере питания.
Слишком частый `endl` может замедлять большой вывод.
После `sync_with_stdio(false)` не рассчитывайте на прежнее согласование
`cout` с printf; это отдельная настройка, её в примере не меняют.

## Типичные ошибки

Перевод строки и `flush` — разные действия. Частый `endl` может добавлять лишние сбросы, но поведение конкретной консоли не доказывает контракт буфера. `flush` не гарантирует сохранность на физическом носителе при сбое питания.
