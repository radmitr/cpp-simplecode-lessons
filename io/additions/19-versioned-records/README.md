# 19. Записи, длины, версии и контрольная сумма

## Версия C++

`auto`, псевдонимы using — **C++11**.
`std::vector`, `std::string`, `std::exception`, `std::runtime_error`, `std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Формат REC2: четыре ASCII-байта версии, uint32 количества, затем
для каждой записи uint32 `id`, uint32 длины и байты имени; в конце uint32 FNV-1a
контрольной суммы всех предыдущих байтов. Все числа little-endian. Ограничения
1000 записей/4096 байтов имени проверяются до выделения соответствующей памяти.
FNV обнаруживает многие случайные изменения, но не является криптографической
защитой и допускает коллизии. Кодек работает в памяти; запись массива в файл
повторяет [Явный бинарный формат вместо записи объекта целиком](../18-portable-binary/README.md). Байты имени подразумевают согласованную кодировку, которую
этот кодек отдельно не валидирует.

## Как это работает

Нужны явный бинарный формат, длины строк и проверка границ.

Формат начинается с REC2, затем идут число записей и для каждой записи
`id`, длина имени и байты имени. Целые кодируются явно младшим байтом вперёд;
в конце лежит 32-битная контрольная сумма.

Имена ограничены 4096 байтами, число записей — 1000. Декодер проверяет
длины до построения строк, а в конце требует полного потребления полезных байтов.
Две записи {7, Ada}, {9, Bob} проходят обратное преобразование.

~~~cpp
if (length > 4096 || length > end - offset) {
    throw std::runtime_error("invalid name length");
}
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Вычитание после проверки границ помогает избежать переполнения offset + `length`.
Изменение байта и усечённый заголовок в `main` отвергаются.

Контрольная сумма обнаруживает ряд повреждений, но не доказывает подлинность:
её можно пересчитать после изменения. Для недоверенного источника нужна
отдельная аутентификация. Версия описывает правила всего формата; добавление
полей требует совместимого протокола чтения старых/новых записей.

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

### Результат и проверка

После показанных в коде значений последняя строка — `OK 19-versioned-records`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.

Проверка всего раздела: `python scripts/check-additions.py --section io/additions`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Нельзя доверять длине из файла до проверки лимита и оставшихся данных. Версия формата должна проверяться до разбора соответствующей схемы. Нативная запись структуры не заменяет заданные размеры и порядок байтов.

### Самостоятельно
