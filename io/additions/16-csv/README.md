# 16. CSV с кавычками и многострочными полями

## Версия C++

`std::string_view` — **C++17**.
`auto`, лямбды, псевдонимы using — **C++11**.
`std::vector`, `std::string`, `std::exception`, `std::invalid_argument`, `std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

CSV нельзя корректно разбирать простым split по запятой или `getline`
по строке: разделители и переводы строк могут находиться в кавычках. Этот небольшой
парсер поддерживает выбранный диалект с запятой, двойными кавычками и LF/CRLF,
сохраняет пустые поля и диагностирует незакрытую кавычку. Пробелы после закрывающей
кавычки не допускаются. Число столбцов и типы полей проверяются отдельно моделью.
Для недоверенных больших файлов добавьте лимиты; для полного промышленного
решения выбирайте специализированную библиотеку и явно согласуйте диалект.

## Как это работает

Нужны строки, конечный автомат и вложенные контейнеры.

Здесь CSV разбирается автоматом состояний: `quoted` означает поле в кавычках,
closed — закрытую кавычку, pending — наличие незавершённой записи.
Поэтому запятая и перевод строки внутри `quoted` становятся содержимым поля.

В примере Ada, A — одно поле, line1 и line2 — одна многострочная ячейка,
а a""b внутри кавычек превращается в a"b. Последнее пустое поле тоже сохраняется.
Всего получается пять записей вместе с заголовком.

Обычный `getline` по строке, затем split по запятой не разберёт эти случаи.
Незакрытая кавычка, кавычка в незакавыченном поле и текст сразу после
закрывающей кавычки отклоняются. Пустой ввод даёт ноль записей.

Это конкретный диалект с запятой и фиксированными правилами кавычек.
Для больших/внешних входов дополнительно ограничивают размер поля,
число записей и объём памяти. Заголовки, типы столбцов и схема проверяются
следующим этапом, а не самим синтаксическим разбором CSV.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 16-csv`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.

Проверка всего раздела: `python scripts/check-additions.py --section io/additions`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Разделитель и перевод строки внутри кавычек принадлежат полю. Проверка CSV-синтаксиса не определяет типы столбцов или число обязательных полей. Правила диалекта и лимиты больших входов задаются отдельно.

### Самостоятельно

Добавьте ограничение размера поля и числа столбцов, затем преобразуйте id через `from_chars` с указанием номера записи в ошибке.
