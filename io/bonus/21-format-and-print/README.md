# 21. `std::format` и `std::print`

## Версия C++

`std::println` — **C++23**.
`std::format`, `std::vformat` — **C++20**.
`auto` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++23**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`std::format` возвращает строку (C++20), `std::print` и `std::println` выводят её без
привычной цепочки `operator<<` (C++23). Этот объединённый пример требует
libstdc++ с print, поэтому исходный `main.cpp` требует GCC 14; только `format` появился в GCC 13.
Новые варианты с форматированием диапазонов требуют более новой библиотеки;
общая конфигурация этого урока теперь выбирает GCC 16.
Проверка литеральных форматных строк может выполняться при компиляции,
для runtime-строки используется `vformat` с обработкой format_error.
На Ubuntu с GCC 11 урок требует `CXX_MODERN`, остальные обычные бонусы — нет.

`link-libraries.txt` подключает stdc++exp. В MinGW это требуется для реализации
терминального вывода `std::print`; отсутствие библиотеки даёт ошибку линковки,
хотя заголовок print уже найден. Общие скрипты добавляют -lstdc++exp после
исходников. [Параметры libstdc++](https://gcc.gnu.org/onlinedocs/libstdc++/manual/using.html).

## Как это работает

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

`format` строит строку, `std::print` и `std::println` выводят её.
{:04} задаёт минимум четыре позиции с нулевым заполнением,
{:.2f} — две цифры после десятичной точки.
Для 7 и 1.25 результат id=0007, score=1.25.

~~~cpp
auto text = std::format("id={:04}, score={:.2f}", 7, 1.25);
std::println("{}", text);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Строка формата с проверяемым литералом позволяет компилятору обнаружить
многие ошибки. Для runtime-текста в данном примере используется `vformat`
с make_format_args; одиночная { вызывает format_error.
Переносимые способы runtime-форматов зависят от выбранной версии стандарта.

format_error отличается от ошибки записи в устройство: успешное построение
строки не гарантирует успешный вывод. `format` — C++20, `std::print` и `std::println` — C++23;
этому уроку нужна также достаточная версия стандартной библиотеки,
а не только режим `-std=...`. Точные требования заданы рядом с исходником.

`main2.cpp` показывает добавленное в C++23 форматирование контейнеров и tuple: `[1, 2, 3] | (7, "Ada")`. Диапазон обходится во время форматирования; его элементы должны быть форматируемыми. `main3.cpp` показывает formatter пользовательского `Point`: `parse` проверяет спецификацию, `format` пишет результат в предоставленный контекст. Эта специализация поддерживает только пустую спецификацию. Она не обещает поддержку ширины и выравнивания.

Оба новых варианта завершаются `OK modern-example`, код `0`; ввода, служб и файлов нет. Дополнительные возможности форматирования требуют достаточно новой стандартной библиотеки; учебная конфигурация новых вариантов — GCC 16.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 21-format-and-print`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

### Самостоятельно

Добавьте форматтер своего простого типа и сравните его с `operator<<`, отдельно сохраняя обработку ошибок runtime-формата.
