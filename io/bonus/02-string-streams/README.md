# 02. Строковые потоки и разбор записей

## Версия C++

`std::string`, `std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`istringstream` читает из строки теми же операциями, что `ifstream`,
`ostringstream` формирует строку. После формального успеха проверьте лишний хвост.
Для повторного использования отдельно замените буфер через `str` и сбросьте
состояние через `clear`: это разные действия. Разбор по пробелам не поддерживает
произвольные строки с пробелами и не является CSV/JSON-парсером.

## Как это работает

Нужны `string`, потоковое чтение, EOF и флаги состояния.

`istringstream` оборачивает строку 7 Ada 42 в обычный интерфейс чтения.
Цепочка >> заполняет `id`, `name` и `score`, `std::ws` потребляет хвостовые пробелы,
а eof после этого подтверждает отсутствие дополнительного содержимого.

`ostringstream` делает обратную операцию: собирает текст 7:Ada:42.
Это удобно для проверки точного вывода без перенаправления глобального `cout`.

~~~cpp
input.clear();
input.str("9 Bob 10");
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`str` меняет исходный текст, `clear` сбрасывает флаги прежнего чтения.
Это разные действия: замена строки не является универсальным сбросом состояния.
`operator>>` для `string` читает слово; имя с пробелами требует другого формата,
например `getline` с разделителем или CSV/JSON.

## Типичные ошибки

Замена строки через `str()` не сбрасывает флаги состояния; для повторного чтения нужен `clear()`. Успешно разобранный префикс ещё не подтверждает отсутствие лишних полей. `operator>>` для строки не сохраняет пробелы внутри поля.

### Самостоятельно

Разберите запись с отсутствующим score и запись с лишним четвёртым полем, сохраняя исходный объект при ошибке.
