# 11. Ошибки записи, исключения и закрытие

## Версия C++

`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Неудачное открытие и неудачная запись — разные события. Собственный
`streambuf` воспроизводимо отказывает в записи без заполнения реального диска.
По умолчанию `ostream` устанавливает флаги; маска `exceptions` включает выбрасывание.
Установка самой маски также может выбросить исключение при уже установленном
соответствующем флаге. Успех записи в буфер не гарантирует успех последующего
`flush()` и `close()`, а RAII-деструктор не является удобным каналом сообщения об ошибке сохранения.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны состояние потока, буфер и исключения.

`FailingBuffer` специально отказывает при записи: overflow возвращает EOF.
Первая попытка `output` << ... отражает неудачу в состоянии потока,
не выбрасывая исключение при стандартной маске.

~~~cpp
output.clear();
output.exceptions(std::ios::badbit | std::ios::failbit);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

После очистки задаётся маска исключений. Следующая неудачная запись
выбрасывает `ios_base::failure`, которую программа перехватывает.
Если включить маску при уже выставленном соответствующем флаге,
исключение может возникнуть в самом `exceptions(...)`.

Успешное открытие не означает успешную последующую запись или close.
RAII закрывает ресурс, но не предоставляет вызывающему обычный способ
получить ошибку из деструктора. Для ответственного сохранения проверьте
запись и явное закрытие до сообщения об успехе.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 11-io-errors`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.

Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Открытие, запись, `flush` и `close` могут отказывать независимо. Установка маски `exceptions` сама может бросить при уже выставленном флаге. Для сообщения об успехе сохранения проверьте явное закрытие, не только деструктор.

### Самостоятельно

Добавьте контекст имени файла к перехваченному исключению через `throw_with_nested` и сохраните исходную причину.
