# 08. Блочная обработка и неполный последний блок

## Версия C++

`std::filesystem` — **C++17**.
`std::array` — **C++11**.
`std::string`, `std::exception`, `std::runtime_error` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

read может заполнить только часть буфера и установить EOF. Записывать
нужно `gcount` байтов, а не весь буфер. Функция копирования использует постоянный
буфер независимо от размера файла; небольшой исходный `string` здесь только
создаёт контрольные данные для проверки. Нельзя открывать тот же файл как
источник и цель с trunc. Пример предполагает разные пути внутри собственной
временной папки и не сохраняет права/время файла.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны бинарные потоки, буфер массива и флаги EOF.

read запрашивает 4096 байтов. У файла из 10003 байтов два полных блока
и последний неполный 1811 байт. Последний read может установить флаги конца,
но `gcount` всё ещё сообщает успешно полученную часть.

~~~cpp
while (input.read(buffer.data(), buffer.size()) || input.gcount() != 0) {
    output.write(buffer.data(), input.gcount());
}
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Если писать весь `buffer.size()` на последнем шаге, в копию попадёт лишний хвост.
Если обрабатывать только полностью успешные read, последняя часть потеряется.
Пустой файл тоже корректно превращается в пустую копию.

После цикла отличают нормальный EOF от ошибки чтения, затем явно проверяют
закрытие выхода. Такой копировщик не поддерживает совпадающие source/target:
открытие назначения с trunc могло бы стереть источник.
При ошибке уже записанная часть назначения остаётся; сильной гарантии замены нет.

## Типичные ошибки

Последний неполный блок записывают по `gcount()`, а не по размеру буфера. Открытие совпадающего назначения с `trunc` может стереть источник. Успешное чтение всех блоков не освобождает от проверки закрытия выходного файла.

### Самостоятельно

Добавьте явный отказ при `equivalent(source,target)` и проверьте размеры 0, 4096, 4097 и несколько блоков.
