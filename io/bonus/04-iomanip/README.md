# 04. Форматирование и состояние потока

## Версия C++

`std::quoted` — **C++14**.
`auto` — **C++11**.
`std::string`, `std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`fixed` и `setprecision` управляют представлением числа, `setw` обычно
действует только на следующее форматируемое поле, `setfill` сохраняется.
Пользовательская функция не должна незаметно оставлять чужому потоку другие
`flags`/`precision`/`fill`. `quoted` экранирует кавычки для своего формата, но не
заменяет правила CSV или JSON. Для стабильных машинных данных задавайте
`locale::classic` и формат явно.

## Как это работает

Нужны потоковая запись, числовой формат и строковые потоки.

`fixed` с `setprecision(2)` печатает 1.25 с двумя знаками после точки.
`setw(4)` и `setfill('0')` оформляют 7 как 0007; итог: 1.25 0007.

Ширина `setw` обычно относится только к следующему полю.
`flags`, `precision` и `fill` сохраняются в потоке дольше, поэтому функция
форматирования должна вернуть чужому потоку прежние настройки.

~~~cpp
const auto flags = out.flags();
// Изменение оформления...
out.flags(flags);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Одних `flags` недостаточно для восстановления `precision`/`fill`: пример сохраняет
их отдельно. При `exceptions` для автоматического восстановления используют
RAII-охранник. `quoted` записывает пробелы и кавычки в собственном формате
потокового обмена; он не является кодировщиком JSON или универсального CSV.

## Типичные ошибки

`setw` обычно задаёт ширину только следующего подходящего поля, а `fixed`, точность и заполнитель сохраняются. Ширина не является пределом длины. `quoted` помогает с кавычками в строке, но не является универсальным JSON-экранированием.
