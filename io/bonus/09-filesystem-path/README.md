# 09. Пути, cwd и имена Unicode

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: c++17. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

path хранит платформенное представление пути; используйте operator/
для составления компонентов. Текущая рабочая папка — свойство процесса, а не
расположение exe. absolute/lexically_normal/canonical решают разные задачи:
лексическая нормализация не доказывает существование и не разрешает симлинки.
В C++17 u8path преобразует UTF-8-имя в нативное представление. В C++20 тип u8-строк
меняется; переносите путь через path, а не печатайте wide-буфер как char*.

## Разбор кода и полезные варианты

path хранит путь в представлении, подходящем платформе.
Оператор / соединяет компоненты, extension выбирает .txt,
parent_path — каталог, filename — последний компонент.

Программа создаёт folder with spaces/данные.txt в своём временном каталоге,
записывает payload и читает обратно. u8path в C++17 сообщает, что исходные
байты имени заданы в UTF-8; поток получает filesystem::path, а не случайную
строку в текущей кодовой странице Windows.

lexically_relative выполняет текстовую операцию над компонентами,
не проверяя реальное существование или разрешение симлинков.
Для фактического разрешения есть canonical/weakly_canonical с другими условиями.

Относительный путь зависит от current_path процесса. Путь исходника, папка
бинарника и рабочая папка — разные понятия.
Существование файла не означает, что его удастся открыть; ошибки нужно
обрабатывать непосредственно у файловой операции.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/09-filesystem-path/main.cpp
./build/io/bonus/09-filesystem-path/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 09-filesystem-path`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).
