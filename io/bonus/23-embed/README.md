# 23. Включение файла через embed

## Версия C++

Режим сборки — **C++26**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках. Для C++26 реализация ещё может быть неполной.

## Что изучаем

Встраиваем байты файла в исполняемую программу при компиляции. Нужны препроцессор, массивы и числовое представление байтов.

## Примеры

- [main.cpp](main.cpp) — байты ресурса и limit/prefix/suffix/if_empty.

## Как это работает

Препроцессор читает `sample.bin` рядом с исходником и подставляет список целых значений вместо `#embed`. Во время выполнения исходный файл уже не нужен. `limit(2)` берёт только первые два байта, `prefix` и `suffix` окружают непустой список, `if_empty` задаёт содержимое для пустого файла. Пример использует все четыре параметра, не создавая непереносимый массив нулевой длины.

## Сборка и запуск

[Настройка компилятора и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/23-embed/main.cpp
./build/io/bonus/23-embed/main
```

Для остальных вариантов замените `main.cpp` и имя исполняемого файла. На Windows вызовите `scripts/build-windows.sh` через MSYS2 Bash, затем соответствующий файл `build/io/bonus/23-embed/main.exe`. Готовые `tasks.json` и `launch.json` содержат оба варианта системы.

Ввода, сетевых служб и постоянных файлов не требуется, если ниже не указано другое. Каждый пример проверяет результаты; успех — строка `OK modern-example` и код `0`, ошибка проверки — код `1`. При сборке читаются поставляемые с уроком `sample.bin` (байты `41 42 43 00`) и пустой `empty.bin`; при запуске файлы не читаются.

## Типичные ошибки

Это действие сборки, а не чтение файла программой. После изменения ресурса нужна пересборка. В бинарном файле может быть нулевой байт, поэтому `strlen` не измеряет его размер. Не подставляйте сетевые адреса вместо имён файлов. Требуется поддержка директивы компилятором, а не только заголовок.
