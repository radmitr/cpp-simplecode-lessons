# 20. Файловый журнал и ограничение размера

## Версия C++

`std::filesystem` — **C++17**.
`std::move`, `std::chrono`, `std::error_code`, `std::to_string`, `auto` — **C++11**.
`std::string`, `std::exception`, `std::runtime_error`, `std::invalid_argument` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Журнал добавляет время и уровень, проверяет размер отдельной записи,
при необходимости переименовывает прежний файл и сохраняет один архив.
Это синхронный однопоточный пример, а не production logging framework:
нет межпроцессных блокировок, асинхронной очереди и гарантии сохранения при сбое.
Не пишите в журнал секретные значения автоматически. Ошибка записи должна
иметь явную политику, а обработчик ошибки журналирования не должен рекурсивно
писать в тот же отказавший журнал.

## Как это работает

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

`Logger` формирует строку из времени, уровня и сообщения. Перед добавлением
проверяет предел 80 байт: если файл переполнится, текущий становится .1,
а запись идёт в новый основной файл. После шести событий event 5 должно
быть в основном файле. Старый архив .1 заменяется при следующей ротации.

Запрет CR/LF не позволяет одной записи изображать несколько строк журнала.
Отдельная проверка отвергает сообщение, которое само больше лимита.
Открытие с app|binary дописывает байты без текстового преобразования LF.

Это одноуровневая ротация, а не полная система журналирования:
архив только один, повторный запуск не обязан сохранять всю историю.
Несколько потоков/процессов здесь не синхронизированы. Проверка размера,
переименование и добавление записи не образуют одной атомарной операции.

Время system_clock отображено числом секунд, а не локальной датой.
Не проверяйте конкретное значение timestamp в ожидаемом выводе.
Для измерения длительности операции вместо календарных часов нужны steady_clock.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/20-file-logger/main.cpp
./build/io/bonus/20-file-logger/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

После показанных в коде значений последняя строка — `OK 20-file-logger`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).
