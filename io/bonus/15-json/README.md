# 15. JSON: библиотека, типы и обязательные поля

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: c++17. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

Внешняя header-only библиотека nlohmann/json разбирает синтаксис
и экранирование. Модель отдельно проверяет обязательность, неизвестные ключи,
типы и диапазоны до изменения исходного состояния. Получение int без проверки
представимости не является полной валидацией. Принадлежность ключа объекту
не делает null подходящим значением. Установка и локальный вариант зависимости
описаны в dependencies.md; не пишем собственный упрощённый JSON-парсер.

## Разбор кода и полезные варианты

Библиотека сначала разбирает JSON-синтаксис, затем parse_config проверяет
модель: объект ровно с name/count, строковое имя и целочисленное количество
от 0 до 1000. Корректный JSON не обязательно является корректной конфигурацией.

~~~json
{"name":"Ada","count":3}
~~~

В main успешно получается Config с Ada и 3. Неизвестный extra, отсутствие
поля, неверный тип и отрицательное число отвергаются.
dump формирует текст, parse(dump) восстанавливает тот же JSON-объект;
порядок ключей в строке не является частью этой проверки.

document.at(key) подходит для обязательного поля с проверкой, contains
позволяет явно выбрать политику отсутствия. null, отсутствующий ключ,
пустая строка и ноль — разные состояния.
Преобразование большого JSON-числа в C++ int требует проверки диапазона.
Зависимость nlohmann/json описана в README раздела.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/15-json/main.cpp
./build/io/bonus/15-json/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 15-json`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).
