# 06. Создание, перезапись, app, ate и binary

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: `c++17`. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

app направляет каждую запись в конец, ate только задаёт исходную позицию
после открытия и допускает последующий seek. Не все комбинации режимов имеют
смысл; in|`out` обычно не создаёт отсутствующий файл, а `ofstream` по умолчанию
заменяет содержимое. binary отключает текстовые преобразования платформы,
но не определяет кодировку или endian. Все операции примера выполняются
в собственной временной папке, а не над учебным `myFile.txt`.

## Разбор кода и полезные варианты

Файл проходит состояния abc → abcd → Xbcd → z.
app добавляет d в конец. ate начинает с конца **один раз**,
после чего `seekp(0)` позволяет заменить первый байт на X.
trunc стирает прежнее содержимое при открытии.

~~~cpp
std::fstream io(file, std::ios::in | std::ios::out | std::ios::ate);
io.seekp(0);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Флаги объединяются побитовым |. app удерживает каждую запись у конца;
ate допускает дальнейшее позиционирование. Это не взаимозаменяемые метки.
binary запрещает текстовые преобразования платформы, но не задаёт формат
чисел, кодировку строк или атомарность записи.

Обычный in|`out` может требовать уже существующий файл. `ofstream` при стандартном
режиме обычно открывает с очисткой, поэтому для дополнения явно выбирают app.
Все эти опыты выполняются в отдельном `LessonWorkspace`.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/06-open-modes/main.cpp
./build/io/bonus/06-open-modes/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
F5 — запуск с отладчиком; Ctrl+F5 — без отладчика.

В VS Code открывайте `main.cpp` и нажимайте F5/Ctrl+F5: доступны корневая и локальная конфигурации.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 06-open-modes`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).
