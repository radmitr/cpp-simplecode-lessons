# 02. Явный бинарный формат вместо записи объекта целиком

Продолжение урока 117. Нужны бинарные потоки, массивы, сдвиги целых чисел,
uint32_t и try/catch. Стандарт — C++17.

## Формат

Файл содержит ровно 16 байтов:

- Смещения 0–3: ASCII-заголовок PT01, где 01 обозначает версию формата.
- Смещения 4–7: поле x, беззнаковое 32-битное число, младший байт первым.
- Смещения 8–11: поле y в том же представлении.
- Смещения 12–15: поле z в том же представлении.

Требуются 8-битные байты и наличие uint32_t; обычные Windows/MinGW64 и Linux
этим условиям соответствуют. sizeof(Point), выравнивание структуры и порядок
байтов процессора не определяют содержимое файла: каждое поле кодируется явно.
Отрицательные координаты здесь не поддерживаются — это отдельное условие формата.

## main.cpp

Без аргументов программа создаёт или перезаписывает point-v1.bin с координатами
487, 212, 946, закрывает файл с проверкой результата и читает запись обратно.
Ожидаемый вывод: Point(487, 212, 946).

Ожидаемые байты в шестнадцатеричном виде:

```text
50 54 30 31 e7 01 00 00 d4 00 00 00 b2 03 00 00
```

В режиме --read FILE программа только читает указанный файл. Она отклоняет
отсутствующий файл, неполную запись, неизвестный заголовок/версию, лишние байты
и ошибки чтения. Ошибка выводится в stderr, код завершения — 1.
Это формат одной записи: несколько Point подряд требуют отдельного протокола.

## Запуск

Из корня на Linux:

```bash
bash scripts/build-linux.sh io/bonus/02-portable-binary/main.cpp
(cd io/bonus/02-portable-binary && ../../../build/io/bonus/02-portable-binary/main)
./build/io/bonus/02-portable-binary/main --read io/bonus/02-portable-binary/point-v1.bin
```

На Windows / MSYS2 Bash используйте build-windows.sh и расширение .exe.
При F5 рабочая папка — папка исходника. point-v1.bin там игнорируется Git.
Для опытов с повреждёнными данными используйте копии во временной папке.

## Почему это отличается от урока 117

В уроке 117 записывается представление всего Point размером sizeof(Point).
Здесь reinterpret_cast используется только для передачи уже подготовленного
массива байтов потокам, а не для сериализации памяти произвольного класса.
Строки и указатели нельзя сохранять записью их адресов или внутреннего
представления: строкам нужны длина, кодировка и сами данные, а ссылкам —
осмысленные идентификаторы в выбранном формате.

Заголовок и длина помогают распознать формат, но не обнаруживают любое изменение
данных: для контроля целостности нужно отдельное поле, например контрольная сумма.
Запись здесь не атомарна и не гарантирует сохранение при сбое питания.

Упражнение: добавьте количество записей и ограничение этого количества перед
выделением памяти. Изменение структуры файла оформите новой версией заголовка.
