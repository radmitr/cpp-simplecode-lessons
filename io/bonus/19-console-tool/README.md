# 19. Аргументы, stdin/stdout/stderr и коды завершения

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Стандарт и компилятор: c++17. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

Без аргументов запускается самопроверка. Рабочий режим принимает
--scale 1..1000 и читает числа из stdin, ошибки направляет в stderr с кодом 1.
stdout в рабочем режиме содержит только результат — без приглашений и строки
самопроверки — чтобы его можно было передавать дальше по конвейеру. Запуск:
printf '1 2 3\n' | ./build/io/bonus/19-console-tool/main --scale 2.
Пути с пробелами передавайте отдельным аргументом в кавычках, не собирайте
команду оболочки конкатенацией непроверенных строк.

## Разбор кода и полезные варианты

Без аргументов main выполняет встроенный пример и печатает usage,
не блокируясь на вводе. С --scale N программа читает stdin до EOF,
проверяет целые токены и выводит сумму, умноженную на N.

После сборки из корня, Linux / MSYS2 Bash:

~~~bash
printf '1 2 3\n' | ./build/io/bonus/19-console-tool/main --scale 2
~~~

На Windows добавьте .exe. Результат — 12.
scale разрешён в пределах 1…1000, входные числа — -1000000…1000000.
Ошибки идут в stderr с кодом 1, успешный числовой результат — в stdout:
так программу удобно соединять с другими командами.

< numbers.txt означает перенаправление стандартного ввода оболочкой,
а не аргумент имени файла для main. Это Bash-синтаксис; в PowerShell
используйте его средства передачи содержимого или запускайте команду в Bash.
Неверные аргументы, недопустимый токен и переполнение проверяются раздельно.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh io/bonus/19-console-tool/main.cpp
./build/io/bonus/19-console-tool/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 19-console-tool`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section io/bonus`
(на Linux команда Python обычно называется python3).
