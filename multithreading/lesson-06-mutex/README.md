# 06. `std::mutex`

Три потока вызывают `print()` для символов *, # и @.
Каждый захватывает общий `mtx` перед печатью пяти строк и освобождает после них.
Пока один поток удерживает `mtx`, остальные ожидают на `lock()`.

Оба `sleep_for` по 2 секунды находятся за пределами защищённого участка.
Поэтому эти паузы в разных потоках могут идти одновременно.
Порядок блоков символов заранее не определён.

Каждому успешному `lock()` нужен `unlock()` в том же потоке.
При раннем `return` или исключении ручной `unlock` можно пропустить;
следующий урок показывает автоматическое освобождение через `lock_guard`.
`SimpleTimer` выводит длительность при выходе из `main`.

## Какие строки защищены

~~~cpp
mtx.lock();
// Весь участок печати, включая вложенные циклы и внутренние паузы.
mtx.unlock();
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Один поток держит блокировку на все 50 символов, а не на одну строку.
Другие вызывающие `print` ждут `lock`. Это взаимное исключение между участками,
которые используют **тот же** `mtx`; сам объект `cout` мьютексом не «помечается».
Код, не захватывающий `mtx`, способен вмешаться в вывод.

Внутренний i скрывает внешний i в своей области видимости: это два
независимых локальных счётчика. Они также отдельные для каждого вызова `print`.
Явное `std::size_t` с `cstddef` обозначает стандартный тип размера.

Ручной `unlock` должен выполняться владельцем. Повторный захват обычного `mutex`
тем же потоком, чужой `unlock` и уничтожение занятого `mutex` недопустимы.
Планировщик не обещает порядок выдачи блокировки или справедливость.
Паузы внутри `lock` намеренно делают сериализацию заметной; в прикладной
задаче критическую секцию стараются ограничить необходимой общей работой.
