# 03. Передача по ссылке через `std::ref`

`main.cpp` создаёт `q = 5` и запускает `doWork(int&)` с аргументом `std::ref(q)`.
В потоке параметр a ссылается на исходную `q`, поэтому a = a * 2 меняет её на 10.

`std::thread` обычно сохраняет переданные аргументы по значению.
`std::ref` явно указывает на исходный объект; сама переменная должна существовать
до завершения потока. `std::ref` объявлен в заголовке `<functional>`.

Главный поток читает `q` только после `th.join()`, когда рабочий поток завершён.
Результат: `q=10`. Если читать или менять `q` одновременно с рабочим потоком
без синхронизации, возникнет гонка данных.

## Почему одного `int&` в `doWork` недостаточно

~~~cpp
std::thread th(doWork, std::ref(q));
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`std::thread` должен сохранить аргументы до их использования в другом потоке.
`std::ref` создаёт небольшой `reference_wrapper`: он копируется, но продолжает
обозначать исходную `q`. При вызове `doWork` обёртка превращается в ссылку.

Передача просто `q` не означает автоматическую ссылку только из-за `int&`
в сигнатуре функции; такой вызов здесь не соответствует требованиям запуска.
Для чтения константного объекта есть `std::cref`.
Обе обёртки не владеют объектом и не синхронизируют обращения к нему.

`functional` стоит включать явно в коде, который использует ref/cref.
Текущая сборка может видеть их через другой стандартный заголовок,
но это не универсальная гарантия переносимости.
Пауза `main` не доказывает готовность результата: её гарантирует `join`,
а не предполагаемое число прошедших секунд.
