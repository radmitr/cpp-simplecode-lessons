# 12. std::barrier — C++20

Три потока выполняют три этапа вычислений.
Каждый записывает результат в свой элемент массива partial.
Нулевой поток затем суммирует все три значения.

## Зачем два барьера

calculated.arrive_and_wait() отмечает прибытие потока и ждёт остальных.
После прибытия всех трёх результаты текущего этапа готовы и доступны для чтения.
Например, на первом этапе массив содержит 1, 2, 3; сумма равна 6.

Нулевой поток читает массив и печатает сумму.
Два других ждут его на printed.arrive_and_wait().
Это не позволяет им начать следующий этап и перезаписать partial
одновременно с чтением предыдущего результата.

Каждый объект barrier используется повторно на всех этапах.
Каждый из трёх потоков обязан прибыть на оба барьера каждой итерации.
Если один поток выйдет раньше без соответствующего изменения протокола,
остальные могут остаться ждать.

## Почему здесь нет mutex для массива

Потоки записывают разные элементы массива int — это разные участки памяти.
Чтение всего массива происходит после calculated, а новые записи —
после printed. Эти границы этапов обеспечивают нужную синхронизацию.

Вывод должен быть таким:

~~~text
Phase 1: total = 6
Phase 2: total = 12
Phase 3: total = 18
~~~

Паузы изображают разную длительность работы и не обеспечивают правильность.
Синхронизацию выполняют барьеры.
std::latch, в отличие от barrier, подходит для однократного отсчёта до нуля;
здесь нужен повторно используемый механизм.
