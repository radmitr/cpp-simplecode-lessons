# 14. thread_local

C++17. incrementLocal() содержит thread_local int counter = 0.
У каждого потока свой counter, который сохраняется между вызовами этой функции
внутри данного потока.

Два рабочих потока вызывают incrementLocal() по три раза.
Поэтому каждый выводит local = 3, а не общий результат 6.
Главный поток затем вызывает функцию первый раз и получает local = 1.

Для сравнения оба рабочих потока увеличивают shared — общий atomic<int>.
Он выводит Shared total: 6. Вызов incrementLocal() из main не увеличивает shared.

Мьютекс outputMutex нужен для цельных сообщений в консоли.
Сами личные счётчики в этом примере не требуют взаимного исключения,
потому что каждый поток обращается только к собственному объекту.

Обычная локальная переменная `int counter = 0` создавалась бы заново при каждом
вызове `incrementLocal()`. С `thread_local` у каждого потока своя переменная,
и её значение сохраняется между вызовами до завершения этого потока.
В пуле потоков один работник выполняет много заданий. Его `thread_local`
сохранится между ними: новое задание не получит автоматически новый счётчик.

Если передать указатель на свой thread_local другому потоку, доступ к одному
объекту снова может потребовать синхронизации; в этом примере указатели не передаются.

Откройте main.cpp и нажмите F5 или Ctrl+F5.
