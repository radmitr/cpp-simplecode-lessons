# 03. std::scoped_lock

main.cpp показывает перевод между счетами с захватом двух мьютексов.

Продолжение урока про deadlock. Два счёта начинают с 10000.
Один поток переводит единицу с первого на второй, другой — обратно.
После 1000 переводов в каждом направлении оба счёта снова содержат 10000.

Для изменения двух счетов нужны оба мьютекса. Строка

~~~cpp
std::scoped_lock guard(from.mtx, to.mtx);
~~~

захватывает их с помощью алгоритма предотвращения deadlock при захвате.
На каждой итерации guard автоматически освобождает оба мьютекса.

Потоки передают мьютексы в противоположном порядке; последовательные ручные
lock() здесь могли бы привести к взаимной блокировке. scoped_lock управляет
захватом всей пары. Это не универсальная защита от любого deadlock:
другие ожидания и вложенные блокировки всё равно требуют внимания.
В этом примере from и to всегда разные объекты; один mutex нельзя передавать дважды.

В угловых скобках можно явно написать std::scoped_lock<std::mutex, std::mutex>,
но здесь типы выводятся автоматически — эта возможность доступна с C++17.
