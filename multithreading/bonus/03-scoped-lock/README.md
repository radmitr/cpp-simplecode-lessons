# 03. std::scoped_lock

main.cpp показывает перевод между счетами с захватом двух мьютексов.

Продолжение урока про deadlock. Два счёта начинают с 10000.
Один поток переводит единицу с первого на второй, другой — обратно.
После 1000 переводов в каждом направлении оба счёта снова содержат 10000.

Для изменения двух счетов нужны оба мьютекса. Строка

~~~cpp
std::scoped_lock guard(from.mtx, to.mtx);
~~~

захватывает оба мьютекса, прежде чем код изменит балансы.
В конце каждой итерации объект `guard` уничтожается и освобождает их.

Потоки передают мьютексы в противоположном порядке. При двух отдельных
вызовах `lock()` каждый поток мог бы захватить первый мьютекс и ждать второй,
которым уже владеет другой поток. Возникла бы взаимная блокировка — deadlock.
`scoped_lock` использует алгоритм, который предотвращает такое взаимное
ожидание при захвате этой пары. Если добавить в защищённый участок другие
ожидания, например `join()`, их безопасность нужно проверять отдельно.
В этом примере `from` и `to` всегда разные объекты;
один `std::mutex` нельзя передавать в `scoped_lock` дважды.

В угловых скобках можно явно написать std::scoped_lock<std::mutex, std::mutex>,
но здесь типы выводятся автоматически — эта возможность доступна с C++17.
