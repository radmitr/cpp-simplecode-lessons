# 18. `std::latch`

## Версия C++

`std::latch` — **C++20**.
`std::thread`, `std::array`, лямбды — **C++11**.
`std::vector`, `std::accumulate`, `std::size_t` — **C++98**.

Сборка примеров: **C++20**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Как это работает

~~~cpp
std::latch finished(3);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

### Как работает отсчёт

1. Каждый работник записывает результат в свой элемент results.
2. `finished.count_down()` атомарно уменьшает внутренний счётчик на один.
3. Главный поток находится в `finished.wait()`.
4. Когда счётчик достигает нуля, ожидание заканчивается.
5. Главный поток читает результаты и получает сумму 60.

~~~text
Prepared values: 10 20 30
Total: 60
~~~

Если все работники успели раньше, чем `main` вызвал `wait()`, ожидание сразу
завершится: нулевое состояние сохраняется. Ложные пробуждения и предикат
вручную обрабатывать не требуется.

`count_down()` сообщает о завершении работы и сам не ждёт остальных.
Для действия «уменьшить счётчик и ждать нуля» есть `arrive_and_wait()`.
Вычитать больше оставшегося значения нельзя.

### Почему безопасно читать results

Работники изменяют разные элементы `std::array<int, 3>`.
Каждая запись происходит перед `count_down()`. Механизм latch обеспечивает
видимость этих записей после завершения `wait()`, когда счётчик достиг нуля.
После `count_down()` работники больше не изменяют results.

Для самих результатов дополнительный `mutex` в этом примере не требуется.
Если бы потоки изменяли один общий элемент одновременно, один latch
не защитил бы эти изменения во время работы.

### Зачем ещё нужен `join()`

`count_down()` не завершает поток. После него в функции работника может
оставаться другой код. latch ждёт события «счётчик достиг нуля»,
а `thread::join()` ждёт полного завершения конкретного потока.
Пример делает и то и другое.

В отличие от [std::barrier](../19-barrier/), latch не начинает новый этап
с восстановленным счётчиком. После достижения нуля его нельзя перезапустить.
barrier подходит для повторяющихся фаз, latch — для одного отсчёта.

### `main2.cpp`: каждый ждёт остальных

Работник записывает свой элемент `values` и вызывает
`prepared.arrive_and_wait()`. Вызов эквивалентен `count_down()`,
затем `wait()`. Когда пришли все трое, каждый может безопасно
прочитать все три значения и записать сумму в свой элемент `totals`.

В основном `main.cpp` работники только сообщают о готовности, а ждёт главный.
В этом варианте ждут и работники. Вывод: `Totals: 60 60 60`.
После публикации никто больше не меняет `values`, а `totals` главный
читает после всех `join()`.

### `main3.cpp`: неблокирующая проверка

`try_wait()` не уменьшает счётчик и не ждёт.
При счётчике `2` и `1` программа получает `false`.
После второго `count_down()` ноль уже достигнут, `wait()` возвращает сразу.

Обычно следующая проверка даёт `true`, однако стандарт допускает
ложный `false` с очень малой вероятностью.
Поэтому разрешены оба вывода:

~~~text
Before: false; halfway: false; after zero: true
Before: false; halfway: false; after zero: false
~~~

`true` подтверждает нулевое состояние, `false` не доказывает, что оно
ещё не достигнуто. Для обязательного ожидания используйте `wait()`,
а не цикл активных проверок.

У `latch` нет сброса в исходное состояние. После достижения нуля
продолжать уменьшать счётчик нельзя. Ожидать уже достигнутый ноль можно.
Оба варианта конечные, без ввода и файлов, код успеха `0`, ошибки `1`.
