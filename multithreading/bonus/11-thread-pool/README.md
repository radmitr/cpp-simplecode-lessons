# 11. Учебный пул потоков

Продолжение [producer–consumer](../10-producer-consumer/), C++17.
Три постоянных рабочих потока выполняют семь заданий из общей очереди.
Новый поток для каждого задания не создаётся.

- main.cpp — использование пула и получение результатов.
- ThreadPool.hpp — класс ThreadPool; подключается через include.
  Отдельно запускать заголовочный файл не нужно.

## Как устроен пул

Конструктор создаёт рабочие потоки. Каждый выполняет цикл work():
ждёт stopping || !tasks.empty(), забирает одну задачу и выполняет её
после освобождения мьютекса очереди.

submit() принимает функцию без аргументов, возвращающую int.
Это намеренное ограничение учебного класса. Аргументы можно захватить лямбдой.
Для функции создаётся packaged_task<int()>, который сохраняет результат
или исключение в связанном future.

packaged_task нельзя копировать, а std::function<void()> в очереди
требует копируемый вызываемый объект. Поэтому лямбда в очереди
захватывает shared_ptr на packaged_task.
Пока задача ожидает или выполняется, соответствующий объект остаётся жив.

## Что показывает main

Шесть задач возвращают квадраты чисел 1–6. Седьмая выбрасывает runtime_error.
Результаты читаются в порядке добавления: 1, 4, 9, 16, 25, 36.
Это не означает, что задачи завершились именно в таком порядке.
Их сумма равна 91. Исключение извлекается через failed.get(),
при этом рабочий поток продолжает обрабатывать другие задания.

При выходе из блока деструктор пула устанавливает stopping,
будит работников и делает join() для каждого. Работники сначала
обрабатывают всю очередь и только затем завершаются.
Поэтому future можно читать даже после уничтожения пула:
результаты находятся в отдельных общих состояниях.

## Ограничения примера

Нулевой размер пула отклоняется. Если создание одного потока не удалось,
конструктор завершает уже созданные потоки и повторно выбрасывает исключение.

Деструктор ожидает окончания задач и не прерывает их принудительно.
Владелец должен обеспечить, чтобы пул существовал на протяжении обращений к нему.
Нельзя уничтожать пул из его же задания.
Не следует занимать всех работников задачами, которые ждут результат
других заданий этого же пула: это может привести к deadlock.
Приоритеты, отмена и ограничение очереди в этом учебном пуле не реализованы.
