# 19. `std::barrier`

## Версия C++

`std::barrier` — **C++20**.
`std::thread`, `std::array`, `std::chrono`, `auto`, лямбды — **C++11**.
`std::accumulate`, `std::size_t` — **C++98**.

Сборка примеров: **C++20**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Три потока выполняют три этапа вычислений.
Каждый записывает результат в свой элемент массива partial.
Нулевой поток затем суммирует все три значения.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

- [main2.cpp](main2.cpp): функция завершения этапа подсчитывает сумму.
- [main3.cpp](main3.cpp): `arrive_and_drop()` уменьшает число участников.
- [main4.cpp](main4.cpp): отдельные `arrive()` и `wait()` с токеном прибытия.

## Как это работает

### Зачем два барьера

`calculated.arrive_and_wait()` отмечает прибытие потока и ждёт остальных.
После прибытия всех трёх результаты текущего этапа готовы и доступны для чтения.
Например, на первом этапе массив содержит 1, 2, 3; сумма равна 6.

Нулевой поток читает массив и печатает сумму.
Два других ждут его на `printed.arrive_and_wait()`.
Это не позволяет им начать следующий этап и перезаписать partial
одновременно с чтением предыдущего результата.

Каждый объект barrier используется повторно на всех этапах.
Каждый из трёх потоков обязан прибыть на оба барьера каждой итерации.
Если один поток выйдет раньше без соответствующего изменения протокола,
остальные могут остаться ждать.

### Почему здесь нет `mutex` для массива

Потоки записывают разные элементы массива `int` — это разные участки памяти.
Чтение всего массива происходит после `calculated`, а новые записи —
после `printed`. Эти границы этапов обеспечивают нужную синхронизацию.

Вывод должен быть таким:

~~~text
Phase 1: total = 6
Phase 2: total = 12
Phase 3: total = 18
~~~

Паузы изображают разную длительность работы и не обеспечивают правильность.
Синхронизацию выполняют барьеры.
`std::latch`, в отличие от barrier, подходит для однократного отсчёта до нуля;
здесь нужен повторно используемый механизм.

### `main2.cpp`: функция завершения этапа

В конструктор `std::barrier sync(3, complete)` передана лямбда `complete`.
Работники записывают разные элементы `partial` и вызывают `arrive_and_wait()`.
Когда все прибыли, функция завершения суммирует элементы и сохраняет итог.
Только после её завершения ожидающие переходят к следующей фазе.

Поэтому здесь достаточно одного барьера: чтение массива происходит
внутри завершения фазы, до разрешения новых записей.
В основном `main.cpp` сумму считает один из работников **после** барьера,
поэтому там нужен второй барьер, защищающий это чтение от следующей фазы.

`complete` объявлена `noexcept`: функция завершения не должна выпускать
исключение. Не рассчитывайте, что её всегда вызовет конкретный работник.
У неё нет собственного фонового потока.
После всех `join()` главный печатает суммы `6`, `12`, `18`.

### `main3.cpp`: участник покидает барьер

Изначально ждём троих. Два работника делают три этапа, третий выполняет
свою часть первого и вызывает `arrive_and_drop()`.
Вызов учитывает его прибытие сейчас и уменьшает число ожидаемых
прибытий **в последующих фазах**. Сам он остальных не ждёт.

Оставшиеся двое проходят ещё две фазы без зависания.
Вывод: `Phases: 3; visits: 3 3 1`. Ушедший работник больше не обращается
к барьеру. Просто выйти из функции вместо `arrive_and_drop()` нельзя:
его прибытия будут продолжать ждать.

### `main4.cpp`: прибытие и ожидание отдельно

`arrive()` уменьшает счётчик и возвращает `arrival_token` —
объект, связывающий последующее ожидание с нужной фазой.
Работник затем выполняет независимую работу и вызывает
`sync.wait(std::move(ticket))`. В отличие от `arrive_and_wait()`,
между двумя действиями можно разместить код.

Работу, записи которой нужны другим на границе фазы, выполняют
**до** `arrive()`. После него нельзя считать, что остальные всё ещё ждут:
фаза могла уже закончиться. Здесь независимое число читается только после `join()`.
Вывод: `Independent work: 7`. Не используйте произвольно старые токены
и не смешивайте токены разных барьеров.

Новые варианты конечные, без ввода и файлов: успех — `0`, ошибка проверки — `1`.
