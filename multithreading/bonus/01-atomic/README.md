# 01. Гонка данных и `std::atomic`

Начните с `main.cpp`. Два потока по 100000 раз увеличивают один счётчик.
Сначала каждое увеличение защищено `std::lock_guard`, затем счётчик заменяется
на `std::atomic<int>`. Оба варианта должны вывести 200000.

Обычный ++`counter` включает чтение, увеличение и запись. Без синхронизации
два потока могут обратиться к одному `int` одновременно — это гонка данных
и неопределённое поведение C++. Важно: `join()` только ждёт завершения;
он не защищает обращения к счётчику во время выполнения потоков.

Атомарный ++`counter` выполняет увеличение как одну неделимую операцию.
Не заменяйте его на `counter = counter` + 1: отдельные атомарные чтение и запись
не делают всю последовательность одной атомарной операцией.
Atomic удобен для простого счётчика; `mutex` также позволяет защитить
несколько связанных действий и переменных. Atomic не обязательно работает без блокировок.

`main2.cpp` намеренно содержит гонку данных: оба потока увеличивают обычный
`int` без мьютекса и без атомарных операций. Программа сразу запускает этот
эксперимент и выводит сообщение `Intentional data race: undefined behavior.`
Откройте `main2.cpp` и нажмите F5 или Ctrl+F5; аргументы запуска не нужны.

Для запуска из терминала на Linux выполните из корня репозитория
(папки `cpp-simplecode-lessons`):

~~~bash

./build/multithreading/bonus/01-atomic/main2
~~~

На Windows в PowerShell, из корня репозитория:

У программы нет гарантированного результата: даже число 200000
не доказывает правильность кода. Сравните с корректными вариантами в `main.cpp`,
где мьютекс или атомарный счётчик устраняет гонку данных.
Этот вариант нельзя использовать для измерения производительности.

## Почему два результата по 200000

`countWithMutex` и `countWithAtomic` — два независимых эксперимента.
Каждая функция создаёт **свой** `counter = 0` и запускает по два потока.
Каждый поток делает 100000 увеличений: 2 × 100000 = 200000 в каждом опыте.
Четыре потока не складывают значения в один общий счётчик.

~~~cpp
auto increment = [&]() { /* цикл увеличений */ };
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`auto` здесь выводит конкретный тип лямбды; `increment` — имя объекта,
а не встроенная операция. Захват `[&]` даёт доступ к локальному счётчику.
В `mutex`-варианте `guard` создаётся заново на каждой итерации и защищает один ++.
В `atomic`-варианте ++ — атомарная read-modify-write операция.

Атомарность одной переменной не объединяет несколько отдельных действий
в транзакцию. Например, проверка остатка и последующее списание потребуют
общей блокировки или CAS-цикла. Порядки памяти раскрыты в бонусе 17.
Счётчик читается после `join`: потоки уже закончили свои увеличения.
