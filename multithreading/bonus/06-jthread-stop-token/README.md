# 06. std::jthread и std::stop_token — C++20

Этот пример собирается как C++20: cxx-standard.txt в этой папке содержит c++20.
Общие скрипты Windows и Linux читают этот файл автоматически.
При ручной сборке укажите -std=c++20 -pthread.
Если std::jthread недоступен, проверьте поддержку C++20 компилятором и библиотекой.

В этом примере `std::jthread` запускает лямбду, принимающую `std::stop_token`.
Через этот объект рабочий поток узнаёт о запросе остановки:
на каждой итерации он проверяет `stop.stop_requested()`.

Через 350 мс main вызывает worker.request_stop(). Это только запрос:
он не прерывает sleep_for и не останавливает функцию принудительно.
Рабочий поток завершает текущую итерацию и выходит при следующей проверке.

При выходе из внутреннего блока объект `worker` уничтожается.
В нашем коде его деструктор сам вызывает `request_stop()`, а затем `join()`.
Главный поток ждёт завершения рабочего и только после этого продолжает
выполнение за закрывающей скобкой блока. Поэтому явного `join()` в коде нет.

Рабочий поток увеличивает `completed`, а главный читает эту переменную
только после завершения рабочего. Одновременного чтения и записи здесь нет.

Число завершённых итераций зависит от планирования потоков, обычно получается
около четырёх. Не используйте это число как точный результат проверки.

Попробуйте убрать явный request_stop(): запрос при выходе из блока выполнит деструктор.
Если функция не проверяет запрос остановки и работает бесконечно, деструктор
будет ждать бесконечно — автоматический join не означает принудительное завершение.
