# 13. std::timed_mutex

C++17. Продолжение [try_lock](../02-try-lock/).
try_lock делает попытку без ожидания. timed_mutex позволяет ограничить ожидание:

- try_lock_for(duration) — задать длительность.
- try_lock_until(deadline) — задать момент времени.

В примере используется unique_lock<timed_mutex> с defer_lock.
Его методы try_lock_for и try_lock_until управляют владением мьютексом;
деструктор освобождает его, только если захват получен.

## Почему первые две попытки неудачны

Главный поток держит mtx и ждёт worker через join().
Рабочий поток дважды пробует захват с таймаутом 50 мс.
Оба раза результат false: main ещё не освободил mtx.
Попытки конечны, поэтому worker может завершиться.
Если заменить их обычным lock(), получится взаимное ожидание.

Затем main выходит из блока, освобождает mtx и повторяет попытку.
Она обычно успешна. Стандарт допускает ложную неудачу и при свободном мьютексе,
поэтому false означает отсутствие захвата, а не доказательство занятости.
В коде обработаны оба результата.

steady_clock не зависит от перевода системных часов.
Таймаут не является жёстким ограничением времени исполнения:
планирование ОС может задержать возврат.
