# 26. Поиск гонки данных с ThreadSanitizer

C++17. ThreadSanitizer (TSan) инструментирует программу при компиляции
и во время выполнения обнаруживает конфликтующие обращения к памяти
без необходимой синхронизации.

Этот бонус нужно проверять под TSan на Linux, в том числе Linux внутри WSL.
Обычная Windows-сборка MinGW позволяет разобрать и запустить исходники,
но не выполняет такую диагностику.

## Два варианта одной задачи

- main.cpp — корректный счётчик: каждый ++counter защищён одним mtx.
  Два потока делают по 100000 увеличений, итог — 200000.
- main2.cpp — намеренная гонка: два потока увеличивают обычный int
  без синхронизации. Это неопределённое поведение C++.

Начните с корректного main.cpp, затем сравните с main2.cpp под TSan.
Обычный запуск main2.cpp может даже напечатать 200000:
совпадение результата с ожидаемым не доказывает правильность.
join() дожидается потоков, но не исправляет гонку во время их работы.

## Запуск с диагностикой на Linux/WSL

Нужен Clang с библиотекой исполнения ThreadSanitizer либо GCC с поддержкой
-fsanitize=thread. Установка зависит от дистрибутива; для Debian/Ubuntu
обычно нужны пакеты clang и libclang-rt-dev. Для варианта GCC — g++
и доступная соответствующему компилятору libtsan.

Команды из корня репозитория:

~~~bash
# Корректный вариант: код возврата 0, сообщений о гонке быть не должно.
bash multithreading/bonus/26-thread-sanitizer/run-tsan.sh main.cpp

# Намеренная гонка: ожидается диагностическое сообщение.
bash multithreading/bonus/26-thread-sanitizer/run-tsan.sh main2.cpp
~~~

По умолчанию скрипт выбирает clang++. Можно явно выбрать GCC:

~~~bash
CXX=g++ bash multithreading/bonus/26-thread-sanitizer/run-tsan.sh main2.cpp
~~~

Скрипт использует -O1 -g -fsanitize=thread -fno-omit-frame-pointer -pthread.
-g помогает показать имена файлов и строки, -fsanitize=thread включает
инструментирование и подключает библиотеку диагностики.
Результаты находятся в build/multithreading/bonus/26-thread-sanitizer/
под именами main-tsan и main2-tsan. Обычные бинарники не перезаписываются.

TSAN_OPTIONS в скрипте задаёт halt_on_error=1:exitcode=66:
при обнаружении гонки выполнение прекращается с кодом 66.
Это ожидаемый результат для ошибочного main2.cpp.
Сбой компиляции, запуска библиотеки или сообщение FATAL сами по себе
не являются подтверждением гонки: сначала исправьте проблему окружения.

Упрощённый вид отчёта:

~~~text
WARNING: ThreadSanitizer: data race
  ... обращение одного потока к counter ...
  ... конфликтующее обращение другого потока к counter ...
~~~

Точные адреса, строки, стек вызовов и номера потоков зависят от сборки.
Найдите две конфликтующие операции ++counter и места создания потоков.
Затем запустите main.cpp с теми же флагами и сравните отчёты.
Отсутствие сообщения в одном запуске произвольной программы
не является доказательством отсутствия всех возможных гонок.

## VS Code и Windows

Для диагностики откройте папку этого бонуса в VS Code внутри Linux/WSL.
Выберите main.cpp или main2.cpp и выполните:

Terminal → Run Task… → ThreadSanitizer: Build and Run (Linux/WSL).

Задача вызывает run-tsan.sh. Для ошибочного примера код 66 будет
показан как неуспешное завершение задачи — здесь это ожидаемо.
Отчёт лучше читать в терминале, а не запускать инструментированный
бинарник через обычную конфигурацию отладчика.

Обычные F5/Ctrl+F5 и C/C++: Build используют общую сборку без TSan.
Из PowerShell на Windows корректный пример запускается так:

~~~powershell
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh multithreading/bonus/26-thread-sanitizer/main.cpp
& .\build\multithreading\bonus\26-thread-sanitizer\main.exe
~~~

Для WSL используйте терминал Linux и путь к репозиторию в нём,
например /mnt/d/Code/CPP_PRJ/cpp-simplecode-lessons, либо отдельный клон
в файловой системе WSL. На стороне Linux должны быть установлены
компилятор и библиотека TSan. run-tsan.sh проверяет ОС и завершится
с пояснением, если его запустить через Windows/MSYS2.

После добавления исходников обновите IntelliSense через задачу
C/C++: Update IntelliSense на той системе, где работаете.
