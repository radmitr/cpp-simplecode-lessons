# 05. Результат фоновой задачи: std::async и std::future

C++17. Нужны функции, возвращаемые значения, лямбды, исключения и базовый
std::thread. [main.cpp](main.cpp) вычисляет 2 + 5 и передаёт исключение
из другой задачи в main. Задержка 500 мс имитирует долгую работу.

## Три разных назначения

- std::thread представляет поток. join() ждёт его завершения и возвращает void;
  значение return рабочей функции он не передаёт.
- `std::future<T>` предоставляет доступ к одному будущему результату T либо
  исключению. Сам по себе future не создаёт поток.
- std::async организует вызов функции и возвращает связанный с ним future.
  Политика определяет отдельный поток или отложенный вызов.

С обычным потоком результат передают самостоятельно:

~~~cpp
int value = 0;
std::thread worker([&] { value = sum(2, 5); });
// main может делать другую работу, но value ещё не читает.
worker.join();
std::cout << value;
~~~

Захват & относится к исходной переменной. Она должна жить до завершения worker.
После join() запись рабочего потока видна main. Чтение value одновременно
с записью без синхронизации дало бы гонку. join() не исправляет гонки,
уже возникшие во время работы.

## Как выполняется текущий main.cpp

~~~cpp
std::future<int> result = std::async(std::launch::async, sum, 2, 5);
std::cout << "Main: can do other work while sum is running\n";
const int value = result.get();
~~~

1. async получает функцию sum и аргументы 2 и 5. Запись sum(2, 5) вместо sum
   вызвала бы функцию ещё до передачи результата в async.
2. launch::async выбирает отдельный поток. Планировщик определяет момент
   выполнения; задача может закончиться ещё до вызова get().
3. sum возвращает 7, библиотека сохраняет его в общем состоянии задачи.
4. main получает future и может выполнять независимую работу.
5. get() ждёт готовности, если нужно, и извлекает 7 в обычный int value.

Общая переменная по ссылке для результата не нужна. Ручного join() здесь нет:
своим объектом std::thread мы не управляем. Если сразу вызвать get(), main
сразу станет ждать; полезное перекрытие работы появляется между запуском
и ожиданием. Для сложения двух чисел расходы на поток превышают пользу.

## Почему get() только один раз

~~~cpp
const int value = result.get();
// result.get(); // Нельзя: result.valid() теперь false.
std::cout << value;
std::cout << value; // Полученный int используем сколько угодно.
~~~

get() извлекает результат и освобождает связь future с общим состоянием.
Повторный get() недопустим; нельзя рассчитывать, что любая реализация
обязательно сообщит об этом исключением. Новый async создаёт новый future.
После успешного join() повторно присоединять тот же поток тоже нельзя.

## wait, get и таймаут

Следующие фрагменты дополняют main.cpp примерами API; отдельных файлов
с такими вариантами в этом уроке нет:

~~~cpp
result.wait(); // Только дождаться готовности.
result.wait(); // Допустимо: результат ещё не извлекали.
const int value = result.get();
~~~

wait() не возвращает значение и не извлекает сохранённое исключение.
Для получения результата или обработки ошибки используйте get().
После get() этот future нельзя использовать для нового wait().

~~~cpp
const auto status = result.wait_for(std::chrono::milliseconds(100));
if (status == std::future_status::ready) {
    const int value = result.get();
    std::cout << value;
}
~~~

Нужен chrono. ready означает готовность значения **или исключения**.
timeout означает истечение ожидания, а не отмену задачи.
wait_until принимает абсолютный момент; для интервалов полезны steady_clock.
Задача может продолжать работу и после таймаута. Третий статус — deferred.

## Что будет без std::launch::async

~~~cpp
auto result = std::async(sum, 2, 5);
~~~

Разрешён выбор между launch::async и launch::deferred (политика async | deferred).
Реализация выбирает вариант; параллельная работа не гарантирована.

При async функция выполняется в отдельном потоке. При deferred функция
и аргументы сохраняются, но вызов начнётся только при первом get() или wait(),
в потоке, который вызвал ожидание. Если это main, вычисление выполнит main.

~~~cpp
auto result = std::async(std::launch::deferred, sum, 2, 5);
// sum ещё не вызвана.
const int value = result.get(); // Теперь sum выполняется в этом потоке.
~~~

wait_for()/wait_until() отложенную функцию не запускают: возвращают deferred.
Без get()/wait() функция может вообще не выполниться.
Явный launch::async исключает deferred; невозможность создать поток может
привести к system_error. Сам async не является обещанием пула потоков.

## Передача исключения

Вторая задача в main.cpp выбрасывает runtime_error. Библиотека сохраняет
исключение, а failed.get() выбрасывает его в main:

~~~cpp
try {
    failed.get();
} catch (const std::exception& error) {
    std::cout << "Caught: " << error.what() << '\n';
}
~~~

Без get() сохранённое исключение само в main не выбрасывается.
У обычного std::thread неперехваченное исключение рабочей функции вызывает
std::terminate(). Для явной передачи есть [promise/future](../09-promise-future/README.md).

## Время жизни и завершение

Уничтожение последнего владельца состояния незавершённой задачи launch::async
может ждать её завершения. Поэтому такая запись:

~~~cpp
std::async(std::launch::async, sum, 2, 5);
// Временный future уничтожается в конце строки и может ждать задачу.
~~~

не является универсальным способом «запустить и забыть». Два таких выражения
могут фактически выполниться последовательно. Это специальное поведение
состояния от async: future от promise не присоединяет произвольный std::thread.
Получение сигнала от promise не заменяет управление отдельно созданным потоком.

Аргументы обычно сохраняются по значению; для явной ссылки используют std::ref
из functional. Захват ссылки не продлевает жизнь объекта.
Для повторного чтения одного результата и нескольких потребителей есть
[std::shared_future](../22-shared-future/README.md). Он не запускает функцию
заново: все потребители обращаются к одному подготовленному результату.
