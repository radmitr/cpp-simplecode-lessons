# 17. Порядки памяти: relaxed, acquire и release

Оба примера используют C++17. Это продолжение atomic.
Порядок памяти определяет синхронизацию и упорядочивание обращений,
а не «скорость обновления переменной» и не задержку в миллисекундах.

## main.cpp — relaxed для самостоятельного счётчика

Два потока выполняют counter.fetch_add(1, memory_order_relaxed)
по 100000 раз. Увеличения остаются атомарными, итог равен 200000.
relaxed не используется для публикации других данных.

Главный поток вызывает `join()` для обоих рабочих потоков и лишь затем
читает счётчик. К этому моменту все увеличения уже закончены, поэтому
он получает итог 200000. Значение счётчика здесь не служит сигналом
для чтения каких-либо других общих данных.

## main2.cpp — публикация данных

Писатель заполняет обычные поля payload.number и payload.text,
затем вызывает ready.store(true, memory_order_release).

Читатель в цикле вызывает `ready.load(memory_order_acquire)`.
Пока результат `false`, он не обращается к `payload`.
Когда он получает `true`, записанное через `memory_order_release`,
записи `payload.number = 42` и `payload.text = "ready data"` уже видны читателю.
После этого он может прочитать эти поля. Это и есть публикация данных
через пару `release`/`acquire`.

Ожидаемый результат: `Received: 42, ready data`.

Здесь ровно один писатель и одна публикация. После неё payload не меняется.
Заменять acquire/release на relaxed в этом примере нельзя:
тогда готовность атомарного флага сама не синхронизирует доступ к обычному payload.

Для наглядности в C++17 используется цикл с yield().
yield лишь даёт подсказку планировщику, сам не синхронизирует память
и не является гарантированным сном. Для C++20 вариант без собственного
опроса показан в [atomic::wait](../16-atomic-wait/).

## Как это связано с предыдущими примерами

Обычные load(), store() и ++ у atomic по умолчанию используют seq_cst —
более строгий порядок. Ручное ослабление порядка требует обоснования.
Acquire здесь не захватывает mutex и не является методом semaphore.acquire().
Это характеристика атомарной операции чтения.

Примеры корректны независимо от того, какой поток стартует первым.
Запуск без ошибки на одном процессоре не доказывает корректность произвольного
ослабления синхронизации; здесь опираемся на правила языка.
