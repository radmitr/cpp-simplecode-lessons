# 19. Перемещение std::unique_lock

C++17. Дополнение к [уроку 10 — std::unique_lock](../../lesson-10-unique-lock/).
Перед изучением примера нужно знать захват мьютекса и освобождение через RAII
из этого урока. Этот бонус можно изучать сразу после урока 10.

## Передача захвата при оформлении заказа

На складе три единицы товара. Два потока оформляют заказы по две единицы.
Успешным должен быть ровно один заказ, а остаток должен стать равен одному.
Порядок обслуживания потоков не определён.

1. `lockInventory()` захватывает мьютекс склада и возвращает `unique_lock`.
   Возврат передаёт управление захватом вызывающей функции: мьютекс остаётся
   занят. `return lock` не требует `std::move`: компилятор может сразу создать
   результат на месте вызывающего объекта (NRVO) или выполнить перемещение.
2. `placeOrder()` проверяет остаток под этим захватом. При отказе её локальный
   `lock` освобождает мьютекс при выходе из функции.
3. При успехе `completeOrder(..., std::move(lock))` передаёт управление
   захватом параметру другой функции. Параметр принимается **по значению**;
   скопировать `unique_lock` нельзя, поэтому здесь нужно перемещение.
4. `completeOrder()` списывает товар под тем же захватом. При выходе её параметр
   уничтожается и освобождает мьютекс. Перемещённый объект в `placeOrder()`
   уже не связан с мьютексом: `owns_lock()` равен `false`, `mutex()` — `nullptr`.

Между проверкой остатка и списанием нет промежуточного `unlock()` и повторного
`lock()`. Другой поток не может купить товар между этими действиями. Здесь
функция завершения заказа получает ответственность за освобождение мьютекса;
это и демонстрирует передачу владения. Такой же сценарий можно организовать,
оставив один `lock_guard` в вызывающей функции, если передавать ответственность
другой функции не требуется.

`std::move` сам не освобождает и не захватывает мьютекс: он разрешает
перемещение, которое выполняет конструктор параметра `unique_lock`.
Сам мьютекс остаётся на месте. Передача в этом примере происходит между
функциями **одного потока**; освобождать захваченный `std::mutex` должен тот
же поток, который его захватил.

Пример вывода, если первым обслужен заказ 1:

~~~text
Order 1: checking 2 items; available 3
Order 1: new owner holds lock = true; reserved 2; remaining 1
Order 2: checking 2 items; available 1
Order 2: rejected
Accepted orders: 1
Remaining items: 1
~~~

Откройте `main.cpp` и запустите через F5 или Ctrl+F5. Проверки `assert`
проверяют состояние владельца до и после перемещения. Программа возвращает 0,
если принят ровно один заказ и осталась одна единица товара. После добавления
нового исходника выполните **Terminal → Run Task… → C/C++: Update IntelliSense**.
