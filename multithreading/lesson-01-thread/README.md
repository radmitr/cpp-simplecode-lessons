# 01. Запуск потоков

## Версия C++

`std::thread`, `std::chrono` — **C++11**.
`std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`main.cpp` создаёт два потока: `th` и `th2` вызывают `doWork()`.
Главный поток тоже выполняет свой цикл, поэтому сообщения перемешиваются.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Конструктор `std::thread` запускает поток, но точный момент начала работы
зависит от планирования ОС. `th.join()` и `th2.join()` ожидают завершения
обоих потоков, после чего печатается END MAIN.

Закомментированные `detach()` показывают другой способ управления:
поток отделяется, а `join()` после `detach()` вызывать нельзя.
Для текущего примера оставьте `join()`: он обеспечивает ожидание завершения.

### Поток начинается до `join`

~~~cpp
std::thread th(doWork);
std::thread th2(doWork);
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

Конструкторы запускают два независимых выполнения. `join` не запускает
`doWork`: к моменту ожидания она уже может завершиться.
`main` делает десять пауз по 500 мс, каждый работник — десять по 1000 мс.
Поэтому после своего цикла `main` обычно ещё ждёт работников.
Два последовательных `join` не заставляют работников выполняться последовательно.

`std::thread` нельзя копировать, но можно перемещать. Даже уже закончившийся
поток остаётся joinable, пока не выполнен `join()` или `detach()`.
Уничтожение joinable `std::thread` приводит к `terminate` — автоматического `join`
у него нет. У C++20 `std::jthread` другое управление завершением.

detach снимает связь с объектом `thread` и лишает возможности `join`.
Он не продлевает жизнь захваченных ссылок и не гарантирует работу после
завершения процесса. В этом примере он не нужен.
Вывод нескольких цепочек << может смешиваться внутри строки; безопасный
доступ к стандартному `cout` сам по себе не делает целое сообщение атомарным.
