# 09. `std::recursive_mutex`

## Версия C++

`std::mutex`, `std::recursive_mutex`, `std::chrono`, `std::thread` — **C++11**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`main.cpp` трижды захватывает `mtx` в одном потоке и трижды освобождает его.
Окончательно мьютекс становится доступен другим потокам после третьего `unlock()`.
Функция `foo()` в этом файле не вызывается.

## Примеры

- [main.cpp](main.cpp).
- [main2.cpp](main2.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

`main2.cpp` запускает `foo(10)` в двух потоках. Каждый рекурсивный вызов `foo()`
снова захватывает `mtx`. Владельцу разрешён повторный захват: `foo(9)` выполняется
в том же потоке, что и `foo(10)`. Но другой поток ждёт полного освобождения `mtx`.

При возврате из рекурсии каждый вызов делает свой `unlock()`,
в том числе базовый случай с `a <= 1`. Получаются два блока чисел от 10 до 1.

Обычный `std::mutex` нельзя повторно захватывать в уже владеющем им потоке:
это неопределённое поведение, которое может проявляться зависанием.
В комментариях `main.cpp` есть намеренно неверные варианты работы с `std::mutex`;
не считайте их альтернативными корректными способами синхронизации.

### Почему рекурсия проходит, а второй поток ждёт

Мьютекс `mtx` учитывает владельца и глубину его захватов. При вызовах `foo(10)`, `foo(9)`, …
`foo(1)` **один и тот же поток** успешно захватывает `mtx` десять раз.
Это не десять новых потоков. При возврате вызовы освобождают захваты
по одному; только нулевая глубина открывает доступ другому потоку.

Другой поток ждёт в своём первом `mtx.lock()`, пока владелец не освободит
все захваты. Пауза 200 мс перед созданием второго потока делает ожидаемый
порядок вероятным, но не доказывает, кто захватит `mtx` первым.

Результат — два отдельных блока 10…1; идентичные числа не показывают,
какой из работников был первым.
Все ветви `foo()` должны освобождать свой успешный захват, включая базовый случай.
Автоматическое освобождение при выходе из блока разобрано в
[«`std::lock_guard`: автоматическое освобождение мьютекса»](../lesson-07-lock-guard/README.md).

`std::recursive_mutex` нужен только при осознанном повторном входе владельца.
Он не решает deadlock двух разных мьютексов и может скрыть слишком сложную
схему вызовов. Часто интерфейс можно разделить на внешнюю функцию с `lock`
и внутреннюю, вызываемую при уже удерживаемой блокировке.
