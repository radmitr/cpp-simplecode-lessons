# 07. `std::lock_guard`

## Версия C++

`std::thread`, `std::mutex`, `std::lock_guard`, `std::chrono` — **C++11**.
`std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Как и в уроке [«06. `std::mutex`»](../lesson-06-mutex/README.md), три потока печатают блоки символов.
Объект `guard` захватывает `mtx` при создании, а при уничтожении освобождает его.

## Как это работает

Дополнительные фигурные скобки внутри `print()` ограничивают время жизни `guard`:
мьютекс занят только при печати, а последняя пауза уже выполняется без блокировки.
Освобождение произойдёт также при `return` или исключении с выходом из этого блока.

При занятом мьютексе конструктор `lock_guard` ждёт так же, как `mtx.lock()`.
Преимущество — автоматическое освобождение, а не отсутствие ожидания.
У `guard` нет методов `lock()` и `unlock()`; для явного управления есть `unique_lock`.

### Почему `guard` надёжнее ручной пары

~~~cpp
{
    std::lock_guard<std::mutex> guard(mtx);
    // Защищённая работа.
} // Деструктор guard вызывает unlock.
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

`guard` — имя обычной локальной переменной. Его срок жизни, а не отступы
или имя функции, определяет границы владения.
RAII связывает ресурс с объектом: при выходе из блока деструктор выполняет
освобождение, в том числе при раскрутке стека из-за исключения.

Если `guard` объявлен в начале функции, он удерживает `mutex` до её конца,
даже после последнего обращения к общим данным.
Не заменяйте именованный объект на временный `std::lock_guard<std::mutex>{mtx};`
такой объект уничтожится в конце строки и не защитит следующий код.

`lock_guard` нельзя копировать или перемещать. Он не предоставляет `unlock`.
Для простой одной области это удобный выбор; `unique_lock` нужен для ожидания
`condition_variable`, раннего освобождения или передачи владения.
Метка `adopt_lock` — отдельный режим: вызывающий уже обязан владеть `mutex`.
