# 26. False sharing

## Версия C++

`std::hardware_destructive_interference_size` — **C++17**.
`std::thread`, `std::atomic`, `std::shared_future`, `std::promise`, `std::chrono` — **C++11**.
`std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Два потока увеличивают два разных атомарных счётчика.
Гонки данных нет, но расположение счётчиков в памяти может влиять на скорость.
Перед изучением полезны [atomic](../20-atomic/),
[shared_future](../13-shared-future/) и [измерение времени](../25-parallel-sum/).

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

### Почему разные переменные могут мешать друг другу

Процессор работает с кешем блоками памяти — кеш-линиями.
Если два счётчика находятся в одной линии, записи с разных ядер могут
вызывать согласование и передачу владения этой линией между кешами.
Счётчики логически независимы, но аппаратно делят один блок.
Это называется `false` sharing, или ложное совместное использование.

Пример сравнивает два расположения:

- `AdjacentCounters`: два атомарных счётчика рядом в одном объекте;
- `SeparateCounter`: каждый счётчик в отдельном выровненном объекте.

`alignas(separation)` задаёт выравнивание объекта. Размер типа также учитывает
это выравнивание, поэтому отдельные объекты `SeparateCounter` занимают
раздельные участки памяти.

separation выбирается из `std::hardware_destructive_interference_size`,
если библиотека предоставляет эту константу. Это рекомендация реализации
для разнесения объектов, а не запрос фактического размера кеша процессора.
Запасное значение 64 байта предназначено для учебного эксперимента
и не является универсальным размером кеш-линии.

### Что делает программа

В каждом варианте два потока выполняют по 1000000 операций `fetch_add()`.
Каждый изменяет свой счётчик; memory_order_relaxed здесь достаточно,
потому что счётчики не публикуют другие данные.

`shared_future<void>` используется как разрешение начать работу:
оба работника ждут `gate.wait()`, `main` вызывает `start.set_value()`.
Это не гарантирует запуск инструкций в один физический момент:
процессорное время всё равно распределяет планировщик.

Каждый вариант повторяется три раза. Программа проверяет, что оба счётчика
равны 1000000, и печатает среднее время. Время включает создание потоков,
разрешение старта и `join()`, но не первоначальную подготовку `promise`.
Порядок вариантов фиксированный, поэтому прогрев и фоновые нагрузки
тоже могут влиять на сравнение.

После `join()` можно безопасно сбросить счётчики перед следующим запуском.
Обращения обоих вариантов атомарны: для измерения не используется гонка данных.

Программа не требует, чтобы Separated оказался быстрее.
Эффект зависит от процессора, кеша, размещения потоков, настроек компилятора
и нагрузки. Отсутствие ускорения в одном запуске не опровергает `false` sharing.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

F5 или Ctrl+F5 собирает отладочный вариант с общим для проекта `-O0`.
Он подходит для разбора кода. Для сравнения времени используйте `-O2`.
Следующие команды выполняются из корня репозитория.

Linux:

~~~bash
mkdir -p build/multithreading/additions/26-false-sharing
g++ -std=c++17 -O2 -g -Wall -Wextra -Wpedantic -pthread multithreading/additions/26-false-sharing/main.cpp -o build/multithreading/additions/26-false-sharing/main-optimized
./build/multithreading/additions/26-false-sharing/main-optimized
~~~

Windows, MSYS2 Bash:

~~~bash
mkdir -p build/multithreading/additions/26-false-sharing
/mingw64/bin/g++ -std=c++17 -O2 -g -Wall -Wextra -Wpedantic -pthread multithreading/additions/26-false-sharing/main.cpp -o build/multithreading/additions/26-false-sharing/main-optimized.exe
./build/multithreading/additions/26-false-sharing/main-optimized.exe
~~~

Для обычной сборки используйте `scripts/build-linux.sh` или
`scripts/build-windows.sh` с путём к `main.cpp`, как в остальных дополнениях.
После добавления исходников обновите IntelliSense через задачу
C/C++: Update IntelliSense.
