# 02. `thread_local`

## Версия C++

`std::thread`, `std::mutex`, `std::lock_guard`, `std::atomic`, `auto` — **C++11**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`incrementLocal()` содержит `thread_local int counter = 0`.
У каждого потока свой `counter`, который сохраняется между вызовами этой функции
внутри данного потока.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

- [main2.cpp](main2.cpp): создание и уничтожение объекта `thread_local`.
- [main3.cpp](main3.cpp): два задания одного работника пула разделяют его состояние;
  этот вариант изучайте после [учебного пула потоков](../14-thread-pool/README.md).

## Как это работает

Два рабочих потока вызывают `incrementLocal()` по три раза.
Поэтому каждый выводит `local = 3`, а не общий результат 6.
Главный поток затем вызывает функцию первый раз и получает `local = 1`.

Для сравнения оба рабочих потока увеличивают shared — общий `atomic<int>`.
Он выводит Shared total: 6. Вызов `incrementLocal()` из `main` не увеличивает shared.

Мьютекс `outputMutex` нужен для цельных сообщений в консоли.
Сами личные счётчики в этом примере не требуют взаимного исключения,
потому что каждый поток обращается только к собственному объекту.

Обычная локальная переменная `int counter = 0` создавалась бы заново при каждом
вызове `incrementLocal()`. С `thread_local` у каждого потока своя переменная,
и её значение сохраняется между вызовами до завершения этого потока.
В пуле потоков один работник выполняет много заданий. Его `thread_local`
сохранится между ними: новое задание не получит автоматически новый счётчик.

Если передать указатель на свой `thread_local` другому потоку, доступ к одному
объекту снова может потребовать синхронизации; в этом примере указатели не передаются.

### Локальная переменная, `static` и `thread_local`

Обычный `int counter = 0` в теле функции создавался бы при каждом входе:
каждый вызов вернул бы 1. `static int counter = 0` сохранялся бы между
всеми потоками и требовал бы синхронизации.
`thread_local` сохраняет отдельное состояние для каждого потока.

Срок жизни связан с потоком, а не с одним заданием. В пуле один работник
может исполнить несколько задач и сохранить между ними `thread_local`-счётчик.
Это важно для кешей, накопителей и состояния обработчика запросов.

У класса с `thread_local`-хранением может выполняться деструктор при нормальном
выходе потока. Не передавайте адрес его экземпляра наружу с ожиданием,
что он переживёт этот поток. `thread_local` не является средством передачи
общего результата между работниками.

### `main2.cpp`: когда вызывается деструктор

Функция `state()` хранит `thread_local State instance`.
Первый вызов в рабочем потоке создаёт объект, второй возвращает **тот же**
объект этого потока. Два обращения увеличивают `calls` до `2`.

При нормальном завершении рабочего потока уничтожается его `State`,
деструктор увеличивает `destroyed`. Главный читает итоги после `join()`,
поэтому к этому моменту деструктор уже закончил работу.
Вывод: `Created: 1; destroyed: 1; calls: 2`.

Главный не вызывает `state()`, поэтому своего экземпляра не создаёт.
Счётчики создания и уничтожения атомарные, их общая память живёт дольше работника.
Остановка всего процесса через `_Exit/terminate` не обязана выполнять
такую обычную очистку.

### `main3.cpp`: состояние принадлежит работнику, а не заданию

Используем [учебный пул потоков](../14-thread-pool/README.md) с **одним**
работником. Первый вызов `nextTaskNumber` возвращает `1`, второй — `2`.
Задание закончилось, но поток продолжает жить и сохраняет свой счётчик.

После уничтожения первого пула его работник завершается.
Новый пул создаёт новый поток с новым экземпляром счётчика: снова `1`.
Даже если ОС повторно использует числовой идентификатор потока,
старое локальное состояние не наследуется.
Вывод: `Same worker: 1 2; new pool: 1`.

Это важно для кешей и данных запроса: если их надо сбрасывать между заданиями,
сброс должен выполнять ваш код. `thread_local` сам не знает границ задания.

Оба варианта не требуют ввода, не создают файлов и проверяют результат:
`0` при успехе, `1` при несоответствии.
