# 08. Взаимная блокировка — deadlock

## Версия C++

`std::thread`, `std::mutex`, `std::chrono` — **C++11**.
`std::size_t` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

В текущем `main.cpp` обе функции захватывают сначала `mtx1`, затем `mtx2`.
Потоки по очереди печатают блоки * и #, после чего завершаются.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Закомментированная альтернатива в `print()` меняет порядок на `mtx2`, затем `mtx1`.
Если включить её вместо активных строк, один поток может удерживать `mtx1`
и ждать `mtx2`, а другой — удерживать `mtx2` и ждать `mtx1`.
Ни один не сможет продолжить, `main` останется в `join()`.

Пауза между захватами повышает вероятность проблемы, но не гарантирует
взаимную блокировку при каждом запуске.
Для опыта выбирайте один вариант захвата, не добавляйте оба подряд.

Порядок освобождения обычных `mutex` не обязан быть обратным,
но каждый должен освобождаться владельцем ровно один раз на успешный захват.
Продолжение темы: [scoped_lock](../bonus/03-scoped-lock/).

### Как возникает цикл ожидания

Если `print` захватил `mtx2`, а `print2` — `mtx1`, каждый может ждать второй `mutex`,
который удерживается соседом. Оба остановились до `unlock`. `join` в `main`
не устраняет такую взаимную зависимость и тоже остаётся ждать.

Единый порядок захвата разрывает этот цикл: все начинают с `mtx1`.
В текущем активном варианте именно это и происходит.
Порядок освобождения не создаёт тот же цикл, но освобождение в обратном
порядке часто упрощает чтение и соответствует вложенным RAII-объектам.
