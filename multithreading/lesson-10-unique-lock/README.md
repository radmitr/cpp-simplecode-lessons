## Как это работает

В активном `print()` объект `lock` создаётся с `std::defer_lock`:
он связан с `mtx`, но пока не захватывает его.
Затем поток спит 2 секунды и вызывает `lock.lock()`.
Один поток печатает, второй ждёт. При выходе из `print()` объект `lock`
освобождает `mtx`.

В закомментированной версии после печати выполняется `lock.unlock()`,
а затем ещё одна пауза без удержания мьютекса. Это альтернативная реализация:
две функции `print(char)` одновременно определить нельзя.

### Зачем нужен `std::unique_lock`

Для активного примера подошёл бы и `std::lock_guard`, созданный после первой
паузы. `std::unique_lock` позволяет создать управляющий объект заранее,
захватить мьютекс позже и явно освободить его вызовом `lock.unlock()`, не
дожидаясь выхода из области видимости.
Деструктор освобождает мьютекс только если объект всё ещё им владеет.
Сам мьютекс должен существовать дольше управляющего им объекта.

зависит от выполнения. При успешном завершении код возврата `0`.
