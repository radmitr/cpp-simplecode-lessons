# 10. std::unique_lock

В активном print() объект ul создаётся с std::defer_lock:
он связан с mtx, но пока не захватывает его.
Затем поток спит 2 секунды и вызывает ul.lock().
Один поток печатает, второй ждёт. При выходе из print() ul освобождает mtx.

В закомментированной версии после печати выполняется ul.unlock(),
а затем ещё одна пауза без удержания мьютекса.
Это альтернативная реализация: две функции print(char) одновременно определить нельзя.

Для активного примера подошёл бы и lock_guard, созданный после первой паузы.
Преимущество unique_lock — возможность отложить захват, освободить мьютекс
до уничтожения объекта и затем захватить его снова.
Деструктор освобождает мьютекс только если ul всё ещё им владеет.

Практическое применение: [condition_variable](../bonus/04-condition-variable/).
Её wait() нужен unique_lock, чтобы отпускать mutex на время ожидания
и заново захватывать его перед возвратом.
