# 10. std::unique_lock

`main.cpp` — исходный пример урока. Закомментированная версия `print()`
оставлена для сравнения с работающей функцией.

В активном print() объект ul создаётся с std::defer_lock:
он связан с mtx, но пока не захватывает его.
Затем поток спит 2 секунды и вызывает ul.lock().
Один поток печатает, второй ждёт. При выходе из print() ul освобождает mtx.

В закомментированной версии после печати выполняется ul.unlock(),
а затем ещё одна пауза без удержания мьютекса.
Это альтернативная реализация: две функции print(char) одновременно определить нельзя.

Для активного примера подошёл бы и lock_guard, созданный после первой паузы.
Преимущество unique_lock — возможность отложить захват, освободить мьютекс
до уничтожения объекта и затем захватить его снова.
Деструктор освобождает мьютекс только если ul всё ещё им владеет.

## main2.cpp — сравнение четырёх вариантов

Откройте `main2.cpp` и запустите его через F5 или Ctrl+F5. Каждый вариант
по очереди запускает два потока, печатает их символы и примерное время работы.
Общая функция `printChars()` убирает повторение циклов печати.

1. `printLockImmediately()` захватывает мьютекс и затем делает паузу. Второй
   поток ждёт мьютекс даже во время первой паузы.
2. `printLockAfterPause()` сначала делает паузу, затем захватывает мьютекс.
   Оба потока могут выполнить первую паузу одновременно.
3. `printDeferred()` создаёт `unique_lock` с `defer_lock`, делает паузу и
   вызывает `lock()`. Поведение похоже на вариант 2, но объект `unique_lock`
   создаётся до паузы.
4. `printUnlockEarly()` после печати вызывает `unlock()`, а затем делает ещё
   одну паузу без мьютекса. В это время другой поток может печатать.

Время зависит от планирования потоков и служит лишь иллюстрацией порядка
захвата. `main.cpp` при этом остаётся отдельным примером исходного урока.
