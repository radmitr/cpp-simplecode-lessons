# 05. Методы класса в потоке

Все четыре файла — самостоятельные программы. Открывайте и запускайте их по очереди.

- main.cpp: лямбда с [&] вызывает m.sum(2, 5) у исходного m.
  result читается после join(), результат равен 7.
- main2.cpp: thread(&MyClass::doWork, m) сохраняет копию m и вызывает метод у неё.
- main3.cpp: thread(&MyClass::doWork2, m, 123) тоже копирует m,
  но дополнительно передаёт аргумент 123.
- main4.cpp: std::ref(m) передаёт исходный объект без копирования m.

&MyClass::doWork2 — указатель на метод класса. Это другой смысл символа &,
чем ссылка в int& или захват по ссылке в [&].
std::ref объявлен в `<functional>`. При передаче по ссылке объект должен жить
до завершения потока; в этих примерах это обеспечивается join() перед выходом из main.

Закомментированные лямбды позволяют сравнить две формы запуска метода.
## Один символ &, три разных операции

~~~cpp
std::thread a(&MyClass::doWork2, m, 123);           // Копия объекта.
std::thread b(&MyClass::doWork2, std::ref(m), 123); // Исходный объект.
// Альтернатива отдельному примеру:
std::thread c([&m] { m.doWork2(123); });           // Ссылка в замыкании.
~~~

Это иллюстрация форм API; при добавлении всех трёх строк каждый созданный
поток нужно отдельно завершить через join. Текущие файлы запускаются раздельно.

&MyClass::doWork2 создаёт указатель на нестатический метод. Для его вызова
нужен ещё объект. std::ref(m) хранит ссылку на объект. [&m] захватывает
ссылку внутри лямбды. Вариант [&] из main захватывает по ссылке используемые
внешние m и result, но не каждую существующую переменную вообще.

Копия m имеет отдельные обычные поля. Но если в классе есть указатели или
shared_ptr, копирование класса не обязательно копирует целиком связанные данные.
При использовании исходного m join обеспечивает срок жизни, а защита
одновременного изменения его полей потребовала бы отдельной синхронизации.
