# Общий код libpq

db.hpp включается непосредственно из каждого main.cpp, отдельной компиляции не требует.
Это небольшие учебные обёртки, а не универсальная библиотека доступа к БД.

- Connection — `unique_ptr<PGconn, ...>`. PGconn представляет соединение;
  PQfinish закрывает его в деструкторе.
- Result — `unique_ptr<PGresult, ...>`. PQclear освобождает результат.
  result.get() даёт обычный указатель для функций C API.
- connect задаёт параметры через PQconnectdbParams и проверяет CONNECTION_OK.
  Путь к pgpass.conf вычисляется относительно заголовка, поэтому запуск
  работает из корня проекта и папки урока.
- exec выполняет фиксированный SQL через PQexec.
- params вызывает PQexecParams с текстовыми параметрами; nullptr означает NULL.
- checked принимает PGRES_COMMAND_OK / PGRES_TUPLES_OK; при ошибке
  сохраняет SQLSTATE в db::Error. COPY проверяет специальные статусы отдельно.
- value проверяет границы и NULL и возвращает копию текста std::string.
  PQgetvalue сам возвращает заимствованный указатель, действующий до PQclear.
- print печатает строки, явно отображая NULL. Это вывод для обучения,
  а не формат сериализации.
- Transaction делает BEGIN, commit — COMMIT, деструктор без commit — ROLLBACK.
  Соединение обязано жить дольше транзакции; вложенные BEGIN не поддерживаются.
  Для вложенных этапов используйте SAVEPOINT.
- SharedSchema нужна только для уроков 17–18: имя `cpp_lab_<backend_pid>`
  формируется из числа сервера, без пользовательского ввода. При обычном выходе
  удаляется только схема этого запуска. Это не образец построения SQL из ввода.
- run перехватывает исключение, выводит ошибку и возвращает ненулевой код.

Возвращённый PGresult существует независимо от следующих запросов,
пока не вызван PQclear. Владение результатом и удержание блокировки — разные вещи:
освобождение результата SELECT FOR UPDATE не снимает блокировку транзакции.

По умолчанию libpq передаёт результаты текстом. Для чисел нужны проверки
преобразования и диапазона; для NULL — PQgetisnull. В этих примерах нет ORM,
пула соединений, автоматических повторов, бинарного протокола или TLS-настройки
для удалённого сервера. Для локального учебного стенда это позволяет видеть SQL
и основные вызовы libpq.
