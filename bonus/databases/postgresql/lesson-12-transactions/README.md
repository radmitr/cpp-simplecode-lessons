# 12. Транзакции: COMMIT и ROLLBACK

C++17 · PostgreSQL · libpq · Windows/MinGW64 и Linux.

Перевод состоит из двух UPDATE: списать 30 с первого счёта и добавить
30 второму. Оба запроса выполняются между BEGIN и COMMIT.

Затем начинается второй перевод: деньги списываются, но программа выбрасывает
исключение до зачисления. Деструктор db::Transaction выполняет ROLLBACK.

~~~text
Second transfer rolled back
1 | 70
2 | 130
~~~

Транзакция объединяет изменения: COMMIT сохраняет их, ROLLBACK отменяет.
Деструктор — страховка на случай исключения или раннего выхода.
Объект соединения должен жить дольше объекта Transaction.
Класс запрещает копирование, чтобы два объекта не управляли одной транзакцией.

Транзакция не делает любую бизнес-логику автоматически безопасной при нескольких
клиентах: доступ к одним строкам требует продуманного SQL, ограничений,
блокировок или подходящего уровня изоляции. Здесь используется один клиент;
конкурентные сценарии разобраны в уроках 17–18.

Если соединение потеряно во время COMMIT, клиент может не знать, сохранился ли
результат. Повторение операции требует отдельного решения, например
уникального идентификатора операции; слепой повтор может выполнить её дважды.

[Транзакции](https://www.postgresql.org/docs/current/tutorial-transactions.html).

## Сборка и запуск

Сначала [установите зависимости и запустите учебный сервер](../README.md).
Команды из корня репозитория собирают main.cpp и запускают результат.

Linux / MSYS2 MinGW64:

~~~bash
bash bonus/databases/postgresql/scripts/run.sh 12
~~~

Windows PowerShell:

~~~powershell
& C:\msys64\usr\bin\bash.exe bonus/databases/postgresql/scripts/run.sh 12
~~~

В VS Code откройте main.cpp и нажмите F5. Сервер должен быть запущен заранее.
