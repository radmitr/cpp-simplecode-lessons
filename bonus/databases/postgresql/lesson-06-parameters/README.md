# 06. Параметры и защита от SQL-инъекции

C++17 · PostgreSQL · libpq · Windows/MinGW64 и Linux.

В SQL остаются места $1 и $2, а значения передаются отдельным массивом
в PQexecParams. db::params — небольшая обёртка над этим вызовом.

~~~sql
INSERT INTO notes VALUES ($1::int, $2::text);
~~~

::int и ::text явно задают ожидаемые типы. Параметры не заключают в кавычки.
Строка с кавычкой и SQL-подобным содержимым сохраняется буквально:

~~~text
Stored literally: O'Reilly; DROP TABLE notes; --
~~~

Склеивание SQL с пользовательским вводом могло бы изменить смысл команды.
Параметры разделяют команду и данные: сервер не исполняет содержимое параметра
как отдельную SQL-команду. Дополнительное ручное экранирование параметра не нужно.

Параметром нельзя заменить имя таблицы, столбца, ASC/DESC или SQL-оператор.
Для таких вариантов выбирайте SQL из заранее разрешённого набора.
Если действительно нужно динамическое имя, используйте PQescapeIdentifier
и проверяйте права/допустимые объекты; это не замена параметрам значений.

[Выполнение параметризованных запросов](https://www.postgresql.org/docs/current/libpq-exec.html).

## Сборка и запуск

Сначала [установите зависимости и запустите учебный сервер](../README.md).
Команды из корня репозитория собирают main.cpp и запускают результат.

Linux / MSYS2 MinGW64:

~~~bash
bash bonus/databases/postgresql/scripts/run.sh 06
~~~

Windows PowerShell:

~~~powershell
& C:\msys64\usr\bin\bash.exe bonus/databases/postgresql/scripts/run.sh 06
~~~

В VS Code откройте main.cpp и нажмите F5. Сервер должен быть запущен заранее.
