# 18. HTTP/2 и HTTP/3 через libcurl

## Версия C++

`std::unique_ptr` — **C++11**. Сборка примера — **C++17**.
Версии HTTP не связаны с версией C++: их реализует внешняя библиотека `libcurl`.
Нужны заголовки и библиотека **libcurl 7.88.0 или новее** для режима
`CURL_HTTP_VERSION_3ONLY`. Поддержка HTTP/2 и HTTP/3 зависит от сборки библиотеки.

## Что изучаем

Продолжаем [HTTP GET](../14-http-get/README.md) и
[HTTPS](../17-https/README.md): запрашиваем версию протокола и проверяем,
какая версия действительно использована. HTTP/2 использует двоичные кадры и
потоки внутри TCP-соединения, HTTP/3 — QUIC поверх UDP с TLS 1.3.
Программа работает через API `libcurl`; собственные кодеки HTTP/2/QUIC здесь
не реализуются. Мультиплексирование нескольких запросов не демонстрируется.

## Примеры

- [main.cpp](main.cpp) — один GET-запрос с выбором режима, проверкой возможностей,
  сертификата, фактической версии и HTTP-статуса.
- [Локальные службы](../tests/local_services.py) — HTTPS HTTP/1.1 и HTTP/2,
  а также HTTP/3 для воспроизводимого запуска.
- [Интеграционная проверка](../tests/smoke_advanced.py) — настоящие локальные
  обмены HTTP/2 и HTTP/3, возврат к HTTP/1.1 и ошибки строгого режима/сертификата.

## Как это работает

Сначала запустите программу с `--features`: она напечатает, например,
`libcurl 8.22.0; HTTP2=1; HTTP3=1`. Данные берутся через `curl_version_info()`
из загруженной библиотеки. Наличие новых заголовков ещё не означает, что
в исполняемой библиотеке есть соответствующий транспорт.
При `HTTP3=0` клиент явно сообщает об отсутствии поддержки и возвращает `1`.

Предположим, локальный сервер поддерживает HTTP/2. Режим `h2-only` задаёт
`CURLOPT_HTTP_VERSION`, выполняет GET и читает `CURLINFO_HTTP_VERSION`.
Ожидаемый результат: `Negotiated HTTP/2; status 200` и `Body bytes: 2`.
Если сервер поддерживает только HTTP/1.1, строгий режим не считается успешным.
В режиме `h2` такой переход разрешён: программа честно напечатает HTTP/1.1.
Число `200` — статус ответа, оно не сообщает версию HTTP.

Доступные режимы той же программы:

- `h1` — `CURL_HTTP_VERSION_1_1`, обычный HTTP/1.1-запрос.
- `h2` — `CURL_HTTP_VERSION_2TLS`: при HTTPS предлагается HTTP/2 с разрешённым
  возвратом к HTTP/1.1; для `http://` используется HTTP/1.1.
- `h2-only` — `CURL_HTTP_VERSION_2_PRIOR_KNOWLEDGE`: для `http://` сразу посылается
  HTTP/2 без HTTP/1.1 Upgrade, поэтому сервер должен быть заранее известен как
  HTTP/2-совместимый. Для HTTPS версия согласуется через TLS ALPN.
- `h3` — `CURL_HTTP_VERSION_3`: попытка HTTP/3 с разрешённым возвратом к более
  раннему HTTP, если QUIC недоступен.
- `h3-only` — `CURL_HTTP_VERSION_3ONLY`: HTTP/3 без возврата к TCP/HTTP/1.1–2.

**ALPN** — обмен именами поддерживаемых прикладных протоколов во время TLS
handshake. Начиная с libcurl 8.10, `2_PRIOR_KNOWLEDGE` при HTTPS предлагает
только HTTP/2; более старые версии могли предложить также HTTP/1.1. Поэтому
пример в любом случае отдельно сравнивает фактическую версию со строгим режимом.
HTTP/3 использует HTTPS и UDP: наличие обычного TLS-сервера на TCP-порту
не делает его HTTP/3-сервером. В режиме `h3` libcurl может параллельно пробовать
более ранний транспорт; успешный ответ не гарантирует выбор HTTP/3.

Для каждого запуска создаётся новый easy handle, поэтому существующее соединение
другой версии не переиспользуется. Значение `CURLOPT_HTTP_VERSION` передаётся
как `long`: это важно для старых заголовков и вариативного API `curl_easy_setopt()`.
Адрес ограничен схемами `http://`/`https://`, автоматических перенаправлений нет.
Для HTTPS включены проверка CA и имени, минимум TLS 1.2 (для HTTP/3 транспорт
использует TLS 1.3). Третий аргумент задаёт доверенный CA; без него используются
пути доверия текущей сборки `libcurl`. Отключения проверки нет.

Дедлайн подключения — 2 секунды, всего запроса — 5 секунд. Общий обработчик
`web::collect()` ограничивает тело 64 КиБ и не выпускает исключения C++ через
границу C callback. Тело хранится в `std::string` до окончания запроса.
`unique_ptr` освобождает easy handle и при ошибке; `web::Runtime` выполняет
общую инициализацию и очистку `libcurl` после уничтожения handle.

## Сборка и запуск

[Установка libcurl на Windows](../README.md#windows), [Linux](../README.md#linux),
[F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Используйте `libcurl >= 7.88`; старые дистрибутивы могут поставлять более раннюю
версию. Для HTTP/3 также нужна сборка `libcurl` с QUIC-зависимостями — установка
одних заголовков это не добавит. `--features` проверяет фактическую библиотеку.
[Отдельная установка libcurl на Linux](../linux-curl.md) включает HTTP/2 и HTTP/3;
общие скрипты выбирают `/opt/curl/8` или явно заданный `CURL_PREFIX`.

Из корня, Linux:

```bash
bash scripts/build-linux.sh bonus/networking/18-http-versions/main.cpp
./build/bonus/networking/18-http-versions/main --features
```

Windows, PowerShell:

```powershell
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh bonus/networking/18-http-versions/main.cpp
& .\build\bonus\networking\18-http-versions\main.exe --features
```

Создайте [сертификат](../tests/README.md#сертификат-для-ручных-примеров) и
подготовьте [Python-окружение](../tests/README.md#зависимости-python).
В отдельном терминале запустите [локальную службу `h2`](../tests/README.md#службы-для-ручного-запуска)
на порту `42023`, дождитесь `Listening`. Linux:

```bash
./build/bonus/networking/18-http-versions/main h2-only https://localhost:42023/ build/networking-tls/cert.pem
```

Windows:

```powershell
& .\build\bonus\networking\18-http-versions\main.exe h2-only https://localhost:42023/ build/networking-tls/cert.pem
```

Остановите службу и запустите её с режимом `h3` вместо `h2`; повторите клиент
с `h3-only`. Ожидается `Negotiated HTTP/3; status 200`.
Для fallback запустите службу `h1`, а клиент — с `h2` или `h3`: ожидается
`Negotiated HTTP/1.1; status 200`. Подменять только URL без смены службы недостаточно.
Режим `h1` на этой же службе показывает прямой HTTP/1.1-запрос.

Синтаксис: `main h1|h2|h2-only|h3|h3-only URL [ca.pem]` либо `main --features`.
Ввода нет; внешние URL допускаются только при явной передаче пользователем,
локальные команды Интернета не требуют. Сертификат и ключ нужны службе;
клиент читает только CA-файл, данных на диск не пишет.
Код `0` — статус 2xx и выполнение требований выбранного режима; ошибка сети,
TLS, неподдержанная функция, другой статус или нарушение строгой версии — `1`.
Точный текст системной ошибки и версия при разрешённом fallback могут отличаться.

F5 в папке урока по умолчанию запускает `--features`; для запроса измените
`args` или используйте терминал. Полный тест — `smoke_advanced.py` в подготовленном
окружении. Если библиотека не поддерживает HTTP/3, полный набор явно завершается
ошибкой; режим `--skip-services` отмечает пропущенные успешные обмены как `SKIP`.

## Типичные ошибки

- Печатать запрошенную версию вместо значения `CURLINFO_HTTP_VERSION`.
- Считать режим `h2`/`h3` гарантией версии, когда он разрешает fallback.
- Посылать HTTP/2 prior knowledge обычному HTTP/1.1-серверу.
- Ожидать HTTP/3 только из-за TLS-сертификата или считать его протоколом поверх TCP.
- Проверять возможности установленной утилиты `curl`, когда программа загружает
  другую DLL `libcurl` из другого окружения.
