# 22. MQTT: публикация и подписка через брокер

## Версия C++

`std::string_view` в учебном кодеке — **C++17**; `std::chrono` и перемещение
сокета — **C++11**. Сборка — **C++17**. MQTT 3.1.1 — внешний протокол,
не часть стандарта языка. Код использует общие WinSock/POSIX-обёртки проекта.

## Что изучаем

В отличие от [TCP echo](../lesson-02-tcp-echo/README.md), издатель не подключается
напрямую к получателю. Оба соединяются с **брокером** — сервером, который принимает
публикации и направляет их подписчикам соответствующей темы. В этом примере
датчик публикует `23.5` в тему `lesson/temperature`, а отдельная программа читает её.
Прежде разберите [границы сообщений TCP](../lesson-03-tcp-framing/README.md).

## Примеры

- [subscriber.cpp](subscriber.cpp) подключается, подписывается на одну тему,
  получает одно сообщение и завершается.
- [publisher.cpp](publisher.cpp) публикует значение `23.5` с QoS 0 и завершается.
- [mqtt.hpp](mqtt.hpp) — ограниченный учебный кодек пакетов MQTT 3.1.1.
  Это не универсальная MQTT-библиотека.
- [Локальный брокер](../tests/local_services.py) использует готовую библиотеку
  aMQTT; [автоматическая проверка](../tests/smoke_advanced.py) запускает его
  и ждёт подтверждения подписки перед публикацией.

## Как это работает

Сначала запускается брокер. Подписчик устанавливает TCP-соединение и отправляет
`CONNECT`: имя протокола `MQTT`, уровень 4 (то есть версия 3.1.1), флаг
`Clean Session` и идентификатор `lesson-subscriber`. Брокер отвечает `CONNACK`.
TCP-подключение само по себе не означает, что MQTT-сеанс принят: отказ в `CONNACK`
обрабатывается как ошибка. `Clean Session` просит новый сеанс без восстановления
прежних подписок. Здесь `Keep Alive = 0`: MQTT-проверка активности выключена,
а собственные дедлайны ограничивают все ожидания.

Затем подписчик отправляет `SUBSCRIBE` с темой `lesson/temperature`, требуемым
QoS 0 и `Packet Identifier = 1`. Это номер операции подписки, не номер измерения.
Ответ `SUBACK` должен подтвердить тот же идентификатор и разрешить QoS 0.
Только после него печатается `Subscribed: lesson/temperature`.
До этой строки публикацию начинать не следует: непринятая подписка ещё не
обязана получить сообщение.

Издатель выполняет отдельный `CONNECT` с идентификатором `lesson-publisher`,
затем посылает `PUBLISH`: имя темы и полезную нагрузку `23.5`. Подписчик получает
от брокера другой пакет `PUBLISH` в своём соединении. Он проверяет тему и выводит
`Received: 23.5`. Брокер выбирает получателей; издателю не нужен их адрес.
Идентификаторы клиентов должны различаться, иначе брокер может закрыть старое
соединение того же клиента.

**Тема** — имя маршрута для сообщений, а не файл и не TCP-порт. Полезная нагрузка —
последовательность байтов; MQTT не требует JSON. Наше значение — обычный текст.
QoS 0 означает отсутствие протокольного подтверждения доставки публикации:
сообщение может потеряться. Вывод `Published QoS 0` подтверждает запись в сокет,
но не получение подписчиком. Другие уровни QoS, шаблоны тем `+`/`#`, сохранённые
публикации, постоянные сеансы и повторные подключения в этом уроке не реализованы.

Пакеты двоичные, без разделения по `\n`. `mqtt.hpp` отправляет первый байт типа
и флагов, затем **Remaining Length** — число байтов оставшейся части пакета,
закодированное группами по 7 бит. Например, длина 128 передаётся байтами
`0x80 0x01`; старший бит первого байта означает продолжение.
Текстовые поля MQTT имеют двухбайтовую длину в сетевом порядке, а payload
занимает остаток `PUBLISH`. `receiveExact()` читает точное количество байтов,
даже если TCP разделил пакет. Один дедлайн применяется ко всему пакету,
а не начинается заново после каждого поступившего байта.

Кодек принимает пакеты не больше 4096 байт и ограничивает создаваемые поля
1024 байтами. Более четырёх байтов длины, неверные ответы брокера и неподдержанный
формат публикации приводят к ошибке. В примере тема, ID и payload фиксированы;
произвольные MQTT UTF-8 строки и все комбинации флагов кодек не поддерживает.
Не используйте его как замену полноценной библиотеке для произвольного брокера.

Обе программы посылают `DISCONNECT` и освобождают сокет через RAII — деструктор
закрывает ресурс при выходе из области видимости, включая исключения.
Брокер не подтверждает `DISCONNECT`. Здесь нет дополнительных потоков клиента:
операции последовательны и ограничены временем.

## Сборка и запуск

[Зависимости Windows](../README.md#windows), [Linux](../README.md#linux),
[F5/Ctrl+F5](../../../README.md#сборка-и-запуск-в-vs-code).
Самим C++-программам нужны только общие сокеты проекта. Брокер — отдельный процесс:
установите [Python-окружение](../tests/README.md#зависимости-python) и запустите
[локальную службу MQTT](../tests/README.md#службы-для-ручного-запуска) на порту 1883.
Служба работает 120 секунд при указанной там команде и слушает только loopback.
Совместимый локальный брокер MQTT 3.1.1 без пароля можно использовать вместо неё.

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/networking/lesson-22-mqtt/subscriber.cpp
bash scripts/build-linux.sh bonus/networking/lesson-22-mqtt/publisher.cpp
```

Windows:

```powershell
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh bonus/networking/lesson-22-mqtt/subscriber.cpp
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh bonus/networking/lesson-22-mqtt/publisher.cpp
```

Пока брокер работает, во втором терминале запустите подписчика, дождитесь
`Subscribed`, затем в третьем — издателя. Linux:

```bash
./build/bonus/networking/lesson-22-mqtt/subscriber
./build/bonus/networking/lesson-22-mqtt/publisher
```

Windows:

```powershell
& .\build\bonus\networking\lesson-22-mqtt\subscriber.exe
& .\build\bonus\networking\lesson-22-mqtt\publisher.exe
```

Оба принимают необязательный порт, по умолчанию `1883`; адрес — `127.0.0.1`.
Ввода и файлов данных нет. Ожидаемый вывод издателя:
`Published QoS 0: lesson/temperature = 23.5`; подписчика —
`Subscribed: lesson/temperature` и `Received: 23.5`. Успех — `0`, ошибка — `1`.
Подключение, подтверждения и запись ограничены пятью секундами; после подписки
на первое сообщение отведено 30 секунд. Если издатель не запущен вовремя,
подписчик возвращает `1`: перезапустите его перед следующим опытом.
Публикация не сохраняется брокером как retained: подписчик, запущенный позже
издателя, не получит старое значение.

В папке урока доступны задачи `Networking: Run subscriber/publisher`.
Они запускают только C++-программы; брокер нужно заранее запустить отдельно.
Полная локальная проверка — `smoke_advanced.py` в подготовленном окружении.
Нужный порядок процессов в ней задаётся по `SUBACK`, без задержек наугад.

## Типичные ошибки

- Подключать издателя напрямую к подписчику вместо MQTT-брокера.
- Путать тему с адресом, QoS с приоритетом, а запись в сокет с доставкой сообщения.
- Публиковать до принятия подписки и ожидать обязательного получения.
- Использовать одинаковые client ID или ожидать поддержки MQTT 5 от этого кодека.
- Передавать пароли и рабочие данные: локальный пример использует обычный TCP
  без TLS и аутентификации.
