# 16. Передача файла блоками и CRC32

C++17. Windows: MinGW64; Linux: POSIX.

По умолчанию клиент создаёт 128 КиБ двоичных данных с байтами 0..255,
передаёт их блоками по 4096 байтов и ждёт подтверждение STORED.
Исходный файл на диске для такого запуска не нужен.

Протокол соединения:

1. Имя файла как кадр с 32-битным префиксом длины.
2. Размер файла: uint32_t в сетевом порядке.
3. CRC32: uint32_t в сетевом порядке.
4. Ровно указанное количество байтов файла.
5. Строка STORED с проверенной CRC32 от сервера.

Максимальный размер учебного файла — 1 МиБ.
Отправитель печатает прогресс, приёмник обновляет CRC32 по каждому блоку.
Пустой файл тоже допустим. Нулевой байт не завершает двоичные данные.

Чтобы передать свой файл, укажите его после порта:

~~~text
client 42016 input.bin
~~~

Сервер по умолчанию сохраняет результат в build/bonus/networking/
lesson-16-file-transfer/received/ внутри проекта. Общие скрипты позволяют
определить этот путь по абсолютному __FILE__. При переносе готового бинарника
или иной сборке укажите каталог явно вторым аргументом:

~~~text
server 42016 output-directory
~~~

Для каждой передачи создаётся новый каталог transfer-... .
Полученное имя используется только как метаданные: файл записывается
под фиксированным именем payload.part. Пути с /, \ и нулевым байтом отклоняются.
После проверки размера и CRC частичный файл переименовывается в payload.bin.
Существующие файлы не перезаписываются. При неудачной проверке частичный файл
и пустой каталог этой передачи удаляются.

CRC-32/ISO-HDLC проверяется на известном векторе 123456789 -> 0xcbf43926.
Это обнаружение случайного повреждения, не криптографическая проверка
подлинности данных. Для защищённой передачи нужен, например, TLS.

STORED означает, что сервер завершил запись и проверку, но не гарантирует
сохранение данных при внезапном отказе питания: принудительный сброс на диск
здесь не реализован. Если файл записан, а ответ потерялся, клиент всё ещё
может не знать результата. Дедупликацию повторной передачи этот урок не добавляет.

## Сборка и запуск

Команды выполняются из корня проекта. Порт по умолчанию — 42016.
Сначала соберите обе программы.

Linux:

~~~bash
bash scripts/build-linux.sh bonus/networking/lesson-16-file-transfer/server.cpp
bash scripts/build-linux.sh bonus/networking/lesson-16-file-transfer/client.cpp
~~~

В первом терминале:

~~~bash
./build/bonus/networking/lesson-16-file-transfer/server
~~~

Во втором терминале после Listening:

~~~bash
./build/bonus/networking/lesson-16-file-transfer/client
~~~

Windows, PowerShell:

~~~powershell
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh bonus/networking/lesson-16-file-transfer/server.cpp
& C:\msys64\usr\bin\bash.exe scripts/build-windows.sh bonus/networking/lesson-16-file-transfer/client.cpp
~~~

В первом терминале:

~~~powershell
& .\build\bonus\networking\lesson-16-file-transfer\server.exe
~~~

Во втором терминале после Listening:

~~~powershell
& .\build\bonus\networking\lesson-16-file-transfer\client.exe
~~~

При открытии папки урока в VS Code используйте Networking: Run server,
затем Networking: Run client. Задачи соберут нужные исходники и запустят их
в разных терминалах. Для отладки клиента оставьте сервер в терминале
и нажмите F5 на client.cpp. Дополнительные аргументы можно передавать из терминала.
После добавления исходников обновите C/C++: Update IntelliSense.
