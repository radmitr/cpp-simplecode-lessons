# 01. Описание работы через senders и receivers

## Версия C++

Режим сборки — **C++26**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках. Для C++26 реализация ещё может быть неполной.

## Что изучаем

Собираем операции в цепочку с явными исходами: значение, ошибка или остановка. Нужны лямбды, tuple, `optional` и исключения.

## Примеры

- [main.cpp](main.cpp) — ленивый запуск, успех и остановка.
- [main2.cpp](main2.cpp) — следующая асинхронная операция, ошибка и восстановление.

## Как это работает

Sender описывает работу, receiver принимает её завершение. Создание `just(3) | then(...)` ещё не выполняет обработчик: работа начинается при подключении и запуске. `sync_wait` выполняет эти шаги и ждёт завершения. `sync_wait` требует ровно одну сигнатуру завершения значением. Поэтому для остановки показан `MaybeValue`: он объявляет значение `int` и остановку, а во время запуска выбирает один канал. Его `connect` создаёт состояние с receiver; `start` синхронно вызывает ровно одно завершение. Receiver хранится в состоянии до конца вызова. Один `just_stopped()` без сигнатуры значения напрямую для `sync_wait` не подходит. Успех представлен непустым `optional<tuple<...>>`, остановка — пустым `optional`, ошибка — исключением. Во втором примере `let_value` возвращает следующий sender, а `upon_error` превращает ошибку в значение. Простые операции `just` выполняются без создания отдельного потока.

`MaybeValue` содержит `get_completion_signatures` для актуального протокола и
alias `completion_signatures` для ранних реализаций.
Маркер `operation_state_concept` обозначает состояние операции. Это служебные
требования протокола, а не дополнительный запуск: вызов `start` выполняется один раз.

## Сборка и запуск

[Настройка компилятора и запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).
Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/execution/01-senders/main.cpp
./build/bonus/execution/01-senders/main
```

Для остальных вариантов замените `main.cpp` и имя исполняемого файла. На Windows вызовите `scripts/build-windows.sh` через MSYS2 Bash, затем соответствующий файл `build/bonus/execution/01-senders/main.exe`. Готовые `tasks.json` и `launch.json` содержат оба варианта системы.

Если возможности нет, программа печатает `UNAVAILABLE` и возвращает `77`: это пропуск, а не успешная демонстрация. Включённая ветка примера требует совместимой реализации; один флаг стандарта не добавляет отсутствующую библиотеку.

Ввода, сетевых служб и постоянных файлов не требуется, если ниже не указано другое. Каждый пример проверяет результаты; успех — строка `OK modern-example` и код `0`, ошибка проверки — код `1`.

## Типичные ошибки

Не разыменовывать пустой результат `sync_wait`. Не считать sender уже готовым future. Обработчики должны сохранять время жизни захваченных данных до завершения операции. Заголовок `<execution>` с одними политиками C++17 не означает поддержку senders C++26: проверяется версия feature-test macro. В локальной libstdc++ ветка senders пока не выполнялась.
