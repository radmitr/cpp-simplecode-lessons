# 02. Планировщик и время жизни операции

## Версия C++

Режим сборки — **C++26**, учебная конфигурация — GCC 16+. Версии отдельных механизмов отмечены в исходниках. Для C++26 реализация ещё может быть неполной.

## Что изучаем

Переносим работу на цикл другого потока и завершаем его в правильном порядке. Нужны предыдущий урок, `jthread` и RAII.

## Примеры

- [main.cpp](main.cpp) — запуск на run_loop другого потока и корректная остановка.

## Как это работает

Сначала создаётся `run_loop`, затем поток начинает обслуживать его очередь. `starts_on` назначает этот планировщик для запуска sender. `sync_wait` в вызывающем потоке ждёт результат; обработчик проверяет, что он выполнился в другом потоке. При выходе из области RAII-объект вызывает `finish`, после чего деструктор `jthread` ждёт завершения потока. Порядок объявлений обеспечивает этот порядок и при исключении.

## Типичные ошибки

Если разрушить `jthread` до `finish`, ожидание может никогда не закончиться: `request_stop` сам по себе не останавливает `run_loop::run`. Цикл, планировщик, захваченные данные и состояние операции должны жить до завершения работы. `starts_on` выбирает место запуска; это не обещание, что любой вложенный асинхронный этап всегда завершится на том же потоке. В текущей локальной библиотеке стандартные senders отсутствуют.
