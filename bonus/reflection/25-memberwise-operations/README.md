# 25. Практика: сравнение, копирование и хеширование

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
обобщённые лямбды — **C++14**.
`auto`, `constexpr`, `decltype`, лямбды, псевдонимы using — **C++11**.
`std::string`, `std::exception`, `std::size_t` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

Для одного поддерживаемого типа обход полей строит три согласованные
операции. Равные объекты должны иметь равные хеши; обратное не гарантируется.
`std::hash` не задаёт устойчивый файловый идентификатор. Поэлементное копирование
может частично изменить получателя при исключении; оно не обеспечивает сильную
гарантию автоматически. `const`-поля, базовые подобъекты и поля без нужных операций
нужно исключать или диагностировать. Обычные defaulted-операции часто проще рефлексии.

## Как это работает

Нужны присваивание, равенство, хеширование и гарантии исключений.

Два `Record{7, "Ada"}` равны и имеют одинаковый вычисленный хеш.
После замены имени на Bob равенство ложно; `copy_fields` возвращает поля
к значениям исходного объекта.

`equal_fields` сравнивает значения, не padding памяти.
`hash_fields` применяет `std::hash` к каждому подходящему типу поля.
Коллизии возможны: одинаковый хеш не доказывает равенства.

Копирование по полям — последовательность присваиваний. Если позднее поле
бросит исключение, прежние уже могли измениться. Для сильной гарантии нужен
отдельный кандидат и безопасная фиксация.
Это не конструктор копирования и не передача владения произвольного сырого
указателя. Для обычного типа defaulted-операции могут быть понятнее.

### Результат и проверка

Последняя строка успешного запуска — `OK 25-memberwise-operations`.
Интерактивного ввода и файловых операций при запуске нет; успех — код `0`.
Ошибка проверки перехватывается: причина выводится в `stderr`, код — `1`.

Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Одинаковые хеши не доказывают равенства. Последовательное присваивание полей может частично изменить получателя при исключении.
