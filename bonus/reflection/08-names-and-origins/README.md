# 08. Имена, псевдонимы, родитель и исходник

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
`auto`, `constexpr`, псевдонимы using — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

identifier_of даёт идентификатор именованной сущности, display_string_of —
строку для отображения и диагностики. dealias снимает псевдоним; parent_of
описывает объявление, а не объект-владелец при запуске. `source_location_of`
помогает диагностике. Имена файлов и диагностические строки не являются
стабильным форматом хранения; перед identifier_of проверяйте has_identifier.

## Как это работает

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

Alias обозначает `model::Item`. dealias снимает псевдоним и позволяет
сравнить основную сущность, parent_of связывает `Item` с пространством model.
`identifier_of(Item)` даёт короткое `Item`, а `display_string_of(Alias)` —
предназначенное для показа описание реализации.

`source_location_of` показывает место объявления, а не место каждого
использования объекта. Номер строки может измениться после правки файла,
поэтому проверяется наличие корректного номера, не одно жёсткое значение.

Не каждое отражение имеет identifier; для потенциально разных категорий
сначала используют has_identifier. Имя для диагностики не заменяет явно
выбранный стабильный идентификатор схемы или протокола.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/08-names-and-origins/main.cpp
./build/bonus/reflection/08-names-and-origins/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

После показанных в коде значений последняя строка — `OK 08-names-and-origins`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
