# 30. Границы, переносимость и стоимость

## Версия C++

`статическая рефлексия` — **C++26**.
`обобщённые лямбды` — **C++14**.
`лямбды` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

Рефлексия не заменяет время жизни, права доступа, корректный формат данных
или типобезопасность. Она не предоставляет Java-подобную динамическую загрузку
неизвестных C++ типов и не генерирует произвольные объявления из строк.
Метаданные могут увеличить работу компилятора, а развёртывание — объём кода;
runtime-стоимость зависит от сгенерированного алгоритма. Сравнивайте одинаковые
задачи с ручной реализацией, фиксируйте версии компилятора, время сборки и размер
бинарника. Для старых инструментов оставляйте явные описатели или обычные функции.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

У `Local` одно поле, поэтому сгенерированный visitor вызывается один раз.
Метаданные известны при компиляции, значение `id` и счётчик `visited`
используются при запуске. Это разделение не означает «вся программа выполняется
при компиляции».

Автоматический список имён меняется при переименовании структуры,
поэтому не заменяет версионированную внешнюю схему.
Неизвестный runtime-текст не создаёт произвольный новый C++-тип в процессе.

Для оценки стоимости сравнивайте одинаковые ручной и отражённый алгоритмы:
время компиляции, размер бинарника, потребление памяти и runtime отдельно.
Этот короткий `main` проверяет только число посещений; он не измеряет
полную стоимость рефлексии и не доказывает преимущество производительности.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/30-limits-and-cost/main.cpp
./build/bonus/reflection/30-limits-and-cost/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

После показанных в коде значений последняя строка — `OK 30-limits-and-cost`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

### Самостоятельно

Сравните ручной и отражённый обход для 3 и 30 полей. Отдельно измерьте время сборки и runtime, не делая вывод по одному запуску.
