# 13. Развёртывание обхода и runtime-значения

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Стандарт и компилятор: GCC 16+ и `c++26`. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

template for разворачивает отдельные фрагменты программы: у каждого поля
может быть свой тип. Обычный цикл выполняет одно тело с одним типом переменной
и не подставляет runtime-info в сплайсер. `std::define_static_array` переносит
полученную при компиляции последовательность в подходящее статическое хранение.
Сам `data` и его значения остаются обычными runtime-данными.

## Разбор кода и границы применения

У `Data` два поля разных типов: `int count = 2` и `double weight = 3.5`.
template for разворачивает отдельное обращение для каждого отражённого поля.
Имена `count` и `weight` известны при компиляции, значения читаются при запуске.
Сумма `total` после обхода — 5.5.

Обычный runtime-for по info не мог бы каждый раз менять статически
проверяемое обращение к неоднородному полю. Expansion statement формирует
подходящие участки кода заранее.

define_static_array предоставляет подходящий сохраняющийся диапазон метаданных.
Разворачивание может увеличивать объём кода и время компиляции.
Оно не создаёт потоков и не означает автоматическое параллельное выполнение.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/13-expansion-statements/main.cpp
./build/bonus/reflection/13-expansion-statements/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
F5 — запуск с отладчиком; Ctrl+F5 — без отладчика.

В VS Code открывайте `main.cpp` и нажимайте F5/Ctrl+F5: доступны корневая и локальная конфигурации.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 13-expansion-statements`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
