# Отрицательные примеры и воспроизводимая проверка

Запуск из корня:

```bash
python3 scripts/check-bonuses.py --section bonus/reflection
```

На Windows используйте python при необходимости. Скрипт собирает каждый main*.cpp
общим build-скриптом, запускает с контролируемыми данными, проверяет код завершения
и собственные проверки примера. Урок 22 собирается из двух единиц трансляции.
Результаты находятся в build/bonus-checks/report.json.

negative.json содержит исходники ожидаемых ошибок, которые компилируются из stdin
с -fsyntax-only и не выполняются:

- Выбор метаданных по runtime-значению.
- Прямое именование private-поля снаружи класса (сплайсинг unchecked-отражения, напротив, разрешён и проверен положительным примером урока 12).
- Использование сплайсера типа без typename в соответствующей позиции.
- define_aggregate вне consteval-блока.

Проверяется ненулевой результат компиляции и характерная категория диагностики,
а не точная полная строка сообщения. Это помогает отличить ожидаемую ошибку
от случайно сломанного исходника. При обновлении компилятора уточняйте диагностику,
а не объявляйте любое падение компиляции успешной проверкой.

Для GCC 11 можно отдельно выполнить --portable-only: будут проверены вводные
уроки 01–05, а C++26 явно пропущен. Это не считается проверкой рефлексии C++26.
Все четыре отрицательных случая требуют нового компилятора.
