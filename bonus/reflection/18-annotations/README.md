# 18. Пользовательские аннотации

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
`if constexpr`, `std::string_view` — **C++17**.
`auto`, `constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

Синтаксис [[=...]] задаёт отражаемую пользовательскую аннотацию.
annotations_of и `annotations_of_with_type` возвращают её отражение. Наличие `Skip`
меняет политику нашего обхода, а не семантику поля в языке. Обычные атрибуты
и пользовательские аннотации — разные механизмы. Для параметризованной аннотации
значение извлекается через extract соответствующего типа.

`main2.cpp` показывает параметризованную `Label` и `extract<Label>`. Аннотация
должна иметь допустимый структурный тип: небольшой публичный массив `char`
подходит, `std::string_view` в качестве её поля в этом интерфейсе не подходит.
Результат — метка identifier, отличная от исходного имени `id`.

## Как это работает

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

У `internal` есть [[=`Skip`{}]], у `visible` аннотации нет.
Обход проверяет `annotations_of_with_type` и суммирует только `visible`:
`included` равно 10. Сам `internal` по-прежнему содержит 20 и существует
как обычное поле — `Skip` интерпретирует наш алгоритм.

main2 задаёт `Label`{"identifier"}, извлекает `Label` через extract
и печатает identifier=7. Это отдельное отображаемое имя, исходное поле
продолжает называться `id`.

Тип аннотации должен удовлетворять требованиям механизма.
В этом примере фиксированный массив `char` подходит для параметра-значения.
Нельзя считать любую произвольную runtime-строку допустимой аннотацией.
Политики пропуска/переименования должны одинаково учитываться чтением и записью.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/18-annotations/main.cpp
./build/bonus/reflection/18-annotations/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

После показанных в коде значений последняя строка — `OK 18-annotations`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
