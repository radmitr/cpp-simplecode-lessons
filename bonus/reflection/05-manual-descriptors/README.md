# 05. Ручные описатели и указатели на члены

## Версия C++

`std::string_view` — **C++17**.
`std::array`, `constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Указатель на член привязывает описатель к объявлению без вычисления смещений
вручную. Разыменование `object.*member` читает или меняет поле. Один массив здесь
поддерживает только поля `int`; для разных типов потребуются `tuple` и шаблонный
обход. Макросы и генераторы могут уменьшить повторение, но список всё равно
нужно где-то описать. Рефлексия C++26 получает его из объявления структуры.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны указатели на члены, массивы и время жизни строк.

Массив `fields` содержит два имени и два указателя на `int`-члены `Person`.
Обход применяет их к `person{10, 20}`, увеличивает значения и выводит
`id=11`, `age=21`. Запись `person.*field.member` выбирает поле по описателю.

Одинаковый тип указателей удобен для этих двух `int`. Поле `string` потребовало бы
другой формы описателя: неоднородный `tuple`, `variant` или вызываемую обёртку.
Одна строка имени сама не позволяет C++ обратиться к полю.

Таблицу удобно использовать для явного разрешённого набора свойств.
Автоматическая рефлексия избавляет от части ручного списка, но не решает
вместо приложения, какие поля допустимо изменять или сериализовать.

## Типичные ошибки

`int Person::*` не подходит для поля другого типа или другого класса. Массив описателей не обновляется автоматически при добавлении поля.

### Самостоятельно

Замените одно поле на `string` и объясните, почему одного типа `int Person::*` уже недостаточно.
