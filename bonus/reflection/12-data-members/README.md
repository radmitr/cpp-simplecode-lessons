# 12. Поля, типы и фильтрация членов

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
обобщённые лямбды — **C++14**.
`auto`, лямбды — **C++11**.
`std::string`, `std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`nonstatic_data_members_of` возвращает описания нестатических полей,
`static_data_members_of` — статических. Общий members_of включает другие категории,
поэтому его результаты нужно фильтровать. Общий helper из `common/reflection.hpp`
разворачивает обращение к каждому полю; значение берётся из `record` при запуске.
Пример работает с открытыми обычными полями; битовые поля и непубличные данные
требуют другого интерфейса.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны нестатические/статические поля и сплайсинг.

`Record` содержит два нестатических поля `id`/`name` и один `static count`.
Для обхода экземпляра выбирается `nonstatic_data_members_of`:
в вывод попадают `id=7` и `name=Ada`, общий `count` обходом не изменяется.

`for_each_field` из `common/reflection.hpp` получает имя и ссылку на поле.
У каждого развёрнутого вызова значение сохраняет свой C++-тип:
`int` и `string` не превращаются в одну нетипизированную ячейку.

Список прямых полей не означает автоматический рекурсивный обход баз
или вложенных объектов. Для них нужна отдельная политика.
В общем helper выбран unprivileged-контекст: он не должен автоматически
раскрывать внутреннее состояние класса через unchecked.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

bash scripts/build-linux.sh bonus/reflection/12-data-members/main.cpp

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение `.exe`.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей

### Результат и проверка

Последняя строка успешного запуска — `OK 12-data-members`.
Интерактивного ввода и файловых операций при запуске нет; успех — код `0`.
Ошибка проверки перехватывается: причина выводится в `stderr`, код — `1`.

Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Статическое поле принадлежит классу, а не каждому экземпляру. Список прямых нестатических полей не включает рекурсивный обход баз и вложенных объектов.
