# 16. Базовые классы и подобъекты

## Версия C++

`std::meta`, статическая рефлексия — **C++26**.
`auto`, `constexpr` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`bases_of` описывает непосредственные базовые подобъекты. Сплайсинг базы
позволяет выбрать конкретный подобъект даже при совпадающих именах `id`. Собственные
нестатические поля и унаследованные поля нельзя бездумно смешивать в один список.
Рекурсивный обход наследования должен отдельно учитывать виртуальные базы,
повторяющиеся типы и выбранную политику включения данных.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Нужны наследование, подобъекты и сплайсинг.

`Derived` содержит `Left::id = 1`, `Right::id = 2` и собственный `own = 3`.
`bases_of` выбирает две прямые базовые связи; `value.[:base:].id` обращается
к конкретному базовому подобъекту без неоднозначного `value.id`.

Сначала печатаются 1 и 2, затем в каждом подобъекте `id` увеличивается:
`Left::id` становится 2, `Right::id` — 3. Поле `own` не изменяется.
Запрос прямых нестатических полей `Derived` находит только `own`.

База и поле — разные категории метаданных. Для полного рекурсивного обхода
иерархии нужно решить, как обрабатывать общие виртуальные базы и дублируемые
пути. Простое склеивание всех списков может посетить общую часть несколько раз.

## Сборка и запуск

[Запуск в VS Code](../../../README.md#сборка-и-запуск-в-vs-code).

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/16-base-subobjects/main.cpp
./build/bonus/reflection/16-base-subobjects/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение `.exe`.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

### Результат и проверка

Последняя строка успешного запуска — `OK 16-base-subobjects`.
Интерактивного ввода и файловых операций при запуске нет; успех — код `0`.
Ошибка проверки перехватывается: причина выводится в `stderr`, код — `1`.

Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).

## Типичные ошибки

Списки баз и собственных полей — разные запросы. Рекурсивный обход обязан отдельно учитывать общую виртуальную базу, чтобы не обработать её несколько раз.
