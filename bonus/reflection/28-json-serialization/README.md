# 28. Практика: JSON без ручного списка полей

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Стандарт и компилятор: GCC 16+ и `c++26`. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

nlohmann/json отвечает за JSON-синтаксис, экранирование и типизированное
преобразование, рефлексия — за список полей. Внешняя библиотека описана в
`dependencies.md`. Пример обрабатывает плоскую структуру со стандартными JSON-типами.
Для вложенных пользовательских структур нужен рекурсивный преобразователь,
для `private`/аннотированных полей — явная политика. Поэлементная загрузка прямо
в объект не даёт сильной гарантии: используйте временный объект, как в следующем уроке.

## Разбор кода и границы применения

Первый обход записывает `Person`{7, "Ada"} в JSON по именам полей.
Второй читает обязательные ключи через `at` и get_to в новый `Person`.
Данные совпадают; замена `id` текстом oops вызывает исключение библиотеки.

Рефлексия предоставляет список полей и типизированные обращения,
nlohmann/json — синтаксис, экранирование и преобразование JSON-типов.
Это две самостоятельные части решения.

Порядок ключей в dump не следует использовать как критерий равенства модели.
Внешние данные могут иметь отсутствующие/лишние ключи, null или большие числа:
нужна явно выбранная политика валидации.
При чтении сразу в объект ошибка второго поля может оставить первое изменённым;
полный кандидат показан в следующем уроке.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/28-json-serialization/main.cpp
./build/bonus/reflection/28-json-serialization/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
F5 — запуск с отладчиком; Ctrl+F5 — без отладчика.

В VS Code открывайте `main.cpp` и нажимайте F5/Ctrl+F5: доступны корневая и локальная конфигурации.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 28-json-serialization`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
