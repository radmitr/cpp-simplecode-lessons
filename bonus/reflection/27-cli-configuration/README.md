# 27. Практика: имена полей и проверка конфигурации

## Версия C++

статическая рефлексия — **C++26**.
`std::string_view`, `std::from_chars`, структурированные привязки — **C++17**.
обобщённые лямбды — **C++14**.
`auto`, лямбды — **C++11**.
`std::exception`, `std::invalid_argument` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

Список имён берётся из объявления `Settings`, runtime-ключ сопоставляется
с уже сгенерированными ветками. Число сначала разбирается во временную переменную
с проверкой полного потребления строки и диапазона; только затем меняется поле.
Демонстрационный интерфейс поддерживает только положительные `int`. Типизированные
ограничения, обязательные параметры и отображаемые имена можно задавать аннотациями.

## Как это работает

Нужны `string_view`, `from_chars` и проверка входных данных.

`set_option` сопоставляет runtime-key с именами уже известных полей.
Для `port` и строки 9000 после `from_chars` проверяются код ошибки,
полное чтение и положительность, затем присваивается `candidate`.

Неизвестный ключ возвращает `false`. Неверные `workers` = 2oops бросают исключение,
при этом исходное `workers = 2` сохраняется. Итоговый вывод:
`port=9000`, `workers=2`.

Рефлексия выбирает готовую ветку обращения к полю, но не проверяет текст
вместо `from_chars`. Здесь поддержаны только соответствующие целочисленные поля.
При расширении структуры строками/`enum` нужен выбор преобразователя по типу.
Для применения сразу нескольких опций транзакционно потребуется кандидат
всей структуры, а не только одного поля.

### Результат и проверка

Последняя строка успешного запуска — `OK 27-cli-configuration`.
Интерактивного ввода и файловых операций при запуске нет; успех — код `0`.
Ошибка проверки перехватывается: причина выводится в `stderr`, код — `1`.

(на Linux команда Python обычно называется python3).

## Типичные ошибки

Успешный разбор начального числа не означает потребления всей строки. Проверяйте также конец диапазона и сохраняйте старое поле при ошибке.

### Самостоятельно

Добавьте аннотацию диапазона для `port` и проверьте границы 1 и 65535, ноль, переполнение и лишние символы.
