# 09. Splicing: переход от метаданных к программе

Предварительно: Шаблоны, constexpr/consteval и предыдущие механизмы этого раздела.
Стандарт и компилятор: GCC 16+ и c++26. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

Сплайсер [:reflection:] возвращает отражённую сущность в подходящий
синтаксический контекст: тип, выражение, член. Отражение должно быть известно
компилятору. reflect_constant отражает значение константы. Это не исполнение
произвольной строки как C++ и не выбор имени поля через runtime-строку.

main2.cpp отдельно показывает reflect_object, reflect_function и extract.
У runtime-объекта shared_value отражение обозначает объект, а не константный
снимок его значения. Для извлечения указателя сначала отражается константное
значение адреса через reflect_constant(&shared_value). После изменения через
сплайсер указатель наблюдает новое значение.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/09-splicing/main.cpp
./build/bonus/reflection/09-splicing/main
```

На Windows / MSYS2 Bash используйте scripts/build-windows.sh и расширение .exe.
В VS Code открывайте main.cpp и нажимайте F5: доступны корневая и локальная конфигурации.
Рабочая папка F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 09-splicing`.
Проверки check(...) выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с NDEBUG.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
