# 29. Итог: загрузка, проверка и сохранение настроек

Предварительно: Шаблоны, `constexpr`/`consteval` и предыдущие механизмы этого раздела.
Стандарт и компилятор: GCC 16+ и `c++26`. Каждый исходник здесь — самостоятельный исполняемый пример.

## Что показывает пример

Небольшой завершённый компонент объединяет метаданные, разбор JSON,
проверку обязательных полей, ограничения и формирование справки. Загрузка
создаёт отдельный `candidate` и возвращает его только после проверок: исходные
настройки не меняются при ошибке. dump создаёт текст для сохранения; работа с
реальным файлом и безопасная замена разобраны в io/bonus. Здесь данные хранятся
в памяти, чтобы отделить ошибки модели от ошибок файловой системы.

## Разбор кода и границы применения

Начальные настройки 8080/2 сохраняются до успешного разбора кандидата.
Неверный `port = 0` и остальные отрицательные случаи не заменяют исходный объект.
Допустимые 9000/4 фиксируются только после всех проверок и возвращаются наружу.

Числовой тип, диапазон 1…65535 и отдельный предел `workers <= 64` проверяются
раздельно. Строка "9000", дробное число, лишний ключ и слишком большое
число не принимаются как подходящие `int`-настройки.

Один обход формирует --`port` и --`workers` с текущими значениями,
другой — JSON. Это генерация справки для известных полей, а не полный
разбор argv: `main` не предоставляет универсальный CLI-фреймворк.

Структура-кандидат обеспечивает сильную гарантию изменения модели.
Для сохранения в реальный файл нужны ещё проверенная запись, закрытие
и подходящий протокол замены из раздела io.

## Запуск

Из корня проекта, Linux:

```bash
bash scripts/build-linux.sh bonus/reflection/29-settings-project/main.cpp
./build/bonus/reflection/29-settings-project/main
```

На Windows / MSYS2 Bash используйте `scripts/build-windows.sh` и расширение .exe.
F5 — запуск с отладчиком; Ctrl+F5 — без отладчика.

В VS Code открывайте `main.cpp` и нажимайте F5/Ctrl+F5: доступны корневая и локальная конфигурации.
Рабочая папка при F5/Ctrl+F5 — папка исходника. Особенности компилятора и зависимостей
описаны в [README раздела](../README.md).

## Результат и проверка

После показанных в коде значений последняя строка — `OK 29-settings-project`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section bonus/reflection`
(на Linux команда Python обычно называется python3).
