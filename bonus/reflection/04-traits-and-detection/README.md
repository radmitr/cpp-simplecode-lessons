# 04. `decltype`, `type_traits` и обнаружение операций

## Версия C++

`std::void_t`, `if constexpr` — **C++17**.
`constexpr`, `decltype` — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`decltype` получает тип уже известного выражения. Traits и detection idiom
могут проверить наличие заранее названного `id` и выбрать ветку `if constexpr`.
Они не находят имена всех неизвестных полей. В C++20 ту же проверку можно
выразить через `requires`. Подробное построение показано в
[уроке свойств типов и `if constexpr`](../../../templates/bonus/03-traits-if-constexpr/README.md);
здесь важна граница между проверкой операции и перечислением сущностей.

## Как это работает

Нужны специализация шаблонов, `decltype` и `if constexpr`.

`has_id` пробует заранее написанное выражение `declval<T>().id`.
Для `Item` оно допустимо, для `int` подстановка в специализацию не подходит,
и остаётся общий false_type. `read_id` возвращает 9 для `Item` и -1 для `int`.

`void_t` стирает конкретный тип допустимого выражения в `void`, позволяя
проверить сам факт корректности. `declval` не создаёт объект и не должен
исполняться при запуске.

Это обнаружение известного имени `id`, а не запрос «дай названия всех полей».
Для незнакомого произвольного имени всё ещё нужна другая информация.
Требования к доступу и допустимости выражения не отменяются traits-проверкой.

## Типичные ошибки

`declval` допустим в невычисляемом контексте и не создаёт объект. Обнаружение заранее названного поля не перечисляет неизвестные имена.
