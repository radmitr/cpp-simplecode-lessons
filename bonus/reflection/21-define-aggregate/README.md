# 21. Создание агрегатного типа

## Версия C++

`std::meta`, статическая рефлексия и `consteval`-блок — **C++26**.
`consteval`-функции появились в **C++20**; блок из этого примера — отдельная возможность C++26.
обобщённые лямбды — **C++14**.
`auto`, лямбды — **C++11**.
`std::exception` — **C++98**.

Сборка примеров: **C++26**. Это режим проекта,
а не дата появления всех использованных конструкций.
Рефлексия здесь экспериментальная: нужны GCC 16+ и `-freflection`; конкретные требования заданы в файлах сборки.

## Что изучаем

`data_member_spec` задаёт описание поля, `define_aggregate` завершает
подходящее объявление класса как агрегата. Дальше `Generated` используется обычным
типобезопасным способом. Имя, тип, выравнивание, аннотации поля задаются по правилам
API. Определение выполняется в `consteval`-блоке, а не простом `constexpr`-инициализаторе.
Это ограниченная стандартизованная генерация агрегатов, а не вставка
произвольного исходного текста, методов или повторное определение готового класса.

## Как это работает

Нужны неполные типы, агрегаты и константное вычисление.

`Generated` сначала только объявлен. `consteval`-блок передаёт `define_aggregate`
описания двух полей: `int` id и `double` score. После завершения определения
компилятор видит обычный агрегат с этими именами и типами.

В `main` `Generated{7, 2.5}` создаёт runtime-объект, а общий обход выводит
id=7 и score=2.5. Метаданные порождают структуру типа заранее,
а значения конкретного экземпляра задаются при запуске.

Здесь нельзя повторно «дописать» произвольные методы в уже готовый класс.
Генерация ограничена контрактом `define_aggregate` и допустимым исходным
объявлением. Имена из внешнего формата требуют выбранной политики и проверки,
а не безусловного превращения любого текста в объявление.

## Типичные ошибки

Готовый класс нельзя дополнять повторным `define_aggregate`. Используйте допустимое неполное объявление и `consteval`-блок; это не вставка произвольного исходного текста.
