# Урок 122. Несколько обработчиков `catch`

## Версия C++

`std::exception`, `std::invalid_argument` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Предварительно: Уроки [«120. Обработка исключений: `try` и `catch`»](../lesson-120-exception-handling-try-catch/README.md) — [«121. Выбрасывание исключений: `throw`»](../lesson-121-exception-throw/README.md) и стандартные исключения.

## Примеры

- [main.cpp](main.cpp): Выбрасывает разные типы в `foo`; `catch(...)` обрабатывает всё, что не подошло предыдущим обработчикам.

Каждый `main*.cpp` — отдельная программа.

## Как это работает

Обработчики проверяются сверху вниз, выбирается первый подходящий.
`catch(...)` должен находиться после конкретных типов; он не предоставляет
имя пойманного объекта для чтения `what()`.

При активном `foo(1)` бросается `int`, его специальный `catch` закомментирован,
поэтому выполняется `catch(...)` с «Что-то пошло не так!!!».
При `foo(0)` выбрасывается `invalid_argument`, который подходит под `exception&`;
при отрицательном аргументе — строковый литерал для `const char*`.

Обработчик производного класса нужно размещать перед обработчиком базы,
иначе база перехватит его раньше. После `catch` выполнение продолжается
за всей конструкцией `try`/`catch`, а не со следующей строки после `throw`.
Неперехваченное исключение приводит к `terminate`.

## Типичные ошибки

Обработчики проверяются по порядку. Производный тип нужно ловить до базового, `catch(...)` ставить последним. В нём нет переменной с описанием ошибки.
