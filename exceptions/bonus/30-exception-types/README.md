# 30. Стандартные и собственные типы исключений

## Версия C++

`try`, `throw`, `catch`, `std::exception` и основные классы `<stdexcept>` —
C++98. `system_error`, `future_error`, `bad_function_call`, `bad_weak_ptr`,
`regex_error` и `stoi` — C++11. `any`, `optional`, `variant` и
`filesystem_error` — C++17. Сборка примеров: **C++17**.
Более новые типы перечислены отдельно ниже; они не используются в этих файлах.

## Что изучаем

`throw std::runtime_error("...")` создаёт объект ошибки и передаёт управление
подходящему `catch`. Это один из типов, а не обязательный тип для всех ошибок.
Тип позволяет отличить причину, `what()` — получить текстовое описание.

Предварительно: [`try/catch`](../../lesson-120-exception-handling-try-catch/README.md),
[`throw`](../../lesson-121-exception-throw/README.md),
[несколько обработчиков](../../lesson-122-multiple-catch-blocks/README.md)
и [собственные классы исключений](../../lesson-123-custom-exception-class/README.md).
Отдельная папка верхнего уровня `exceptions/` не нужна: это продолжение
основ языка, а новые примеры находятся в `basics/bonus/`.

## Примеры

- [main.cpp](main.cpp): наследование `invalid_argument → logic_error`
  и `overflow_error → runtime_error`.
- [main2.cpp](main2.cpp): настоящие исключения из `vector::at`, `stoi`,
  пустой `function`, `optional::value`, неверных `get/any_cast`.
- [main3.cpp](main3.cpp): код `system_error`, включение исключений потока
  ввода и повторное получение `future` из одного `promise`.
- [main4.cpp](main4.cpp): `bad_alloc`, `bad_cast`, `bad_typeid`,
  `bad_weak_ptr` и `regex_error`.
- [main5.cpp](main5.cpp): собственный `ParseError` с номером строки,
  порядок обработчиков и `catch (...)`.

Ввода с клавиатуры, файлов, сети и внешних служб нет.
Успешный запуск заканчивается строкой `OK ...` и кодом `0`.
Провал проверки приводит к ненулевому коду; обычные диагностические тексты
библиотеки могут отличаться между компиляторами и языками системы.

- [main6.cpp](main6.cpp): проверяемый доступ через `get_if`, указательный `any_cast` и `weak_ptr::lock`.

## Как это работает

### Основные семейства

`std::exception` — общий базовый класс большинства стандартных исключений.
Принимать его следует как `const std::exception&`: ссылка сохраняет
конкретный тип и не создаёт срезанную копию.

`std::logic_error` объединяет ошибки в условиях использования операции:

- `invalid_argument` — неподходящий аргумент, например `stoi("text")`.
- `out_of_range` — значение или индекс вне допустимого диапазона:
  `vector.at(9)` у одноэлементного вектора, слишком большое число для `stoi`.
- `length_error` — запрос размера, превышающего допустимую длину контейнера/строки.
- `domain_error` — аргумент вне математической области, если API использует
  именно такую диагностику.

`std::runtime_error` — базовый класс для ошибок, обнаруженных при выполнении:

- `range_error` — результат вне значимого диапазона.
- `overflow_error` — слишком большой результат.
- `underflow_error` — потеря результата из-за слишком малого значения.

Это **назначение классов**, а не обещание автоматической проверки всех
операторов. Обычное переполнение знакового `int` не бросает `overflow_error`:
это неопределённое поведение. Деление целого на ноль не превращается
в `domain_error`. Математические функции могут сообщать через `errno`,
специальные значения и состояние floating-point environment, а не исключения.
Нужен контракт конкретной операции.

В `main.cpp` исключения выбрасываются явно. Производный тип принимается
обработчиком базового семейства; два обработчика успешно срабатывают.

### Исключения библиотечных объектов

`main2.cpp` вызывает каждую ошибочную операцию отдельно, ловит ожидаемый тип
и проверяет, что обработчик действительно был вызван.

`vector::at` проверяет индекс. `operator[]` в таком примере не является
заменой с той же обработкой ошибки: выход за границы нарушает требования.
Для `optional` безопасно проверить наличие значения перед `value()`,
для `variant` — использовать `get_if`, для `any` — указательную форму
`any_cast<T>(&object)`, которая возвращает нулевой указатель при несовпадении.
Это варианты API; их назначение — проверить состояние до доступа.

`stoi` может разобрать только начало строки: `"12abc"` не обязательно ошибка.
Для проверки всей строки используйте позицию окончания преобразования.
Если исключения для разбора нежелательны, есть `from_chars`:
он возвращает код ошибки (см. [проверяемые преобразования](../../../basics/bonus/05-numeric-conversions/README.md)).

### Ошибка с кодом

`std::system_error` наследует `runtime_error` и хранит `std::error_code`.
Текст `what()` удобен человеку; код и категория подходят для программной
проверки. В `main3.cpp` ошибка доступа **явно моделируется**, а не вызывается
изменением прав настоящего файла. Сравнение с `std::errc::permission_denied`
не зависит от перевода сообщения.

`std::ios_base::failure` (в современной библиотеке наследует `system_error`)
связан с ошибками потокового ввода-вывода. По умолчанию многие ошибки
`iostream` устанавливают флаги, а не бросают. Пример включает маску
`failbit | badbit`, затем пытается прочитать число из `"not-a-number"`.
Включение маски тоже может немедленно бросить, если нужный флаг уже установлен.

`std::future_error` наследует `logic_error` и тоже содержит код.
Пример получает `future` из `promise` второй раз и проверяет
`future_already_retrieved`. Другие полезные коды: `promise_already_satisfied`,
`broken_promise` и `no_state`.
При этом не следует испытывать все запрещённые операции в надежде на
исключение: например, вызывать `future::get()` для невалидного объекта
не является переносимым способом получить `no_state`.
[Результаты и исключения через `future`](../../../multithreading/bonus/05-future-async/README.md)
и [`promise/future`](../../../multithreading/bonus/09-promise-future/README.md)
разбирают состояния подробнее.

### Редкие, но полезные типы

`main4.cpp` показывает:

- `bad_alloc` — отказ обычного выделения памяти. Здесь `throw std::bad_alloc()`
  **имитирует** отказ; огромные массивы ради эксперимента не выделяются.
  `new (std::nothrow)` вместо этого обычно возвращает нулевой указатель
  при отказе выделения, но не запрещает исключения конструктора объекта.
- `bad_cast` — неудачный `dynamic_cast` к ссылке.
  Указательная форма при несовпадении возвращает `nullptr`.
- `bad_typeid` — `typeid(*p)` для нулевого указателя на полиморфный тип.
  Это особое правило; произвольное разыменование нулевого указателя не безопасно.
- `bad_weak_ptr` — создание `shared_ptr` из истёкшего/пустого `weak_ptr`.
  `weak_ptr::lock()` позволяет вместо исключения получить пустой `shared_ptr`.
- `regex_error` — некорректное регулярное выражение, здесь незакрытая `(`.

Ещё встречаются `bad_array_new_length` (C++11, наследует `bad_alloc`),
`filesystem::filesystem_error` (C++17, наследует `system_error`;
у файловых функций часто есть перегрузки с `error_code&`),
`format_error` (C++20, наследует `runtime_error`),
`bad_expected_access<E>` (C++23, неудачный `expected::value()`).
Примеры современных API находятся в
[форматировании и печати](../../../io/bonus/21-format-and-print/README.md) и
[результате или ошибке: `std::expected`](../../../stl/bonus/04-expected/README.md).
Наличие имени в стандарте ещё не означает поддержку текущей библиотекой.

### Свой тип и порядок `catch`

`ParseError` в `main5.cpp` сохраняет сообщение и номер строки `12`.
Обработчик производного типа написан раньше `std::exception`.
Если первым поставить базовый, он поймает и `ParseError`,
а специальный обработчик не получит управление.

`catch (...)` ловит любой тип, включая `int`, поэтому стоит последним.
Он не ловит произвольное падение процесса, гонку данных или
`std::terminate()` как исключение. Для прикладных ошибок предпочтителен
свой класс, наследующий `std::exception`, а не `throw 7`.
Сам `what()` возвращает указатель, связанный со временем жизни исключения:
при необходимости сохранить сообщение копируйте его в `std::string`.

### `main6.cpp`: проверить состояние без исключения доступа

`optional::has_value()` проверяет наличие значения.
`get_if<T>(&variant)` возвращает указатель на нужную альтернативу либо `nullptr`.
Указательный `any_cast<T>(&object)` аналогично проверяет тип без `bad_any_cast`.
`weak_ptr::lock()` возвращает пустой `shared_ptr`, если объект уже не существует.

В программе `variant` содержит число `7`: строковый `get_if` возвращает
`nullptr`, целочисленный — действительный адрес. `any` тоже содержит `int`,
поэтому строковый указательный cast неудачен. Пустые `optional` и `weak_ptr`
корректно распознаются. Это проверка конкретного доступа; она не обещает,
что любые дальнейшие действия с результатом не могут бросить исключение.

Вывод заканчивается `OK checked-access`. Ввода, файлов и служб нет;
успех — `0`, провал проверки — `1`. Выберите `main6.cpp`.

## Типичные ошибки

Ловить по значению, ставить базовый `catch` раньше производного,
проверять точный английский текст `what()`, проглатывать ошибку без решения.
Исключение из рабочего потока нужно поймать в нём или передать через
`promise/async`; внешний `catch` в `main` сам его не перехватит.
Исключение, покинувшее `noexcept`-функцию, вызывает `terminate()`.
