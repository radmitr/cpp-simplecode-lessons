# 13. Повторное выбрасывание и вложенные исключения

## Версия C++

`std::exception`, `std::runtime_error`, `std::invalid_argument` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

`throw`; внутри обработчика повторно выбрасывает текущее исключение,
сохраняя его динамический тип. `throw` error создаёт новый объект по статическому
типу выражения и может срезать производную часть. Ловите по `const`-ссылке.
`throw_with_nested` добавляет контекст операции, `rethrow_if_nested` позволяет
разобрать исходную причину. Обход цепочки должен иметь понятный предел и не
терять сообщение верхнего уровня.

## Примеры

- [main.cpp](main.cpp).

Выбирайте один исходник с `main()`; варианты запускаются отдельно.

## Как это работает

Предварительно: Функции, переменные и темы предыдущих уроков раздела.
Каждый исходник здесь — самостоятельный исполняемый пример.

`relay` выбрасывает `Detail` с `code = 7`, ловит через `const std::exception&`
и использует `throw`;. Внешний `catch(const Detail&)` всё ещё видит `code`:
сохранился исходный динамический тип.

~~~cpp
catch (const std::exception&) {
    throw; // Повторно бросить текущий объект исключения.
}
~~~

Сокращённый фрагмент; полный пример: [main.cpp](main.cpp).

В другой цепочке inner `invalid_argument("bad field")` оборачивается
`runtime_error("configuration failed")`. Внешний обработчик получает контекст,
а `rethrow_if_nested` открывает исходную причину.

`throw`; допустим только когда есть обрабатываемое исключение;
без него вызывается `terminate`. `throw` error — новый `throw` выражения,
который может скопировать базовую часть и потерять данные `Detail`.
Для переноса ошибки между потоками служат exception_ptr/current_exception,
а не попытка продолжить тот же `catch` в другом потоке.

### Результат и проверка

После показанных в коде значений последняя строка — `OK 13-rethrow-and-nested`.
Проверки `check(...)` выбрасывают исключение при нарушении ожидаемого результата;
в таком случае программа печатает причину и возвращает 1. Они работают и с `NDEBUG`.
Адреса, диагностические имена типов, размеры и время могут отличаться между системами.
Проверка всего раздела: `python scripts/check-bonuses.py --section exceptions/bonus`
(на Linux команда Python обычно называется python3).
