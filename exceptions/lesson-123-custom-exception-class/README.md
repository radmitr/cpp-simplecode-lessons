# Урок 123. Собственные классы исключений

## Версия C++

`std::exception`, `std::invalid_argument` — **C++98**.

Сборка примеров: **C++17**. Это режим проекта,
а не дата появления всех использованных конструкций.

## Что изучаем

Предварительно: Уроки [«120. Обработка исключений: `try` и `catch`»](../lesson-120-exception-handling-try-catch/README.md) — [«122. Несколько обработчиков `catch`»](../lesson-122-multiple-catch-blocks/README.md), классы и наследование.

## Примеры

- [main.cpp](main.cpp): Выбрасывает самостоятельный тип `MyException` без наследования от `std::exception`.
- [main2.cpp](main2.cpp): Наследует `MyException` от `std::invalid_argument` и добавляет состояние ошибки.

Каждый `main*.cpp` — отдельная программа.

## Как это работает

Собственный тип исключения может содержать код, состояние данных и контекст.
В `main.cpp MyException` — самостоятельный тип, поэтому общий `catch(exception&)`
не обязан его ловить; отдельный обработчик `MyException` нужен явно.

В `main2.cpp MyException` наследует `invalid_argument` и добавляет `getDataState`.
Более конкретный `catch` стоит перед `catch(exception&)`, чтобы не потерять
специальные данные ошибки.

Наследование от `std::exception` удобно для общего интерфейса `what()`.
Если переопределять what вручную, его возвращаемая C-строка должна оставаться
живой, а объявление соблюдать контракт `noexcept`. Часто проще наследовать
`runtime_error`/`invalid_argument` и передать им строку сообщения.
Исключение ловят по `const`-ссылке, если изменение его состояния не требуется.

## Типичные ошибки

Первый `MyException` не перехватывается через `std::exception`. Во втором примере специфический `catch` стоит раньше базового. В общем случае ловите объекты исключений по `const`-ссылке; для этого наблюдающие методы класса также должны быть `const`.
